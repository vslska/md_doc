**Terraform** — это инструмент управления инфраструктурой как кодом (Infrastructure as Code, или IaC), разработанный компанией HashiCorp. Terraform позволяет описывать инфраструктурные ресурсы (виртуальные машины, хранилища данных, сетевые интерфейсы) и управлять ими с использованием декларативного языка конфигурации — HCL.

Основные компоненты Terraform:

- **Конфигурационные файлы, или Configuration Files** Файлы ***.tf**, в которых содержится описание инфраструктурных ресурсов, переменных и настроек самого Terraform.
- **Провайдеры, или Providers** Для взаимодействия с сервисами облачных или локальных ресурсов в Terraform используются провайдеры. Они служат мостом между описанием инфраструктуры в виде конфигурационного кода и реальными ресурсами, которые должны быть созданы, изменены или удалены.
- **Ресурсы, или Resources** Инфраструктурные компоненты, которыми управляет Terraform, например виртуальные машины, сетевые интерфейсы, базы данных, балансировщики нагрузки и т. д. Ресурсы описываются в конфигурационных файлах.
- **Провиженеры, или Provisioners** Инструменты, которые позволяют настроить созданные ресурсы: установить программное обеспечение, скопировать файлы или выполнить скрипты после их развёртывания.
- **Состояние, или State** Файл или хранилище (например, S3), в котором Terraform отслеживает текущее состояние управляемых ресурсов. Это позволяет Terraform определять, какие ресурсы уже существуют и как они были настроены.
### . **Всегда проверяй зависимости и зоны визуально**

Перед `apply` — открой `main.tf` и мысленно пройдись по цепочке:

> Диск → в какой зоне? → ВМ → в той же зоне? → Подсеть → в той же? → OK.

Со временем ты начнёшь это делать автоматически.

Terraform **не зависит от имени файла** — он склеивает **все `.tf`-файлы в одной папке** в один логический конфиг.

Поэтому неважно, где лежит:

- `variables` — в `variables.tf`
- `locals` — в `locals.tf`
- `providers` — в `provider.tf`
- `resources` — в `main.tf`
- `outputs` — в `outputs.tf`

→ Terraform всё равно **соберёт это в единое целое**.

**HCL, или HashiCorp Configuration Language,** — это язык конфигурации для описания инфраструктуры как кода в Terraform.
# Синтаксис HCL
Для описания синтаксиса языка HCL можно выделить следующие основные элементы:

 **Декларативный подход** Означает, что вы описываете желаемое состояние вашей инфраструктуры, а не шаги для достижения этого состояния.
 
 **Блоки** Основной элемент синтаксиса HCL. Они используются для описания ресурсов, переменных, выходных значений и других компонентов конфигурации. Каждый блок начинается с открывающей фигурной скобки `{` и заканчивается закрывающей фигурной скобкой `}`
```hcl
data "yandex_compute_image" "ubuntu" {
  family = "ubuntu-2204-lts"
}
```

**Атрибуты** Внутри блоков используются атрибуты для определения параметров ресурсов или других элементов конфигурации. У атрибутов есть имя и значение, разделённые знаком равенства `=`.
```hcl
resource "yandex_compute_snapshot" "default" {
  name           = "test-snapshot"
  source_disk_id = "test_disk_id"
}
```

**Переменные** HCL позволяет определять переменные для использования в вашей конфигурации. Переменные могут быть определены в отдельных файлах или внутри конфигурационных файлов.
```hcl
variable "zone" {
  type    = string
  default = "ru-central1-a"
}   
```

**Встроенные функции Terraform** В HCL могут использоваться функции для динамического определения значений атрибутов и переменных, такие как арифметические операции и условные выражения.
Например, функция `timestamp`
```hcl
metadata = {
   ...
    date     = timestamp()
}
```

**Модули** позволяют организовывать и переиспользовать части конфигурации Terraform. Например, модуль `S3`:
```hcl
module "s3" {
  source      = "https://github.com/terraform-yc-modules/terraform-yc-s3"
  bucket_name = "unique-bucket-name"
}
```

**Выходные атрибуты** С помощью выходных атрибутов можно определять данные, которые будут доступны после применения конфигурации Terraform. Эти значения могут использоваться в других конфигурациях или скриптах.
```hcl
output "image_id" {
  description = "Image ID from data block"
  value       = data.yandex_compute_image.default.image_id
}
```


# Ресурсы и провайдеры
Ресурсы — это инфраструктурные объекты (виртуальные машины, хранилища данных, сетевые интерфейсы и т. д), которыми вы хотите управлять с помощью Terraform. У каждого ресурса есть собственный тип и набор атрибутов.

```hcl
resource "yandex_vpc_network" "default" {
  name = "vpc-name"
}
```

В этом примере:
- `"yandex_vpc_network"` — тип ресурса, в данном случае — VPC в облаке Yandex Cloud;
- `"default"` — локальное имя для данного экземпляра ресурса/блока;
- `name` — атрибут этого ресурса, определяющий имя VPC.

Провайдеры в Terraform определяют использование конкретных облачных платформ или других систем, с которыми Terraform взаимодействует для управления ресурсами. У каждого провайдера — собственная документация, где описаны поддерживаемые ресурсы и параметры. Перед использованием ресурса лучше свериться с документацией, например с [yandex_vpc_network](https://terraform-provider.yandexcloud.net/resources/vpc_network), которую мы использовали в примере выше.
### Пример синтаксиса использования провайдера в Terraform

```hcl
provider "yandex" {
  cloud_id                 = "cloud_id_here"
  folder_id                = "folder_id_here"
}
```
