# Архитектура Multi-folder VPC: Руководство по настройке сетевого взаимодействия ресурсов из разных каталогов в Yandex Cloud

> **Сфера применения:** Проектирование облачных сетей enterprise-уровня, межпроектная изоляция, построение инфраструктуры CI/CD и разделение сред (Development, Staging, Production) в Yandex Cloud.
> 
> **Цель документа:** Исчерпывающее техническое руководство по реализации концепции `Multi-folder VPC` (растянутые сети) для организации прямой IP-связности и DNS-резолюции между виртуальными машинами и сервисами, размещенными в изолированных каталогах одного облака, с детальным разбором через консоль управления, Yandex CLI и Terraform.

## Архитектурный разбор механизма Multi-folder VPC

### Проблема изоляции каталогов

В Yandex Cloud архитектура безопасности строится на строгой изоляции вычислительных и сетевых ресурсов по каталогам (Folders). По умолчанию облачные сети (VPC Networks) и подсети создаются локально внутри конкретного каталога. Ресурсы из разных каталогов не имеют прямого сетевого доступа друг к другу, если они принадлежат разным виртуальным сетям.

### Концепция растянутых подсетей

Метод **Multi-folder VPC** обходит это ограничение за счет разделения жизненного цикла облачной сети и подсетей:

1. Базовая облачная сеть создается в центральном (управляющем) каталоге.
2. Подсети этой же сети создаются или физически перемещаются в целевые рабочие каталоги (`dev-folder`, `prod-folder`).
3. Виртуальные машины и сервисы в целевых каталогах подключаются к локализованным в них подсетям единой сети.

```
                        [ Облако Yandex Cloud ]
                                  │
                                  ▼
               [ Облачная сеть: shared-net (net-folder) ]
                                  │
         ┌────────────────────────┼────────────────────────┐
         ▼                        ▼                        ▼
  [ Подсеть: subnet-a ]    [ Подсеть: subnet-b ]    [ Подсеть: subnet-d ]
  (Каталог: net-folder)    (Каталог: dev-folder)    (Каталог: prod-folder)
         │                        │                        │
         ▼                        ▼                        ▼
     [ net-vm ]               [ dev-vm ]               [ prod-vm ]
```

### Преимущества архитектуры

- **Отсутствие шлюзов и маршрутизации:** Пакеты между виртуальными машинами разных каталогов передаются на канальном и сетевом уровнях без использования промежуточных маршрутизаторов (`next hop`), виртуальных шлюзов или NAT.
- **Интеграция со службой DNS:** Узлы автоматически разрешают имена друг друга через внутреннюю службу DNS Yandex Cloud по именам FQDN.
- **Строгое разграничение прав:** Администраторы сред разработки или производства имеют полный контроль над своими каталогами и ресурсами, в то время как сетевая инфраструктура централизована.

## Предварительные требования и безопасность

1. **Платежный аккаунт:** Активный платежный аккаунт в статусе `ACTIVE` или `TRIAL_ACTIVE`.
2. **Права доступа (Роли):**
    - Для управления сетями: `vpc.admin` (или раздельные роли `vpc.privateAdmin`, `vpc.publicAdmin`, `vpc.securityGroups.admin`).
    - Для управления виртуальными машинами: `compute.admin` и `vpc.user`.
3. **Ограничения:** Перемещение подсетей поддерживается **только в пределах одного облака**. Перенос сетей или подсетей между разными облаками невозможен.

## Пошаговая реализация инфраструктуры

Для демонстрации концепции разворачиваем тестовую среду из трех изолированных каталогов (`net-folder`, `dev-folder`, `prod-folder`), объединяем их единой сетью и проверяем связность.

### Этап 1: Создание каталогов без сети VPC

Создаём каталоги `net-folder`, `dev-folder` и `prod-folder`:

#### Консоль управления

1. В [консоли управления](https://console.yandex.cloud) выбираем [облако](https://yandex.cloud/ru/docs/resource-manager/concepts/resources-hierarchy#cloud) и нажимаем кнопку → **Создать каталог**.
2. Вводим имя [каталога](https://yandex.cloud/ru/docs/resource-manager/concepts/resources-hierarchy#folder) `net-folder`.
3. Отключаем опцию **Создать сеть по умолчанию**, чтобы создать сеть и подсети вручную.
4. Нажмем кнопку **Создать**.

> Аналогично создадим еще два каталога без сети VPC с именами `dev-folder` и `prod-folder`.

#### CLI 

Для создания ресурсов с помощью CLI необходимо [аутентифицироваться](https://yandex.cloud/ru/docs/cli/operations/authentication/service-account#auth-as-sa) от имени [сервисного аккаунта](https://yandex.cloud/ru/docs/iam/concepts/users/service-accounts) с [ролью](https://yandex.cloud/ru/docs/iam/concepts/access-control/roles) `admin` на [облако](https://yandex.cloud/ru/docs/resource-manager/concepts/resources-hierarchy#cloud).

1. **Проверяем** описание команды создания каталога:

```bash
yc resource-manager folder create --help
```

2. **Создаём** облачные каталоги `net-folder`, `dev-folder` и `prod-folder`:

```bash
yc resource-manager folder create --name net-folder
yc resource-manager folder create --name dev-folder
yc resource-manager folder create --name prod-folder
```

#### Terraform

1. **Создаём** параметры для Terraform-провайдера Yandex Cloud:

```hcl
# ==================================
# Terraform & Provider Configuration
# ==================================
terraform {
 required_providers {
     yandex = {
       source  = "yandex-cloud/yandex"
       version = "~> 0.92.0"
     }
 }
}
```

2. **Описываем** входные переменные:

```hcl
variable "cloud_id" {
  description = "YC cloud-id. Taken from environment variable."
}
```

3. **Описываем** целевые ресурсы — облачные каталоги:

```hcl
# ========
# Folders
# ========
resource "yandex_resourcemanager_folder" "net_folder" {
  cloud_id = var.cloud_id
  name     = "net-folder"
}

resource "yandex_resourcemanager_folder" "dev_folder" {
  cloud_id = var.cloud_id
  name     = "dev-folder"
}

resource "yandex_resourcemanager_folder" "prod_folder" {
  cloud_id = var.cloud_id
  name     = "prod-folder"
}
```

4. **Создаем** необходимую инфраструктуру:

```hcl
export TF_VAR_cloud_id=$(yc config get cloud-id)
export YC_TOKEN=$(yc iam create-token)
terraform apply
```

### Этап 2: Создание облачной сети VPC с подсетями

В каталоге `net-folder` создаем сеть `shared-net` с тремя подсетями со следующими параметрами:

| Имя подсети | Префикс        | Зона доступности | Целевой каталог |
| ----------- | -------------- | ---------------- | --------------- |
| `subnet-a`  | `10.1.11.0/24` | `ru-central1-a`  | `net-folder`    |
| `subnet-b`  | `10.1.12.0/24` | `ru-central1-b`  | `dev-folder`    |
| `subnet-d`  | `10.1.13.0/24` | `ru-central1-d`  | `prod-folder`   |

#### Консоль управления

**Шаг 1. Создание сети**

- **Выбираем** каталог `net-folder` в [консоли управления](https://console.yandex.cloud/).
- **Переходим** в сервис [Virtual Private Cloud](https://console.yandex.cloud/link/vpc).
- **Нажимаем** кнопку **Создать сеть**.
- **Задаем** имя сети `shared-net`.
- **Отключаем** опцию [Создать подсети](https://yandex.cloud/ru/docs/vpc/operations/subnet-create).
- **Нажимаем** кнопку **Создать сеть**.

**Шаг 2. Создание подсети**

- **Выбираем** созданную сеть `shared-net`.
- **Нажимаем** кнопку **Создать подсеть**.
- **Указываем** имя подсети (`subnet-a`, `subnet-b` или `subnet-d`).
- **Выбираем** зону доступности (`ru-central1-a`, `ru-central1-b` или `ru-central1-d`).
- **Вводим** CIDR `10.1.11.0/24`.
- **Нажимаем** кнопку **Создать подсеть**.

#### CLI

**Шаг 1. Создание сети**

- **Проверяем** описание команды для создания сети:

```bash
yc vpc network create --help
```

- **Создаем** облачную сеть `shared-net` в каталоге `net-folder`:

```bash
yc vpc network create --folder-name net-folder --name shared-net
```

**Шаг 2. Создание подсетей**

- **Проверяем** описание команды для создания подсети:

```bash
yc vpc subnet create --help
```

- **Создаем** подсети в целевых каталогах:

```bash
yc vpc subnet create --folder-name net-folder --name subnet-a \
  --network-name shared-net --zone ru-central1-a --range 10.1.11.0/24

yc vpc subnet create --folder-name dev-folder --name subnet-b \
  --network-name shared-net --zone ru-central1-b --range 10.1.12.0/24

yc vpc subnet create --folder-name prod-folder --name subnet-d \
  --network-name shared-net --zone ru-central1-d --range 10.1.13.0/24
```

- **Проверяем** состояние созданных подсетей:

```bash
yc vpc subnet list --folder-name net-folder
yc vpc subnet list --folder-name dev-folder
yc vpc subnet list --folder-name prod-folder
```

#### Terraform

**Шаг 1. Создание сети**

- **Описываем** целевой ресурс — облачную сеть:

```hcl
# =============
# VPC Resources
# =============
resource "yandex_vpc_network" "shared_net" {
  folder_id = yandex_resourcemanager_folder.net_folder.id
  name      = "shared-net"
}
```

- **Выполняем** команды

```bash
export TF_VAR_cloud_id=$(yc config get cloud-id)
export YC_TOKEN=$(yc iam create-token)
terraform apply
```

**Шаг 2. Создаем подсети**

- **Описываем** целевые ресурсы — облачные подсети:

```hcl
resource "yandex_vpc_subnet" "subnet_a" {
  folder_id      = yandex_resourcemanager_folder.net_folder.id
  name           = "subnet-a"
  description    = "NET folder subnet"
  v4_cidr_blocks = ["10.1.11.0/24"]
  zone           = "ru-central1-a"
  network_id     = yandex_vpc_network.shared_net.id
}

resource "yandex_vpc_subnet" "subnet_b" {
  folder_id      = yandex_resourcemanager_folder.dev_folder.id
  name           = "subnet-b"
  description    = "DEV folder subnet"
  v4_cidr_blocks = ["10.1.12.0/24"]
  zone           = "ru-central1-b"
  network_id     = yandex_vpc_network.shared_net.id
}

resource "yandex_vpc_subnet" "subnet_d" {
  folder_id      = yandex_resourcemanager_folder.prod_folder.id
  name           = "subnet-d"
  description    = "PROD folder subnet"
  v4_cidr_blocks = ["10.1.13.0/24"]
  zone           = "ru-central1-d"
  network_id     = yandex_vpc_network.shared_net.id
}
```

- **Выполняем команды** 

```
export TF_VAR_cloud_id=$(yc config get cloud-id)
export YC_TOKEN=$(yc iam create-token)
terraform apply
```

### Этап 3: Перемещение подсетей

[Перемещаем](https://yandex.cloud/ru/docs/vpc/operations/subnet-move) подсеть `subnet-b` в каталог `dev-folder`:

#### Консоль управления

- **Выбираем** каталог `net-folder` в [консоли управления](https://console.yandex.cloud/).
- **Переходим** в сервис **Virtual Private Cloud**.
- **Нажимаем** на имя облачной сети `shared-net`.
- **Нажимаем** на значок меню (три точки) в строке подсети `subnet-b` и **выбираем** **Переместить**.
- **Выбираем** каталог `dev-folder` из выпадающего списка.
- **Нажимаем** кнопку **Переместить**.
- **Повторяем** эти же действия для подсети `subnet-d`, чтобы переместить её в каталог `prod-folder`.

#### CLI

- **Проверяем** описание команды для перемещения подсети:

```bash
yc vpc subnet move --help
```

- **Перемещаем** подсеть

```bash
yc vpc subnet move subnet-b \
  --destination-folder-name dev-folder
```

> Аналогично переместите подсеть `subnet-d` в каталог `prod-folder`.

### Этап 4: Развертывание виртуальных машин

Создаём по одной виртуальной машине в каждом каталоге с подключением к соответствующей подсети.

|**Имя ВМ**|**Каталог**|**Зона**|**Подсеть**|
|---|---|---|---|
|`net-vm`|`net-folder`|`ru-central1-a`|`subnet-a`|
|`dev-vm`|`dev-folder`|`ru-central1-b`|`subnet-b`|
|`prod-vm`|`prod-folder`|`ru-central1-d`|`subnet-d`|
#### Консоль управления

-  **Выбираем** каталог `net-folder` в консоли управления.
-  **Нажимаем** _Создать ресурс_ ➜ _Виртуальная машина_.
-  **Выбираем** образ ОС: в поиске вводим `Ubuntu 22.04 LTS` и кликаем на публичный образ.
-  **Выбираем** расположение: зона `ru-central1-a`.
-  **Настраиваем** сеть: подсеть `subnet-a`, публичный IP — `Автоматически` (или ваш статический).
-  **Выбираем** доступ по `SSH-ключ`:
    - Логин: `ycuser`.
    - SSH-ключ: выбираем сохраненный в профиле (или нажимаем _Добавить ключ_, генерируем/вставляем свой и сохраняем архив с ключами в папку `.ssh` на ПК).
-  **Вводим** имя ВМ: `net-vm` в блоке общей информации.
-  **Нажимаем** кнопку _Создать ВМ_.

#### CLI

- **Описываем** шаблон для метаданных ВМ в отдельном файле `vm-init.tpl`:

```yaml
#cloud-config

datasource:
  Ec2:
    strict_id: false
ssh_pwauth: yes
users:
  - name: "${USER_NAME}"
    sudo: ALL=(ALL) NOPASSWD:ALL
    shell: /bin/bash
    ssh_authorized_keys:
      - "${USER_SSH_KEY}"
```

- **Генерируем** файл с метаданными для развертывания ВМ:

```bash
export USER_NAME=ycuser
export USER_SSH_KEY=$(cat ~/.ssh/id_rsa.pub)

envsubst < vm-init.tpl > vm-config.txt
```

- **Создаем** виртуальные машины:

```bash
yc compute instance create --name=net-vm --hostname=net-vm \
  --zone=ru-central1-a \
  --platform=standard-v3 \
  --cores=2 --memory=4G --core-fraction=100 \
  --create-boot-disk image-folder-id=standard-images,image-family=ubuntu-2204-lts \
  --network-interface subnet-name=subnet-a,ipv4-address=auto,nat-ip-version=ipv4 \
  --metadata-from-file user-data=vm-config.txt

yc compute instance create --name=dev-vm --hostname=dev-vm \
  --zone=ru-central1-b \
  --platform=standard-v3 \
  --cores=2 --memory=4G --core-fraction=100 \
  --create-boot-disk image-folder-id=standard-images,image-family=ubuntu-2204-lts \
  --network-interface subnet-name=subnet-b,ipv4-address=auto,nat-ip-version=ipv4 \
  --metadata-from-file user-data=vm-config.txt

yc compute instance create --name=prod-vm --hostname=prod-vm \
  --zone=ru-central1-d \
  --platform=standard-v3 \
  --cores=2 --memory=4G --core-fraction=100 \
  --create-boot-disk image-folder-id=standard-images,image-family=ubuntu-2204-lts \
  --network-interface subnet-name=subnet-d,ipv4-address=auto,nat-ip-version=ipv4 \
  --metadata-from-file user-data=vm-config.txt
```

> **Примечание**
> 
>Команды [`yc compute instance create`](https://yandex.cloud/ru/docs/cli/cli-ref/compute/cli-ref/instance/create) | [`create-with-container`](https://yandex.cloud/ru/docs/cli/cli-ref/compute/cli-ref/instance/create-with-container) | [`update`](https://yandex.cloud/ru/docs/cli/cli-ref/compute/cli-ref/instance/update) | [`add-metadata`](https://yandex.cloud/ru/docs/cli/cli-ref/compute/cli-ref/instance/add-metadata) поддерживают подстановку в метаданные ВМ значений переменных окружения. Эти значения, заданные в ключе `user-data` в формате `$<имя_переменной>`, в момент выполнения команды Yandex Cloud CLI будут подставлены в метаданные ВМ из переменных окружения среды, в которой выполняется команда.
>Чтобы изменить такое поведение, не подставлять значение переменной из среды выполнения команды CLI и передать в метаданные ВМ имя переменной в формате `$<имя_переменной>`, используйте синтаксис с двумя символами доллара. Например: `$$<имя_переменной>`.
>Подробнее в разделе [Особенности передачи переменных окружения в метаданных через CLI](https://yandex.cloud/ru/docs/compute/concepts/metadata/sending-metadata#environment-variables).

- **Сохраняем** публичные IP ВМ 

```bash
NET_VM_IP=$(yc compute instance get net-vm --format=json | jq -r '.network_interfaces[0].primary_v4_address.one_to_one_nat.address')
DEV_VM_IP=$(yc compute instance get dev-vm --format=json | jq -r '.network_interfaces[0].primary_v4_address.one_to_one_nat.address')
PROD_VM_IP=$(yc compute instance get prod-vm --format=json | jq -r '.network_interfaces[0].primary_v4_address.one_to_one_nat.address')
```

#### Terraform

- **Описываем** входные переменные:

```hcl
variable "user_name" {
  description = "VM User Name"
  default     = "ycuser"
```

## Справочник команд для управления Multi-folder VPC

|**Задача**|**Команда CLI**|**Описание**|
|---|---|---|
|**Создание сети**|`yc vpc network create --folder-name net-folder --name shared-net`|Создание базовой сети в управляющем каталоге|
|**Создание подсети**|`yc vpc subnet create --folder-name net-folder --name subnet-b --network-name shared-net --zone ru-central1-b --range 10.1.12.0/24`|Создание подсети|
|**Перемещение подсети**|`yc vpc subnet move subnet-b --destination-folder-name dev-folder`|Растягивание сети в целевой каталог|
|**Проверка подсетей**|`yc vpc subnet list --folder-name dev-folder`|Аудит подсетей в каталоге|

## Заключение

Архитектурный шаблон **Multi-folder VPC** предоставляет гибкий инструмент для проектирования облачной инфраструктуры. Он позволяет разделять проекты, среды и команды по изолированным каталогам в соответствии с политиками безопасности и минимальных привилегий, сохраняя при этом высокопроизводительное и прозрачное внутреннее сетевое взаимодействие без необходимости настройки сложных межсетевых шлюзов.
