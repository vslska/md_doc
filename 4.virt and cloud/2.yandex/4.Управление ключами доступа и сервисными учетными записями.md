# Управление ключами доступа и сервисными учетными записями в Yandex Cloud

> **Сфера применения:** Облачное администрирование Yandex Cloud, автоматизация инфраструктуры через Terraform, управление доступом и аутентификация сервисных учетных записей.
> 
> **Цель документа:** Систематизированное руководство по созданию сервисных аккаунтов в Yandex Cloud, назначению ролей безопасности, генерации статических ключей в формате JSON и интеграции их с провайдером Terraform.

## Архитектура управления доступом в Yandex Cloud

В Yandex Cloud доступ к ресурсам и автоматизация управления инфраструктурой строятся на базе сервисных аккаунтов (**Service Accounts**). Сервисный аккаунт используется приложениями, виртуальными машинами или системами CI/CD (например, Terraform) для выполнения вызовов API от своего имени.

Plaintext

```
       [ Администратор / CLI ]
                 │
                 ▼
     [ Service Account (YC SA) ]
                 │
                 ├── Назначение ролей (IAM Access Binding на Folder / Cloud)
                 │
                 ▼
     [ Генерация ключа (JSON) ] ──► [ Подключение в Terraform Provider ]
```

## Создание и настройка сервисного аккаунта через Yandex CLI

### Шаг 1: Создание сервисного аккаунта

Для автоматизации развертывания ресурсов создается специализированный сервисный аккаунт (например, `terraform-sa`):

Bash

```
yc iam service-account create --name terraform-sa
```

### Шаг 2: Назначение прав и ролей безопасности

Чтобы сервисный аккаунт мог управлять ресурсами в целевом каталоге, ему назначается соответствующая роль (например, `admin` или `editor`) на уровень папки (`folder`):

Bash

```
yc resource-manager folder add-access-binding <FOLDER_ID> \
  --role admin \
  --subject serviceAccount:<SA_ID>
```

### Шаг 3: Генерация статического ключа доступа

Для аутентификации Terraform в облаке создается статический ключ доступа в формате JSON, который сохраняется в файл `sa-key.json`:

Bash

````
yc iam key create \
  --service-account-name terraform-sa \
  --output sa-key.json \
  --format json
```[cite: 11]

*Внимание: Файл `sa-key.json` содержит конфиденциальные данные и закрытый ключ доступа. Запрещается передавать его в публичные репозитории.*

---

## Интеграция ключа с провайдером Terraform

Полученный файл ключа используется в конфигурации Terraform для инициализации провайдера Yandex Cloud[cite: 11]:

```hcl
terraform {
  required_providers {
    yandex = {
      source = "yandex-cloud/yandex"
    }
  }
}

provider "yandex" {
  service_account_key_file = "sa-key.json"
  folder_id                = "<FOLDER_ID>"
}
```[cite: 11]

## Справочник команд Yandex CLI для работы с ключами

| Задача | Команда | Описание |
|---|---|---|
| **Создание аккаунта** | `yc iam service-account create --name <name>` | Регистрация новой сервисной записи |
| **Назначение роли** | `yc resource-manager folder add-access-binding ...` | Выдача прав доступа на каталог |
| **Создание ключа** | `yc iam key create --service-account-name ...` | Генерация JSON-ключа для авторизации |
| **Список ключей** | `yc iam key list --service-account-name ...` | Просмотр активных ключей аккаунта |
| **Удаление ключа** | `yc iam key delete --id <KEY_ID>` | Отзыв и удаление скомпрометированного ключа |
````
