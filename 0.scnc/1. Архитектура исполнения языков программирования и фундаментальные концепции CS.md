## Стратегии исполнения программного кода

Классическое деление языков на «компилируемые» и «интерпретируемые» условно, так как компиляция или интерпретация — это **стратегия исполнения**, определяемая реализацией среды выполнения (runtime), а не самим языком.


```Plaintext
                        Стратегии исполнения кода
                                    │
  ┌─────────────────────────────────┼─────────────────────────────────┐
  ▼                                 ▼                                 ▼
[ Прямая компиляция ]      [ Гибридная / Байт-код ]          [ Интерпретация / JIT ]
Исходный код ──► AOT       Исходный код ──► Байт-код         Динамический анализ
  ──► Нативный бинарник      ──► Виртуальная машина            компиляция "на лету"
 (C, C++, Rust, Go)         (Python / CPython, Java / JVM)     (JavaScript / V8, PyPy)
```

### Сравнительный анализ стратегий исполнения

| **Параметр / Тип**          | **Компилируемые AOT (Ahead-Of-Time)**                              | **Байт-код + VM (Гибридные)**                                           | **JIT / Динамическая интерпретация**                                       |
| --------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **Механизм работы**         | Преобразование в машинный код целевой архитектуры (`.exe`, `.so`). | Компиляция в промежуточный байт-код (`.pyc`, `.class`), исполняемый VM. | Построчный разбор с компиляцией «горячих» участков в нативный код на лету. |
| **Производительность**      | 🚀 Максимальная (прямое исполнение процессором).                   | ⚖️ Средняя (оверхед виртуальной машины).                                | ⚡ Высокая после разогрева (Warm-up).                                       |
| **Портируемость**           | ❌ Низкая (требуется пересборка под каждую OS/CPU).                 | 🌍 Высокая (нужна только VM для целевой системы).                       | 🌍 Высокая (при наличии соответствующего движка).                          |
| **Скорость обратной связи** | ⏳ Медленная сборка и линковка.                                     | 🔄 Быстрый запуск, доступен REPL.                                       | 🐢 Быстрый старт (REPL).                                                   |
| **Примеры**                 | C, C++, Rust, Go                                                   | Python (CPython), Java, C#                                              | JavaScript (V8), PyPy, LuaJIT                                              |

## Фундаментальные понятия Computer Science

### Алгоритм, Синтаксис и Переменные

- **Алгоритм** — дискретная, детерминированная последовательность инструкций, гарантированно приводящая к решению задачи за конечное число шагов при валидных входных данных.

- **Синтаксис** — формальная система правил, определяющая допустимые комбинации символов и конструкций языка (грамматическая корректность).

    > **Нарушение синтаксиса** фиксируется на этапе разбора (parsing) и приводит к сбою компиляции/трансляции (например, `SyntaxError` или `IndentationError` в Python).

- **Переменная** — именованная ссылка (ярлык) на область памяти, хранящую объект или значение.

    > **Важно:** При присваивании переменных для изменяемых (mutable) объектов копируется _ссылка_, а не сами данные:
    > 
    > ```Python
    > a = [1, 2]
    > b = a        # b ссылается на тот же список
    > b.append(3)  # Изменение b затрагивает a -> a == [1, 2, 3]
    > ```


### Модульность и Вычисления: Функции и Операторы

- **Функция** — логически изолированный, именованный блок кода, реализующий принцип инкапсуляции и декомпозиции (принимает аргументы, исполняет тело, возвращает результат).

    > **Антипаттерн:** Отсутствие явного возврата значения (`return`). В большинстве языков функция в таком случае неявно возвращает пустой указатель/типовой маркер (`None` в Python, `undefined` в JS).

- **Оператор** — семантическая конструкция языка, выполняющая операции над операндами (арифметика, логика, сравнение, присваивание).

    > **Типичная ошибка:** Путаница между оператором присваивания (`=`) и оператором равенства (`==`).


### Качество кода и Управление потоками: Рефакторинг, Троттлинг, Идемпотентность

```
                  Архитектурные концепции
                             │
 ┌───────────────────────────┼───────────────────────────┐
 ▼                           ▼                           ▼
[ Рефакторинг ]             [ Троттлинг ]               [ Идемпотентность ]
Улучшение структуры         Сознательное ограничение    Повторный вызов =
без изменения логики        интенсивности вызовов       тот же результат
```

- **Рефакторинг (Refactoring)** — контролируемое изменение структуры программного кода без изменения его внешнего поведения. Направлен на снижение технического долга, улучшение читаемости и упрощение поддержки.

- **Троттлинг (Throttling)** — механизм искусственного регулирования частоты выполнения операций или обработки запросов за единицу времени для защиты ресурсов системы от перегрузки.

    > **Разграничение:** _Throttling_ регулирует скорость потока внутри системы/сервиса, тогда как _Rate Limiting_ устанавливает жесткий лимит доступных вызовов на границе API для конкретных клиентов.
    
- **Идемпотентность (Idempotency)** — свойство операции, при котором её многократное повторное применение к объекту дает тот же результат и оставляет систему в том же состоянии, что и единичный вызов.


#### Сравнение HTTP-методов REST API по идемпотентности:

|**HTTP-метод**|**Идемпотентен?**|**Пояснение**|
|---|---|---|
|**`GET` / `HEAD`**|✅ Да|Безопасное чтение, не изменяет состояние сервера.|
|**`PUT`**|✅ Да|Полная перезапись ресурса по ключу/ID. 10 одинаковых запросов дадут тот же результат.|
|**`DELETE`**|✅ Да|Удаление ресурса. Повторный вызов вернет статус (например, 404), но состояние ресурса не изменится.|
|**`POST`**|❌ Нет|Создание нового ресурса. Каждая повторная отправка создаст дублирующую запись.|

## Сводная таблица реализации концепций в Python (CPython)

| **Концепция**       | **Реализация в экосистеме Python**                                                                                                             |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **Исполнение**      | `.py` $\rightarrow$ `CPython Compiler` $\rightarrow$ байт-код (`.pyc`) $\rightarrow$ Виртуальная машина (CPython VM).                          |
| **Переменные**      | Всё является объектом (Objects). Переменные — это связки синонимов (pointers/labels) в таблице имён.                                           |
| **Функции**         | Первоклассные объекты (`First-class functions`): `def`, `lambda`, встроенные функции (`len`, `zip`).                                           |
| **Операторы**       | Включают стандартную арифметику, бинарные, логические (`and`/`or`), операторы членства (`in`), тождественности (`is`), walrus-оператор (`:=`). |
| **Рефакторинг**     | Выделение функций/классов, использование декораторов (`@decorator`), устранение дублирования через DRY/SOLID.                                  |
| **Идемпотентность** | Встроенные методы: `dict.setdefault()`, `set.add()`, `list.sort()`.                                                                            |
| **Троттлинг**       | Реализуется через `time.sleep()`, `asyncio.Semaphore`, rate-limitеры в `celery` или библиотеках повторов (`tenacity`).                         |
