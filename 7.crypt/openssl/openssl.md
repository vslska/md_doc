## **Введение**

**OpenSSL** — это набор утилит командной строки, который большинство администраторов используют для создания ключей, CSR и сертификатов X.509, проверки PEM-файлов и конвертации форматов для серверов и клиентов. Данное руководство собирает практические команды *openssl* для ключей RSA и эллиптических кривых (EC), CSR с альтернативными именами субъекта (SAN), самоподписанных сертификатов, верификации, проверки живых TLS-соединений через *`s_client`*, а также рабочих процессов с PEM, DER, PKCS12 и PKCS7. Оно написано для операторов, которые управляют HTTPS на Linux-серверах, отправляют CSR в публичные или частные CA или устраняют проблемы с рукопожатием и доверием.

### Как пользоваться этим руководством

- Если вам нужна информация о CSR, полях DN и неинтерактивном *`-subj`*, начните с разделов «**Что такое OpenSSL и почему это важно для управления SSL/TLS**» и «**Создание запросов на подпись сертификата (CSR)**».
- Используйте раздел «**Генерация приватных ключей с помощью OpenSSL**», когда вам нужны новые материалы RSA или EC, защита паролем или краткое сравнение RSA 2048, RSA 4096 и кривых P-256.
- Перейдите к разделу «**Создание самоподписанных сертификатов**» для лабораторного или внутреннего TLS, где доверие браузера не требуется.
- Используйте разделы «**Проверка и декодирование сертификатов, CSR и ключей**», «Проверка действительности и срока действия сертификата» и «Тестирование живых TLS-соединений с помощью openssl s_client» при валидации файлов или удалённых сервисов.
- Используйте раздел «**Конвертация форматов сертификатов**», когда Windows, Java или устаревшие приложения требуют DER, PFX или пакеты P7B.
- Большинство команд используют перенос строки (`\`) для читаемости; вы можете вставлять их как многострочные блоки или объединять в одну строку.

## Ключевые выводы

- Генерируйте ключи RSA с помощью *`genrsa`* или *`genpkey`*, а ключи EC — с помощью *`ecparam`*, включая опциональное шифрование паролем с AES-256.
- Создавайте CSR с помощью *`-newkey`*, из существующего ключа, из существующего сертификата или из конфигурации OpenSSL, содержащей SAN для DNS-имён и IP-адресов.
- Выпускайте самоподписанные сертификаты для непроизводственного использования, включая SAN через *`-addext`* в OpenSSL 1.1.1 и новее.
- Проверяйте сертификаты и CSR в кодировке PEM, выводите структуру ключа RSA с помощью *`openssl rsa -text`* и подтверждайте соответствие ключа сертификату или CSR с помощью хешей модуля (RSA) или сравнения открытых ключей (EC).
- Читайте *`notBefore`* и *`notAfter`*, проверяйте конечный сертификат по файлу CA и валидируйте цепочку с помощью *`-untrusted`* для промежуточных сертификатов в соответствии с практикой Baseline Requirements CA/Browser Forum.
- Отлаживайте живой TLS с помощью *`openssl s_client`*, включая SNI, проверки TLS 1.2 и TLS 1.3 (RFC 8446) и строки статуса OCSP со stapling.
- Конвертируйте между PEM, DER, PKCS12 (PFX) и PKCS7 (P7B), включая совместимость PKCS12 *`-legacy`*, когда старые клиенты не могут читать современные настройки по умолчанию.

## **Что такое OpenSSL и почему это важно для управления SSL/TLS**

OpenSSL поставляется по умолчанию в большинстве дистрибутивов Linux и предоставляет команду openssl для каждого файлового этапа работы с TLS-сертификатами: генерации ключей, создания CSR, подписи сертификатов, проверки PEM-файлов и конвертации между форматами. Apache, NGINX, HAProxy, Postfix и большинство TLS-библиотек Python и Node.js напрямую линкуются с ним, что означает: тот же инструмент, которым вы выпускаете CSR, генерирует и ключи, которые эти сервисы используют в продакшене.

### Роль OpenSSL в рабочих процессах с сертификатами

Каждый TLS-сертификат проходит пять этапов: генерация ключа, создание CSR, подпись (публичным CA, внутренним CA или самоподписанная), развёртывание в потребляющем сервисе и продление до истечения срока. OpenSSL предоставляет отдельную подкоманду для каждого этапа. Формат сертификата, создаваемого на этапе подписи, соответствует профилю X.509, определённому в RFC 5280.

```
Private Key Generation
        |
        v
   CSR Creation
        |
        v
  CA Signing (or Self-Sign)
        |
        v
Certificate Deployment
        |
        v
  Renewal / Revocation

```

### Ключевые понятия: приватные ключи, CSR и сертификаты

**Приватный ключ:** секретный файл в формате PEM или DER, который должен храниться только на серверах или в HSM под вашим контролем. Он подписывает доказательства в ходе TLS-рукопожатий и никогда не должен передаваться по электронной почте, вставляться в тикеты или попадать в систему контроля версий.

**CSR (запрос на подпись сертификата):** запрос PKCS#10 в кодировке PEM, который объединяет ваш открытый ключ с отличительным именем (DN) и опциональными расширениями (например, SAN). Вы отправляете CSR в CA; CA возвращает сертификат, привязанный к идентичности, без необходимости в вашем приватном ключе.

**Сертификат:** сертификат открытого ключа X.509 (RFC 5280), который связывает имя субъекта (и записи SAN) с открытым ключом, содержит даты действительности и может выстраиваться в цепочку до доверенного корня. Браузеры и TLS-клиенты используют эту привязку при аутентификации сервера.

### Краткая история OpenSSL

OpenSSL ведёт свою родословную от SSLeay — SSL-библиотеки Эрика Янга (Eric Young) из 1990-х, которая легла в основу первых релизов проекта OpenSSL. Уязвимость Heartbleed, раскрытая в 2014 году, затронула расширение TLS heartbeat в OpenSSL 1.0.1 и вызвала широкую скоординированную работу по патчингу, ротации ключей и финансированию поддержки. Сейчас кодовая база находится под управлением OpenSSL Software Foundation. OpenSSL 3.0 вышла в сентябре 2021 года с пятилетним окном поддержки LTS, за ней последовали 3.1 (март 2023), 3.2 (ноябрь 2023), 3.3 (апрель 2024) и 3.4 (октябрь 2024) с примерно ежегодной периодичностью. OpenSSL 1.1.1 достигла конца жизненного цикла в сентябре 2023 года; производственные хосты должны работать на 3.0 LTS или более новой поддерживаемой ветке.

## Генерация приватных ключей с помощью OpenSSL

Приватные ключи — это корень доверия для ваших TLS-идентичностей. Генерируйте их на доверенных хостах, ограничивайте права доступа к файлам (например, `chmod 600` для файлов ключей) и храните парольные фразы вне репозиториев конфигурации, когда ключи зашифрованы.

### Генерация приватного ключа RSA

Эта команда записывает незашифрованный 2048-битный приватный ключ RSA в PEM-файл:

```bash
# genrsa: RSA key generation; -out sets the PEM path; 2048 selects the modulus size in bits
openssl genrsa -out domain.key 2048
```

Пример вывода:

```
Generating RSA private key, 2048 bit long modulus
........................................................................+++++
............+++++
writing new private key to 'domain.key'
```

| Флаг или аргумент     | Назначение                                            |
| --------------------- | ----------------------------------------------------- |
| `genrsa`              | Подкоманда OpenSSL для генерации приватного ключа RSA |
| `-out ==domain.key==` | Путь вывода для ключа в кодировке PEM                 |
| `2048`                | Размер модуля RSA в битах                             |

OpenSSL 3.x продолжает поддерживать `genrsa`, но руководство отдаёт предпочтение [`openssl-genpkey`](https://www.openssl.org/docs/man3.0/man1/openssl-genpkey.html) для новых скриптов, поскольку она унифицирует выбор алгоритма. Эквивалентная генерация RSA:

```bash
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out domain.key
```

| Флаг                            | Назначение                    |
| ------------------------------- | ----------------------------- |
| `-algorithm RSA`                | Сгенерировать пару ключей RSA |
| `-pkeyopt rsa_keygen_bits:2048` | Задать размер модуля RSA      |
| `-out ==domain.key==`           | Путь вывода в PEM             |

### Генерация приватного ключа EC (эллиптическая кривая)

Эта команда генерирует приватный ключ EC P-256 (`prime256v1`) в формате PEM:

```bash
openssl ecparam -genkey -name prime256v1 -noout -out ec.key
```

| Флаг               | Назначение                                                     |
| ------------------ | -------------------------------------------------------------- |
| `ecparam`          | Утилита генерации параметров и ключей EC                       |
| `-genkey`          | Сгенерировать приватный ключ из указанной кривой               |
| `-name prime256v1` | Использовать кривую NIST P-256 (широко поддерживается для TLS) |
| `-noout`           | Не выводить параметры EC в stdout                              |
| `-out ==ec.key==`  | Записать ключ в PEM на диск                                    |
Ключ EC P-256 обеспечивает безопасность, сопоставимую с RSA 3072, при доле байтового размера (256 бит против 3072 бит). На современном оборудовании x86 подпись P-256 примерно на порядок быстрее подписи RSA 2048, что снижает нагрузку на CPU сервера при высокой частоте рукопожатий. Верификация — обратная ситуация (RSA проверяется быстрее, чем P-256), но TLS-серверы подписывают один раз за рукопожатие, а клиенты верифицируют, поэтому асимметрия благоприятствует EC на стороне сервера.

### Генерация приватного ключа, защищённого паролем

Эта команда создаёт новый 2048-битный ключ RSA, зашифрованный с помощью AES-256:

```bash
openssl genrsa -aes256 -out domain.key 2048
```

|Флаг|Назначение|
|---|---|
|`genrsa`|Сгенерировать приватный ключ RSA|
|`-aes256`|Зашифровать ключ PEM с помощью AES-256 перед записью|
|`-out ==domain.key==`|Путь вывода|
|`2048`|Размер модуля RSA в битах|

При запросе вы вводите парольную фразу. В старой документации часто фигурирует `-des3`; Triple-DES остаётся доступным для совместимости, но AES-256 — лучший выбор по умолчанию для новых ключей.

Этот устаревший вызов встречается в старых руководствах и по-прежнему работает, когда нужно соответствовать ожиданиям от PEM, зашифрованных Triple-DES:

```bash
openssl genrsa -des3 -out domain.key 2048
```

| Флаг    | Назначение                                  |
| ------- | ------------------------------------------- |
| `-des3` | Зашифровать новый ключ с помощью Triple-DES |
| `-out`  | Путь вывода в PEM                           |
| `2048`  | Размер модуля RSA                           |

 **Зашифровать существующий незашифрованный ключ** (тот же класс операций, что и защита материала при хранении):

```bash
openssl rsa -aes256 \
       -in unencrypted.key \
       -out encrypted.key
```

| Флаг                      | Назначение                                  |
| ------------------------- | ------------------------------------------- |
| `rsa`                     | Команда обработки ключа RSA                 |
| `-aes256`                 | Зашифровать выходной ключ с помощью AES-256 |
| `-in ==unencrypted.key==` | Существующий приватный ключ PEM             |
| `-out ==encrypted.key==`  | Зашифрованный вывод в PEM                   |
|                           |                                             |

Шифрование Triple-DES для существующего ключа RSA соответствует старому шаблону `openssl rsa -des3`:

```bash
openssl rsa -des3 \
       -in unencrypted.key \
       -out encrypted.key
```

|Флаг|Назначение|
|---|---|
|`-des3`|Зашифровать с помощью Triple-DES|
|`-in`|Исходный ключ PEM|
|`-out`|Зашифрованный приёмник PEM|

 **Расшифровать зашифрованный ключ** (требуется парольная фраза):

```bash
openssl rsa \
       -in encrypted.key \
       -out decrypted.key
```

| Флаг                     | Назначение                     |
| ------------------------ | ------------------------------ |
| `rsa`                    | Команда обработки ключа RSA    |
| `-in ==encrypted.key==`  | Зашифрованный входной файл PEM |
| `-out ==decrypted.key==` | Расшифрованный вывод в PEM     |

### RSA 2048 vs 4096 vs EC 256: когда что использовать

|Тип ключа|Приблизительный уровень безопасности|Подпись (относительно RSA 2048)|Верификация (относительно RSA 2048)|Рекомендуемый сценарий использования|
|---|---|---|---|---|
|RSA 2048|~112 бит|1x (базовый)|1x (базовый)|По умолчанию для публичного HTTPS; широкая совместимость с клиентами|
|RSA 4096|~140 бит|~5x–7x медленнее|~3x медленнее|Внутренние CA, регулируемые среды с требованием более длинных ключей, корневые или промежуточные CA|
|EC P-256 (`prime256v1`)|~128 бит|~10x–20x быстрее|~3x–5x медленнее|Современные веб-серверы, CDN, развёртывания mTLS с поддержкой EC по всей цепочке|

Для реальных цифр на вашем оборудовании запустите `openssl speed rsa2048 rsa4096 ecdsap256`. Относительные соотношения выше справедливы на большинстве серверов x86_64; абсолютная пропускная способность зависит от CPU, наличия AES-NI и набора шифров.
