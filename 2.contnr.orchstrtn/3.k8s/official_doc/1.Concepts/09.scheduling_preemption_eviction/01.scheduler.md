В Kubernetes **планирование** (scheduling) означает обеспечение соответствия Pod'ов узлам (Nodes), чтобы kubelet мог их запускать.

## Обзор планирования

Планировщик **наблюдает** за вновь созданными Pod'ами, которым не назначен узел. Для каждого обнаруженного Pod'а планировщик отвечает за поиск **лучшего узла** для его запуска. Это решение о размещении принимается с учётом принципов планирования, описанных ниже.

Если вы хотите понять, почему Pod'ы размещаются на конкретном узле, или планируете реализовать собственный планировщик, эта страница поможет изучить планирование.

## kube-scheduler

**kube-scheduler** — планировщик по умолчанию для Kubernetes, работает как часть плоскости управления. kube-scheduler спроектирован так, что при желании и необходимости можно написать собственный компонент планирования и использовать его вместо стандартного.

kube-scheduler выбирает **оптимальный узел** для запуска вновь созданных или ещё не запланированных Pod'ов. Поскольку контейнеры в Pod'ах — и сами Pod'ы — могут иметь разные требования, планировщик **отфильтровывает** узлы, не удовлетворяющие конкретным потребностям Pod'а в планировании. В качестве альтернативы API позволяет указать узел для Pod'а при его создании, но это **необычно** и делается только в особых случаях.

В кластере узлы, удовлетворяющие требованиям планирования для Pod'а, называются **feasible nodes** (подходящие узлы). Если ни один узел не подходит, Pod остаётся **незапланированным**, пока планировщик не сможет его разместить.

Планировщик находит подходящие узлы для Pod'а, затем запускает набор функций для **оценки** (scoring) подходящих узлов и выбирает узел с **наивысшей оценкой** среди подходящих. Затем планировщик уведомляет API-сервер об этом решении в процессе, называемом **binding** (привязка).

Факторы, которые нужно учитывать при решениях о планировании, включают: индивидуальные и коллективные требования к ресурсам, ограничения аппаратного/программного обеспечения/политик, спецификации affinity и anti-affinity, локальность данных, взаимовлияние workload'ов и т.д.

## Выбор узла в kube-scheduler

kube-scheduler выбирает узел для Pod'а в **два шага**:

1. **Filtering** (фильтрация)
2. **Scoring** (оценка)

### Фильтрация

Шаг фильтрации находит набор узлов, где **возможно** запланировать Pod. Например, фильтр `PodFitsResources` проверяет, достаточно ли на узле-кандидате доступных ресурсов для конкретных запросов Pod'а. После этого шага список узлов содержит подходящие узлы; часто их **больше одного**. Если список пуст, Pod **(пока) не планируем**.

### Оценка

На шаге оценки планировщик **ранжирует** оставшиеся узлы, чтобы выбрать наиболее подходящее размещение Pod'а. Планировщик назначает **оценку** каждому узлу, прошедшему фильтрацию, основываясь на активных правилах оценки.

### Привязка

Наконец, kube-scheduler назначает Pod узлу с **наивысшим рангом**. Если есть более одного узла с равными оценками, kube-scheduler выбирает один из них **случайным образом**.

## Способы настройки поведения

Есть два поддерживаемых способа настроить поведение фильтрации и оценки планировщика:

| Способ                  | Что настраивает                                                                                                                                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Scheduling Policies** | Позволяют настроить **Predicates** для фильтрации и **Priorities** для оценки                                                                                                                                             |
| **Scheduling Profiles** | Позволяют настроить **Plugins**, реализующие разные этапы планирования, включая: `QueueSort`, `Filter`, `Score`, `Bind`, `Reserve`, `Permit` и другие. Также можно настроить kube-scheduler на запуск **разных профилей** |
