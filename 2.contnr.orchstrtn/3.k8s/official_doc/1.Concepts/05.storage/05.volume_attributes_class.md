## Назначение и общая модель

`VolumeAttributesClass` (VAC) предоставляет администраторам способ описывать **изменяемые** «классы» хранилища. Разные классы могут соответствовать разным уровням качества обслуживания. Сам Kubernetes не навязывает, что именно представляют эти классы.

**Ключевое отличие от StorageClass**: StorageClass определяет параметры при создании тома и неизменяем для существующих PV. `VolumeAttributesClass` позволяет **менять параметры уже работающего тома на лету** — без изменения размера и без пересоздания PV.

**Статус функции**: GA с Kubernetes v1.34 (можно отключить). В v1.36 функция помечена как стабильная и **включена по умолчанию**; отключить её больше нельзя — если явно задать значение feature gate `VolumeAttributesClass`, Kubernetes его проигнорирует без ошибки .

**Критическое ограничение**: `VolumeAttributesClass` работает **только с хранилищем на основе Container Storage Interface (CSI)**, и только если соответствующий CSI-драйвер реализует **`ModifyVolume` API** .

## API-объект

Каждый `VolumeAttributesClass` содержит поля `driverName` и `parameters`, используемые при динамическом создании или модификации PV, принадлежащего классу.

```yaml
apiVersion: storage.k8s.io/v1
kind: VolumeAttributesClass
metadata:
  name: silver
driverName: csi.storage.example.com
parameters:
  iops: "3000"
  throughput: "50Mi"
```

Имя объекта `VolumeAttributesClass` значимо — именно так пользователи запрашивают конкретный класс. Хотя имя `VolumeAttributesClass` в PVC **изменяемо**, параметры внутри существующего класса **неизменяемы** .

### Provisioner

Каждый `VolumeAttributesClass` имеет provisioner, определяющий, какой плагин тома используется для создания PV. Поле `driverName` **обязательно**. Поддержка функции реализована в `kubernetes-csi/external-provisioner`. Можно использовать и другие внешние provisioner'ы, следующие спецификации Kubernetes .

### Resizer

Каждый `VolumeAttributesClass` имеет resizer, определяющий, какой плагин тома используется для модификации PV. Поле `driverName` **обязательно**. Поддержка модификации томов реализована в `kubernetes-csi/external-resizer` .

**Пример изменения параметров на лету**: существующий PVC использует `VolumeAttributesClass` с именем `silver`. В кластере появляется новый класс `gold` с другими параметрами. Конечный пользователь обновляет PVC, указывая `volumeAttributesClassName: gold`, и применяет изменения. CSI-драйвер через `external-resizer` вызывает `ModifyVolume` API и применяет новые параметры к тому .

## Параметры

Параметры `VolumeAttributesClass` описывают тома, принадлежащие классу. Допустимые параметры зависят от provisioner'а или resizer'а. Например, значение `4000` для параметра `iops` и параметр `throughput` специфичны для GCE PD. Если параметр опущен, при создании тома используется значение по умолчанию. Если пользователь применяет PVC с другим `VolumeAttributesClass` с опущенными параметрами, значение по умолчанию может зависеть от реализации CSI-драйвера .

**Ограничения**: максимум **512 параметров** в одном `VolumeAttributesClass`. Общая длина объекта `parameters`, включая ключи и значения, не может превышать **256 KiB** .

## Поддержка CSI-драйверами

| CSI-драйвер | Поддержка VAC | Что можно менять |
|---|---|---|
| **Amazon EBS CSI** | ✅ Да | Тип тома (gp2 → gp3, io1 → io2), IOPS, throughput  |
| **GCE Persistent Disk CSI** (`pd.csi.storage.gke.io`) | ✅ Да | IOPS, throughput  |
| **Azure Disk CSI** | Зависит от версии | Проверяйте документацию вендора |
| **NFS CSI** | ❌ Нет | NFS не поддерживает изменение параметров |
| **Local storage** | ❌ Нет | Локальные диски не поддерживают online-модификацию |

Для AWS EBS CSI драйвера требуется версия **v1.35.0+** для поддержки `VolumeAttributesClass` . Для GCP PD CSI драйвера на некоторых типах инстансов (например, Hyperdisk) могут быть дополнительные требования к типу кластера .

## Новые возможности в GA (v1.34)

По сравнению с Beta, GA-версия принесла две важные функции :

### Поддержка отмены при ошибках

Если запрошенная модификация тома не может быть применена (например, из-за недопустимых аргументов или ограничений хранилища), пользователи могут **отменить операцию и вернуть том к предыдущей стабильной конфигурации**. Это предотвращает оставление тома в несогласованном состоянии.

### Поддержка квот на основе scope

Хотя `VolumeAttributesClass` не добавляет новый тип квоты, плоскость управления Kubernetes может применять квоты к PVC, ссылающимся на конкретный `VolumeAttributesClass`. Это достигается через поле `scopeSelector` в `ResourceQuota`, которое нацеливается на PVC с `.spec.volumeAttributesClassName`, установленным в определённое имя класса .

## Практическое использование

### Создание классов

```yaml
# Silver: базовый уровень
apiVersion: storage.k8s.io/v1
kind: VolumeAttributesClass
metadata:
  name: silver
driverName: ebs.csi.aws.com
parameters:
  type: gp3
  iops: "3000"
  throughput: "125"
---
# Gold: высокопроизводительный уровень
apiVersion: storage.k8s.io/v1
kind: VolumeAttributesClass
metadata:
  name: gold
driverName: ebs.csi.aws.com
parameters:
  type: io2
  iops: "10000"
```

### Создание PVC с VAC

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-db-pvc
spec:
  accessModes: [ReadWriteOnce]
  storageClassName: fast-ssd
  volumeAttributesClassName: silver
  resources:
    requests:
      storage: 100Gi
```

### Изменение параметров на лету

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-db-pvc
spec:
  accessModes: [ReadWriteOnce]
  storageClassName: fast-ssd
  volumeAttributesClassName: gold   # изменено с silver на gold
  resources:
    requests:
      storage: 100Gi
```

После применения PVC `external-resizer` инициирует `ModifyVolume` через CSI-драйвер. Том в облаке изменит параметры без downtime (если CSI поддерживает online-модификацию).
