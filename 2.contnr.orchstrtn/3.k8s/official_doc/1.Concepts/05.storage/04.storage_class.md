## Назначение и общая модель

`StorageClass` предоставляет администраторам способ описать классы хранилища, которые они предлагают. Разные классы могут соответствовать уровням качества обслуживания, политикам резервного копирования или произвольным политикам, определённым администраторами кластера. Сам Kubernetes не навязывает, что именно представляют классы. Концепция storage class аналогична «профилям» в некоторых других системах хранения.

Каждый `StorageClass` содержит поля `provisioner`, `parameters` и `reclaimPolicy`, используемые при динамическом создании PersistentVolume, принадлежащего классу, для удовлетворения PersistentVolumeClaim (PVC). Имя объекта `StorageClass` значимо — именно так пользователи запрашивают конкретный класс.

## Структура StorageClass

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: low-latency
  annotations:
    storageclass.kubernetes.io/is-default-class: "false"
provisioner: csi-driver.example-vendor.example
reclaimPolicy: Retain # по умолчанию Delete
allowVolumeExpansion: true
mountOptions:
  - discard # может включить UNMAP / TRIM на уровне блочного хранилища
volumeBindingMode: WaitForFirstConsumer
parameters:
  guaranteedReadWriteLatency: "true" # зависит от провайдера
```

## Ключевые поля

| Поле | Обязательное | По умолчанию | Назначение |
|---|---|---|---|
| **provisioner** | Да | — | Определяет, какой плагин тома используется для создания PV |
| **parameters** | Нет | — | Параметры, зависящие от provisioner; максимум 512 параметров, общая длина объекта parameters с ключами и значениями не может превышать 256 KiB |
| **reclaimPolicy** | Нет | `Delete` | Политика возврата для динамически созданных PV: `Delete` или `Retain` |
| **allowVolumeExpansion** | Нет | `false` | Разрешает расширение томов путём редактирования PVC |
| **mountOptions** | Нет | — | Опции монтирования для динамически созданных PV |
| **volumeBindingMode** | Нет | `Immediate` | Когда происходит связывание и динамическое создание: `Immediate` или `WaitForFirstConsumer` |
| **allowedTopologies** | Нет | — | Ограничение топологии создаваемых томов |

## Provisioner

Каждый `StorageClass` имеет provisioner, определяющий, какой плагин тома используется. Это поле обязательно. Встроенные (internal) provisioner'ы имеют имена с префиксом `kubernetes.io` и поставляются вместе с Kubernetes. Однако можно использовать и внешние provisioner'ы — независимые программы, следующие спецификации Kubernetes.

**Важно об актуальности**: встроенные in-tree драйверы для облачных провайдеров (AWS EBS, Azure Disk, GCE PD и др.) устарели и удалены; для них следует использовать соответствующие CSI-драйверы. Внутренний provisioner Ceph RBD устарел с v1.28, рекомендуется CephFS/RBD CSI driver. Для NFS внутреннего provisioner'а нет — требуется внешний provisioner.

## Reclaim policy

PV, динамически созданные `StorageClass`, имеют политику возврата, указанную в поле `reclaimPolicy`, которая может быть `Delete` или `Retain`. Если `reclaimPolicy` не указана при создании `StorageClass`, по умолчанию используется `Delete`. PV, созданные вручную и управляемые через `StorageClass`, имеют ту политику, которая была назначена им при создании.

**Практическое следствие**: при `Retain` после удаления PVC PV переходит в статус `Released`, но не удаляется; предыдущие данные остаются на томе, и том не доступен для нового claim'а, пока администратор вручную не восстановит его .

## Volume expansion

PV можно настроить как расширяемые: это позволяет изменять размер тома, редактируя соответствующий объект PVC и запрашивая больший объём хранилища. Для этого `allowVolumeExpansion` в `StorageClass` должен быть установлен в `true`.

Типы томов, поддерживающие расширение (при включённом `allowVolumeExpansion`): Azure File, CSI, FlexVolume, Portworx, rbd. **Только увеличение, не уменьшение**.

## Mount options

PV, динамически созданные `StorageClass`, получают опции монтирования, указанные в поле `mountOptions`. Если плагин тома не поддерживает опции монтирования, а они указаны, создание завершится ошибкой. Опции монтирования не валидируются ни в классе, ни в PV; при неверной опции монтирование PV завершится ошибкой.

## Volume binding mode

Поле `volumeBindingMode` управляет тем, когда должно происходить связывание тома и динамическое создание. Если не задано, используется режим `Immediate`.

**Immediate**: связывание и динамическое создание происходят сразу при создании PVC. Для бэкендов хранения, ограниченных топологией и не доступных глобально со всех узлов, PV будут связаны или созданы без учёта требований планирования Pod'а. Это может привести к неразмещаемым Pod'ам .

**WaitForFirstConsumer**: откладывает связывание и создание PV до создания Pod'а, использующего PVC. PV выбираются или создаются в соответствии с топологией, заданной ограничениями планирования Pod'а, включая требования к ресурсам, node selectors, pod affinity/anti-affinity, taints и tolerations .

**Поддержка WaitForFirstConsumer**:
- Динамическое создание: CSI-тома, если конкретный CSI-драйвер поддерживает это.
- Связывание с предварительно созданными PV: CSI-тома (если драйвер поддерживает) и `local` .

**Важное предупреждение**: при использовании `WaitForFirstConsumer` **не используйте `nodeName`** в спецификации Pod'а для указания node affinity. Если `nodeName` используется, планировщик обходится, и PVC останется в состоянии pending. Вместо этого используйте node selector для `kubernetes.io/hostname` .

## Allowed topologies

Когда оператор кластера указывает `WaitForFirstConsumer`, в большинстве ситуаций нет необходимости ограничивать создание конкретными топологиями. Однако если это всё же требуется, можно указать `allowedTopologies`. Пример ограничивает топологию создаваемых томов конкретными зонами:

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: standard
provisioner: example.com/example
parameters:
  type: pd-standard
volumeBindingMode: WaitForFirstConsumer
allowedTopologies:
- matchLabelExpressions:
  - key: topology.kubernetes.io/zone
    values:
    - us-central-1a
    - us-central-1b
```

## StorageClass по умолчанию

Можно пометить `StorageClass` как класс по умолчанию для кластера. Когда PVC не указывает `storageClassName`, используется класс по умолчанию.

**Если несколько StorageClass** имеют аннотацию `storageclass.kubernetes.io/is-default-class: "true"` и создаётся PVC без `storageClassName`, Kubernetes использует **наиболее недавно созданный** класс по умолчанию. Рекомендуется иметь только один класс по умолчанию; множественность допускается для бесшовной миграции.

Можно создать PVC без `storageClassName`, даже если класса по умолчанию не существует. В этом случае PVC создаётся как определено, а его `storageClassName` остаётся незаданным, пока не появится класс по умолчанию. Когда класс по умолчанию становится доступным, плоскость управления идентифицирует существующие PVC без `storageClassName` (с пустым значением или без ключа) и обновляет их, устанавливая `storageClassName` в новый класс по умолчанию. PVC с `storageClassName: ""` **не обновляется**.

## Примеры для популярных CSI-драйверов

### AWS EBS

Встроенный драйвер `awsElasticBlockStore` удалён; используется CSI-драйвер `ebs.csi.aws.com`:

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: ebs-sc
provisioner: ebs.csi.aws.com
volumeBindingMode: WaitForFirstConsumer
parameters:
  csi.storage.k8s.io/fstype: xfs
  type: io1
  iopsPerGB: "50"
  encrypted: "true"
  tagSpecification_1: "key1=value1"
allowedTopologies:
- matchLabelExpressions:
  - key: topology.ebs.csi.aws.com/zone
    values:
    - us-east-2c
```

### AWS EFS

Используется out-of-tree CSI-драйвер `efs.csi.aws.com`:

```yaml
kind: StorageClass
apiVersion: storage.k8s.io/v1
metadata:
  name: efs-sc
provisioner: efs.csi.aws.com
parameters:
  provisioningMode: efs-ap
  fileSystemId: fs-92107410
  directoryPerms: "700"
```

- `provisioningMode`: тип тома, создаваемого Amazon EFS; поддерживается только создание на основе access point (`efs-ap`).
- `fileSystemId`: файловая система, в которой создаётся access point.
- `directoryPerms`: права доступа к корневому каталогу, созданному access point.

### NFS

Внутреннего NFS provisioner'а в Kubernetes нет — нужен внешний provisioner. Рекомендуется NFS CSI driver:

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: example-nfs
provisioner: example.com/external-nfs
parameters:
  server: nfs-server.example.com
  path: /share
  readOnly: "false"
```

- `server`: hostname или IP-адрес NFS-сервера.
- `path`: путь, экспортируемый NFS-сервером.
- `readOnly`: флаг, указывающий, будет ли хранилище смонтировано только для чтения (по умолчанию `false`).

### Local

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: local-storage
provisioner: kubernetes.io/no-provisioner # указывает, что этот StorageClass не поддерживает автоматическое создание
volumeBindingMode: WaitForFirstConsumer
```

Локальные тома **не поддерживают динамическое создание** в Kubernetes 1.37; однако `StorageClass` всё равно следует создать, чтобы отложить связывание тома до фактического планирования Pod'а на подходящий узел. Это задаётся режимом `WaitForFirstConsumer`. Отсрочка связывания позволяет планировщику учесть все ограничения планирования Pod'а при выборе подходящего PV для PVC .

### Ceph RBD (устарело с v1.28)

Внутренний provisioner `kubernetes.io/rbd` устарел; рекомендуется CephFS/RBD CSI driver.

### Azure File (устарело)

Пример для `kubernetes.io/azure-file`:

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: azurefile
provisioner: kubernetes.io/azure-file
parameters:
  skuName: Standard_LRS
  location: eastus
  storageAccount: azure_storage_account_name
```

- `skuName`: уровень SKU учётной записи хранения Azure.
- `location`: расположение учётной записи хранения.
- `storageAccount`: имя учётной записи хранения. Если не указано, ищутся все учётные записи, связанные с группой ресурсов, с совпадением `skuName` и `location`.
- `secretNamespace`: namespace секрета с именем и ключом учётной записи; по умолчанию совпадает с Pod'ом.
- `secretName`: имя секрета; по умолчанию `azure-storage-account-<accountName>-secret`.
- `readOnly`: флаг монтирования только для чтения (по умолчанию `false`).

При создании хранилища создаётся секрет с именем, указанным в `secretName`, для учётных данных монтирования. Если в кластере включены и RBAC, и Controller Roles, добавьте разрешение `create` для ресурса `secret` в clusterrole `system:controller:persistent-volume-binder`. В multi-tenancy контексте настоятельно рекомендуется явно задавать `secretNamespace`, иначе учётные данные учётной записи хранения могут быть прочитаны другими пользователями.
