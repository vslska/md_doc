# Финализаторы (Finalizers)

2. [[#Owner references, метки и финализаторы|Owner references, метки и финализаторы]]

Финализаторы — это ключи в пространстве имён, которые указывают Kubernetes подождать выполнения определённых условий, прежде чем полностью удалить помеченные на удаление ресурсы. Финализаторы уведомляют контроллеры о необходимости очистить ресурсы, которыми владел удаляемый объект.

Когда вы указываете Kubernetes удалить объект, для которого заданы финализаторы, API Kubernetes помечает объект на удаление, заполняя `.metadata.deletionTimestamp`, и возвращает код состояния 202 (HTTP «Accepted»). Целевой объект остаётся в состоянии завершения (terminating), пока плоскость управления или другие компоненты выполняют действия, определённые финализаторами. После завершения этих действий контроллер удаляет соответствующие финализаторы из целевого объекта. Когда поле `metadata.finalizers` пусто, Kubernetes считает удаление завершённым и удаляет объект.

Финализаторы можно использовать для управления сборкой мусора (garbage collection) ресурсов. Например, можно определить финализатор, который очищает связанные API-ресурсы или инфраструктуру до того, как контроллер удалит финализируемый объект.

Финализаторы позволяют управлять сборкой мусора объектов, уведомляя контроллеры о необходимости выполнить конкретные задачи очистки перед удалением целевого ресурса.

Финализаторы обычно не содержат код для выполнения. Вместо этого они, как правило, представляют собой списки ключей на конкретном ресурсе, подобно аннотациям. Некоторые финализаторы Kubernetes задаёт автоматически, но вы можете задавать и свои собственные.

## Как работают финализаторы

При создании ресурса из файла манифеста можно указать финализаторы в поле `metadata.finalizers`. Когда вы пытаетесь удалить ресурс, API-сервер, обрабатывающий запрос на удаление, замечает значения в поле `finalizers` и делает следующее:

1. Изменяет объект, добавляя поле `metadata.deletionTimestamp` со временем начала удаления.
2. Не даёт удалить объект, пока все элементы не будут удалены из его поля `metadata.finalizers`.
3. Возвращает код состояния 202 (HTTP «Accepted»).

Контроллер, управляющий этим финализатором, замечает обновление объекта, устанавливающее `metadata.deletionTimestamp`, — это означает, что запрошено удаление объекта. Затем контроллер пытается выполнить требования финализаторов, заданных для этого ресурса. Каждый раз, когда условие финализатора выполнено, контроллер удаляет этот ключ из поля `finalizers` ресурса. Когда поле `finalizers` опустеет, объект с установленным полем `deletionTimestamp` удаляется автоматически. Финализаторы также можно использовать, чтобы предотвратить удаление неуправляемых ресурсов.

Распространённый пример финализатора — `kubernetes.io/pv-protection`, который предотвращает случайное удаление объектов PersistentVolume. Когда PersistentVolume используется Pod'ом, Kubernetes добавляет финализатор `pv-protection`. Если вы попытаетесь удалить PersistentVolume, он перейдёт в статус Terminating, но контроллер не сможет его удалить из-за наличия финализатора. Когда Pod перестанет использовать PersistentVolume, Kubernetes снимает финализатор `pv-protection`, и контроллер удаляет том.

> **Примечание:**
> - При выполнении DELETE для объекта Kubernetes добавляет этому объекту метку времени удаления и сразу же начинает ограничивать изменения поля `.metadata.finalizers` для объекта, ожидающего удаления. Вы можете удалять существующие финализаторы (удаляя запись из списка `finalizers`), но не можете добавлять новый финализатор. Также нельзя изменить `deletionTimestamp` у объекта после того, как он установлен.
> - После запроса удаления «воскресить» этот объект нельзя. Единственный способ — удалить его и создать новый похожий объект.

> **Примечание:** Имена пользовательских финализаторов должны быть публично квалифицированными, например `example.com/finalizer-name`. Kubernetes обеспечивает соблюдение этого формата; API-сервер отклоняет записи в объекты, где для любого пользовательского финализатора не используется квалифицированное имя.

## Owner references, метки и финализаторы

Как и метки, owner references (ссылки на владельца) описывают связи между объектами в Kubernetes, но служат для другой цели. Когда контроллер управляет объектами, например Pod'ами, он использует метки для отслеживания изменений групп связанных объектов. Например, когда Job создаёт один или несколько Pod'ов, контроллер Job применяет метки к этим Pod'ам и отслеживает изменения любых Pod'ов в кластере с той же меткой.

Контроллер Job также добавляет к этим Pod'ам owner references, указывающие на Job, создавший эти Pod'ы. Если вы удалите Job, пока эти Pod'ы работают, Kubernetes использует owner references (а не метки), чтобы определить, какие Pod'ы в кластере нужно очистить.

Kubernetes также обрабатывает финализаторы, когда обнаруживает owner references у ресурса, намеченного к удалению.

В некоторых ситуациях финализаторы могут блокировать удаление зависимых объектов, из-за чего целевой объект-владелец может оставаться дольше ожидаемого, не будучи полностью удалённым. В таких ситуациях следует проверить финализаторы и owner references у целевого объекта-владельца и зависимых объектов, чтобы выяснить причину.

> **Примечание:** Если объекты застряли в состоянии удаления, не удаляйте финализаторы вручную, чтобы дать удалению продолжиться. Финализаторы обычно добавляются к ресурсам не просто так, и принудительное их удаление может привести к проблемам в кластере. Это следует делать только тогда, когда назначение финализатора понятно и достигнуто другим способом (например, вручную очищен какой-то зависимый объект).
