Селекторы полей позволяют выбирать объекты Kubernetes по значению одного или нескольких полей ресурса. Примеры запросов с селекторами полей:

```
metadata.name=my-service
metadata.namespace!=default
status.phase=Pending
```

Эта команда kubectl выбирает все Pod'ы, у которых значение поля `status.phase` равно `Running`:

```bash
kubectl get pods --field-selector status.phase=Running
```

> **Примечание:** селекторы полей — это, по сути, фильтры ресурсов. По умолчанию никакие селекторы/фильтры не применяются, то есть выбираются все ресурсы указанного типа. Поэтому запросы `kubectl get pods` и `kubectl get pods --field-selector ""` эквивалентны.

## Поддерживаемые поля

Набор поддерживаемых селекторов полей зависит от типа ресурса. Все типы ресурсов поддерживают поля `metadata.name` и `metadata.namespace`. Использование неподдерживаемого селектора поля приводит к ошибке. Например:

```bash
kubectl get ingress --field-selector foo.bar=baz
```

```
Error from server (BadRequest): Unable to find "ingresses" that match label selector "", field selector "foo.bar=baz": "foo.bar" is not a known field selector: only "metadata.name", "metadata.namespace"
```

### Список поддерживаемых полей

| Kind | Поля |
|---|---|
| Pod | `spec.nodeName`, `spec.restartPolicy`, `spec.schedulerName`, `spec.serviceAccountName`, `spec.hostNetwork`, `status.phase`, `status.podIP`, `status.podIPs`, `status.nominatedNodeName` |
| Event | `involvedObject.kind`, `involvedObject.namespace`, `involvedObject.name`, `involvedObject.uid`, `involvedObject.apiVersion`, `involvedObject.resourceVersion`, `involvedObject.fieldPath`, `reason`, `reportingComponent`, `source`, `type` |
| Secret | `type` |
| Service | `spec.clusterIP`, `spec.type` |
| Namespace | `status.phase` |
| ReplicaSet | `status.replicas` |
| ReplicationController | `status.replicas` |
| Job | `status.successful` |
| Node | `spec.unschedulable` |
| CertificateSigningRequest | `spec.signerName` |

### Поля пользовательских ресурсов (Custom Resources)

Все типы пользовательских ресурсов поддерживают поля `metadata.name` и `metadata.namespace`.

Кроме того, поле `spec.versions[*].selectableFields` в определении CustomResourceDefinition объявляет, какие ещё поля пользовательского ресурса можно использовать в селекторах полей. Подробнее о работе селекторов полей с CustomResourceDefinition см. раздел «selectable fields for custom resources».

## Поддерживаемые операторы

В селекторах полей можно использовать операторы `=`, `==` и `!=` (`=` и `==` означают одно и то же). Например, эта команда kubectl выбирает все Service'ы Kubernetes, которые находятся не в пространстве имён `default`:

```bash
kubectl get services --all-namespaces --field-selector metadata.namespace!=default
```

> **Примечание:** операторы на основе множеств (`in`, `notin`, `exists`) для селекторов полей не поддерживаются.

## Цепочки селекторов

Как и селекторы меток и другие селекторы, селекторы полей можно объединять в список через запятую. Эта команда kubectl выбирает все Pod'ы, у которых `status.phase` не равно `Running` и поле `spec.restartPolicy` равно `Always`:

```bash
kubectl get pods --field-selector=status.phase!=Running,spec.restartPolicy=Always
```

## Несколько типов ресурсов

Селекторы полей можно применять сразу к нескольким типам ресурсов. Эта команда kubectl выбирает все StatefulSet'ы и Service'ы, которые находятся не в пространстве имён `default`:

```bash
kubectl get statefulsets,services --all-namespaces --field-selector metadata.namespace!=default
```
