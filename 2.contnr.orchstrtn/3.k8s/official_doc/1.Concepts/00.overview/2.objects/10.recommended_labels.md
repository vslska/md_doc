Просматривать объекты Kubernetes и управлять ими можно не только через kubectl и dashboard — существует множество инструментов. Общий набор меток позволяет инструментам работать согласованно, описывая объекты единым образом, понятным всем инструментам.

Помимо поддержки инструментов, рекомендуемые метки описывают приложения так, что по ним можно строить запросы.

Метаданные организованы вокруг концепции **приложения**. Kubernetes не является платформой как услуга (PaaS) и не имеет формального понятия «приложение» и не навязывает его. Приложения неформальны и описываются метаданными. Определение того, что входит в приложение, довольно свободное.

> **Примечание:** это **рекомендуемые** метки. Они упрощают управление приложениями, но не обязательны для какого-либо核心-инструмента.

Общие метки и аннотации используют общий префикс: `app.kubernetes.io`. Метки без префикса являются приватными для пользователя. Общий префикс гарантирует, что общие метки не будут конфликтовать с пользовательскими.

## Метки

Чтобы в полной мере воспользоваться этими метками, их следует применять на **каждом** объекте ресурса.

| Ключ | Описание | Пример | Тип |
|---|---|---|---|
| `app.kubernetes.io/name` | Имя приложения | `mysql` | string |
| `app.kubernetes.io/instance` | Уникальное имя, идентифицирующее экземпляр приложения | `mysql-abcxyz` | string |
| `app.kubernetes.io/version` | Текущая версия приложения (например, SemVer 1.0, хеш ревизии и т.д.) | `5.7.21` | string |
| `app.kubernetes.io/component` | Компонент внутри архитектуры | `database` | string |
| `app.kubernetes.io/part-of` | Имя приложения более высокого уровня, частью которого является данное | `wordpress` | string |
| `app.kubernetes.io/managed-by` | Инструмент, используемый для управления работой приложения | `Helm` | string |

Чтобы проиллюстрировать эти метки в действии, рассмотрим следующий объект StatefulSet:

```yaml
# Это фрагмент
apiVersion: apps/v1
kind: StatefulSet
metadata:
  labels:
    app.kubernetes.io/name: mysql
    app.kubernetes.io/instance: mysql-abcxyz
    app.kubernetes.io/version: "5.7.21"
    app.kubernetes.io/component: database
    app.kubernetes.io/part-of: wordpress
    app.kubernetes.io/managed-by: Helm
```

## Приложения и экземпляры приложений

Приложение может быть установлено в кластер Kubernetes один или несколько раз, а в некоторых случаях — и в одно и то же пространство имён. Например, WordPress можно установить более одного раза, где разные сайты — это разные установки WordPress.

Имя приложения и имя экземпляра записываются отдельно. Например, у WordPress есть `app.kubernetes.io/name` со значением `wordpress`, а имя экземпляра представлено как `app.kubernetes.io/instance` со значением `wordpress-abcxyz`. Это позволяет идентифицировать и приложение, и экземпляр приложения. **Каждый экземпляр приложения должен иметь уникальное имя.**

## Примеры

### Простой stateless-сервис

Рассмотрим простой stateless-сервис, развёрнутый с помощью объектов Deployment и Service. Два фрагмента ниже показывают, как метки можно использовать в простейшей форме.

Deployment используется для управления Pod'ами, на которых работает само приложение:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app.kubernetes.io/name: myservice
    app.kubernetes.io/instance: myservice-abcxyz
...
```

Service используется для публикации приложения:

```yaml
apiVersion: v1
kind: Service
metadata:
  labels:
    app.kubernetes.io/name: myservice
    app.kubernetes.io/instance: myservice-abcxyz
...
```

### Веб-приложение с базой данных

Рассмотрим чуть более сложное приложение: веб-приложение (WordPress), использующее базу данных (MySQL), установленное с помощью Helm. Фрагменты ниже иллюстрируют начало объектов, используемых для развёртывания этого приложения.

Начало Deployment для WordPress:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app.kubernetes.io/name: wordpress
    app.kubernetes.io/instance: wordpress-abcxyz
    app.kubernetes.io/version: "4.9.4"
    app.kubernetes.io/managed-by: Helm
    app.kubernetes.io/component: server
    app.kubernetes.io/part-of: wordpress
...
```

Service для публикации WordPress:

```yaml
apiVersion: v1
kind: Service
metadata:
  labels:
    app.kubernetes.io/name: wordpress
    app.kubernetes.io/instance: wordpress-abcxyz
    app.kubernetes.io/version: "4.9.4"
    app.kubernetes.io/managed-by: Helm
    app.kubernetes.io/component: server
    app.kubernetes.io/part-of: wordpress
...
```

MySQL публикуется как StatefulSet с метаданными как для него самого, так и для более крупного приложения, частью которого он является:

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  labels:
    app.kubernetes.io/name: mysql
    app.kubernetes.io/instance: mysql-abcxyz
    app.kubernetes.io/version: "5.7.21"
    app.kubernetes.io/managed-by: Helm
    app.kubernetes.io/component: database
    app.kubernetes.io/part-of: wordpress
...
```

Service для публикации MySQL как части WordPress:

```yaml
apiVersion: v1
kind: Service
metadata:
  labels:
    app.kubernetes.io/name: mysql
    app.kubernetes.io/instance: mysql-abcxyz
    app.kubernetes.io/version: "5.7.21"
    app.kubernetes.io/managed-by: Helm
    app.kubernetes.io/component: database
    app.kubernetes.io/part-of: wordpress
...
```

С MySQL StatefulSet и Service вы заметите, что включена информация как о MySQL, так и о WordPress — более широком приложении.
