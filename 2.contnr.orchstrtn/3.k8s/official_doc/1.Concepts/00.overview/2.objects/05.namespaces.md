В Kubernetes пространства имён предоставляют механизм изоляции групп ресурсов внутри одного кластера. Имена ресурсов должны быть уникальны в пределах пространства имён, но не между пространствами имён. Область действия на основе пространств имён применима только к объектам уровня пространства имён (например, Deployment, Service и т.д.), но не к объектам кластерного уровня (например, StorageClass, Node, PersistentVolume и т.д.).

## Когда использовать несколько пространств имён

Пространства имён предназначены для окружений с множеством пользователей, распределённых по нескольким командам или проектам. Для кластеров с несколькими или десятками пользователей создавать пространства имён или задумываться о них вообще не нужно. Начинайте использовать пространства имён, когда вам нужны предоставляемые ими возможности.

Пространства имён задают область для имён. Имена ресурсов должны быть уникальны в пределах пространства имён, но не между пространствами имён. Пространства имён не могут быть вложены друг в друга, и каждый ресурс Kubernetes может находиться только в одном пространстве имён.

Пространства имён — это способ разделить ресурсы кластера между несколькими пользователями (через квоты ресурсов).

Не обязательно использовать несколько пространств имён для разделения слегка различающихся ресурсов, например разных версий одного программного обеспечения: используйте метки, чтобы различать ресурсы внутри одного пространства имён.

> **Примечание:** для production-кластера рассмотрите вариант не использовать пространство имён `default`. Вместо этого создайте другие пространства имён и используйте их.

## Начальные пространства имён

Kubernetes начинает работу с четырьмя начальными пространствами имён:

- **default** — включается в Kubernetes, чтобы можно было начать использовать новый кластер, не создавая пространство имён заранее.
- **kube-node-lease** — содержит объекты Lease, связанные с каждым узлом. Lease'ы узлов позволяют kubelet отправлять heartbeats, чтобы плоскость управления могла обнаруживать отказ узла.
- **kube-public** — читается всеми клиентами (включая неаутентифицированных). В основном зарезервировано для нужд кластера — на случай, если некоторые ресурсы должны быть видимы и читаемы публично по всему кластеру. Публичность этого пространства имён — лишь соглашение, а не требование.
- **kube-system** — пространство имён для объектов, созданных системой Kubernetes.

## Работа с пространствами имён

Создание и удаление пространств имён описаны в документации Admin Guide для пространств имён.

> **Примечание:** избегайте создания пространств имён с префиксом `kube-`, так как он зарезервирован за системными пространствами имён Kubernetes.

### Просмотр пространств имён

Список текущих пространств имён в кластере:

```bash
kubectl get namespace
```

```
NAME              STATUS   AGE
default           Active   1d
kube-node-lease   Active   1d
kube-public       Active   1d
kube-system       Active   1d
```

### Установка пространства имён для запроса

Чтобы задать пространство имён для текущего запроса, используйте флаг `--namespace`. Например:

```bash
kubectl run nginx --image=nginx --namespace=<вставьте-имя-пространства-имён>
kubectl get pods --namespace=<вставьте-имя-пространства-имён>
```

### Установка предпочтения пространства имён

Можно навсегда сохранить пространство имён для всех последующих команд kubectl в этом контексте:

```bash
kubectl config set-context --current --namespace=<вставьте-имя-пространства-имён>
# Проверка
kubectl config view --minify | grep namespace:
```

## Пространства имён и DNS

При создании Service создаётся соответствующая DNS-запись. Эта запись имеет вид `<имя-сервиса>.<имя-пространства-имён>.svc.cluster.local`, что означает: если контейнер использует только `<имя-сервиса>`, он разрешится в сервис, локальный для пространства имён. Это удобно для использования одной и той же конфигурации в нескольких пространствах имён, например Development, Staging и Production. Если нужно обратиться к другому пространству имён, используйте полностью квалифицированное доменное имя (FQDN).

Как следствие, все имена пространств имён должны быть валидными DNS-метками по RFC 1123.

> **Предупреждение:** создание пространств имён с именами, совпадающими с публичными доменами верхнего уровня (TLD), может привести к тому, что Service'ы в этих пространствах имён получат короткие DNS-имена, пересекающиеся с публичными DNS-записями. Рабочие нагрузки из любого пространства имён, выполняющие DNS-запрос без завершающей точки, будут перенаправлены на эти сервисы в обход публичного DNS.
>
> Чтобы смягчить это, ограничьте права на создание пространств имён доверенными пользователями. При необходимости можно дополнительно настроить сторонние средства безопасности, например admission webhooks, чтобы блокировать создание пространств имён с именами публичных TLD.

## Не все объекты находятся в пространстве имён

Большинство ресурсов Kubernetes (например, Pod, Service, Deployment и другие) находятся в каком-либо пространстве имён. Однако сами ресурсы пространств имён в пространстве имён не находятся. А низкоуровневые ресурсы, такие как Node и PersistentVolume, не находятся ни в каком пространстве имён.

Чтобы увидеть, какие ресурсы Kubernetes находятся в пространстве имён, а какие нет:

```bash
# В пространстве имён
kubectl api-resources --namespaced=true

# Не в пространстве имён
kubectl api-resources --namespaced=false
```

## Автоматическая маркировка

**Состояние функции:** стабильно с Kubernetes v1.22.

Плоскость управления Kubernetes устанавливает неизменяемую метку `kubernetes.io/metadata.name` на все пространства имён. Значение метки — имя пространства имён.
