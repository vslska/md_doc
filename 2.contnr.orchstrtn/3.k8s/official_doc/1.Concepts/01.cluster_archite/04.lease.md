## Что такое Lease

В распределённых системах часто возникает потребность в аренде (lease) — механизме блокировки общих ресурсов и координации активности между членами набора. В Kubernetes концепция аренды представлена объектами `Lease` в группе API `coordination.k8s.io`, которые используются для системно-критичных возможностей, таких как heartbeats узлов и выбор лидера на уровне компонентов .

Lease — это легковесный объект, служащий распределённой блокировкой. Ключевое поле `spec.renewTime` содержит метку времени последнего обновления аренды. Владелец периодически обновляет это поле; если он перестаёт это делать, аренда истекает, и другой экземпляр может её захватить .

## Heartbeats узлов

Kubernetes использует Lease API для передачи heartbeats узлов от kubelet к API-серверу. Для каждого Node существует объект Lease с совпадающим именем в namespace `kube-node-lease`. Каждый heartbeat kubelet — это update-запрос к этому объекту Lease, обновляющий поле `spec.renewTime`. Плоскость управления использует временную метку этого поля для определения доступности узла .

Такой подход легче для etcd, чем полные обновления `.status` узла, особенно в крупных кластерах.

## Выбор лидера

Kubernetes использует Lease для гарантии того, что только один экземпляр компонента активен в любой момент времени. Это применяется компонентами плоскости управления, такими как `kube-controller-manager` и `kube-scheduler`, в HA-конфигурациях, где только один экземпляр должен активно работать, а остальные находятся в режиме ожидания .

### Как работает выбор лидера

Lease действует как легковесная распределённая блокировка, хранящаяся в API-сервере. Все работающие экземпляры компонента наблюдают или периодически читают соответствующий объект Lease, чтобы определить, какой экземпляр в настоящее время является лидером .

Lease API определяет следующие поля:

| Поле | Назначение |
|---|---|
| `holderIdentity` | Идентификатор текущего лидера (например, имя Pod или строка на основе hostname) |
| `acquireTime` | Временная метка получения лидерства |
| `renewTime` | Временная метка последнего обновления аренды лидером |
| `leaseDurationSeconds` | Период действия аренды |
| `leaseTransitions` | Счётчик смены лидерства |

Когда Lease не существует или истёк (текущее время > `renewTime` + `leaseDurationSeconds`), экземпляры-кандидаты пытаются обновить Lease своим идентификатором. Kubernetes полагается на оптимистичный контроль параллелизма через `resourceVersion` объекта: только одно обновление succeeds из-за несовпадения версий при одновременных попытках. Экземпляр, чьё обновление принято, становится лидером .

После избрания лидер периодически обновляет свою аренду, записывая `renewTime` (например, каждые `leaseDurationSeconds ÷ 2`, чтобы избежать конфликтов при приближении истечения аренды). Пока обновления происходят до истечения аренды, текущий лидер сохраняет лидерство. Если лидер падает, становится недоступным или перестаёт обновлять аренду, она истекает, и другие здоровые экземпляры обнаруживают это и пытаются провести новые выборы .

### Освобождение блокировки kube-controller-manager при выходе

**Статус функции**: Alpha с Kubernetes v1.36; отключено по умолчанию .

При включённом feature gate `ControllerManagerReleaseLeaderElectionLockOnExit` компонент `kube-controller-manager` активно освобождает свою блокировку выбора лидера во время переходов лидерства, вместо ожидания истечения TTL блокировки. Это позволяет быстрее избрать нового лидера, снижая задержку перехода лидерства .

## Идентификация API-сервера

**Статус функции**: Beta с Kubernetes v1.26; включено по умолчанию .

Начиная с Kubernetes v1.26, каждый `kube-apiserver` использует Lease API для публикации своей идентичности остальной системе. Хотя само по себе это не особенно полезно, это предоставляет клиентам механизм для обнаружения количества экземпляров `kube-apiserver`, работающих в плоскости управления .

Проверить Lease, принадлежащие каждому `kube-apiserver`, можно, запросив объекты Lease в namespace `kube-system` с именем `apiserver-<sha256-hash>`, или используя селектор меток `apiserver.kubernetes.io/identity=kube-apiserver` :

```bash
kubectl -n kube-system get lease -l apiserver.kubernetes.io/identity=kube-apiserver
```

SHA256-хеш в имени Lease основан на hostname ОС, который видит этот API-сервер. Каждый `kube-apiserver` должен быть настроен на использование hostname, уникального в кластере. Новые экземпляры `kube-apiserver`, использующие тот же hostname, будут принимать существующие Lease с новой идентичностью держателя, а не создавать новые объекты Lease. Проверить hostname, используемый `kube-apiserver`, можно по значению метки `kubernetes.io/hostname` .

Просроченные Lease от `kube-apiserver`, которые больше не существуют, собираются мусора новыми `kube-apiserver` через 1 час. Отключить Lease идентификации API-сервера можно, отключив feature gate `APIServerIdentity` .

## Использование Lease в пользовательских нагрузках

Пользовательские нагрузки могут определять собственное использование Lease. Например, можно запустить кастомный контроллер, где первичный или лидерский член выполняет операции, которые не выполняют его пиры. Определите Lease, чтобы реплики контроллера могли выбирать или избирать лидера, используя Kubernetes API для координации .

**Рекомендация по именованию**: если вы используете Lease, хорошей практикой является определение имени Lease, очевидно связанного с продуктом или компонентом. Например, для компонента с именем Example Foo используйте Lease с именем `example-foo`. Если оператор кластера или другой конечный пользователь может развернуть несколько экземпляров компонента, выберите префикс имени и механизм (например, хеш имени Deployment) для избежания коллизий имён Lease .

### Пример конфигурации выбора лидера с client-go

Библиотека `client-go` предоставляет пакет `leaderelection` для реализации выбора лидера на основе Lease. Типичная конфигурация включает :

| Параметр | Назначение |
|---|---|
| `LeaseDuration` | Как долго не-лидеры ждут перед принудительным захватом лидерства |
| `RenewDeadline` | Как долго действующий лидер повторяет попытки обновления перед отказом |
| `RetryPeriod` | Пауза между попытками действий клиентов LeaderElector |
| `ReleaseOnCancel` | Освобождать лидерство при отмене контекста |

## Практические команды

```bash
# Просмотр Lease всех узлов
kubectl get lease -n kube-node-lease

# Просмотр деталей Lease конкретного узла
kubectl describe lease <node-name> -n kube-node-lease

# Определение текущего лидера kube-scheduler
kubectl get lease kube-scheduler -n kube-system -o jsonpath='{.spec.holderIdentity}'

# Список экземпляров kube-apiserver через Lease
kubectl -n kube-system get lease -l apiserver.kubernetes.io/identity=kube-apiserver

# Просмотр всех Lease в пользовательском namespace
kubectl get lease -n <namespace>
```
