# Система прав доступа Unix: Биты, маски, специальные флаги и ловушки VFS

В основе классической дискреционной модели доступа Linux (POSIX ACL) лежит концепция разделения прав на три категории субъектов: **User (Владелец)**, **Group (Группа)** и **Others (Все остальные)**.

---

## Архитектура масок и битовых сдвигов

На уровне ядра (VFS) права доступа — это 12-битное поле внутри `inode` файла. Каждому базовому праву соответствует строго определенный бит в маске (битовый сдвиг):

| Символ        | Значение   | Бинарный формат | Восьмеричный (Oct) | Физика маски ядра                                          |
| ------------- | ---------- | --------------- | ------------------ | ---------------------------------------------------------- |
| `r` (read)    | Чтение     | `100`           | `4`                | `1 << 2` — Чтение содержимого / листинг директории         |
| `w` (write)   | Запись     | `010`           | `2`                | `1 << 1` — Изменение содержимого / создание файлов в папке |
| `x` (execute) | Выполнение | `001`           | `1`                | `1 << 0` — Запуск бинарника / вход в директорию (`cd`)     |
| `-`           | Нет прав   | `000`           | `0`                | Бит не установлен                                          |

### Как рассчитывается восьмеричное значение

Ядро суммирует биты для каждой из трех групп субъектов (User | Group | Others) независимо:

text

```
Субъекты  :  Owner (User)  │      Group      │     Others
Символы   :       r w x    │      r - x      │      r - -
Бинарные  :       1 1 1    │      1 0 1      │      1 0 0
Сумма бит :      4+2+1=7   │     4+0+1=5     │     4+0+0=4
Результат :  → 0754
```

## Скрытый первый разряд: Специальные биты доступа

В полной восьмеричной нотации всегда используется **четыре знака** (например, `0755`). Первый разряд отвечает за специальные системные флаги ядра. Их сумма рассчитывается аналогично базовым правам:

```
Специальные биты:  SUID (4) │ SGID (2) │ Sticky Bit (1) -> Сумма: 07000
```


### 1. SUID (Set User ID) — Восьмеричная маска `4000` (Символ `s` вместо `x` у владельца)

- **Механика:** Когда обычный пользователь запускает исполняемый файл с установленным SUID-битом, созданный процесс наследует права **владельца этого файла**, а не запустившего его пользователя.
- **Пример в проде:** Утилита `/usr/bin/passwd`. Ей необходим доступ на запись в защищенный файл `/etc/shadow`, куда обычному пользователю писать запрещено. За счет SUID бинарник passwd работает от лица `root`.
- **Установка:** `chmod 4755 file` или `chmod u+s file`.

### 2. SGID (Set Group ID) — Восьмеричная маска `2000` (Символ `s` вместо `x` у группы)

- **Механика для файлов:** Процесс наследует права группы файла.
- **Киллер-фича для директорий:** Если установить SGID на директорию, то **все новые файлы и поддиректории**, созданные внутри неё любыми пользователями, будут автоматически наследовать группу этой родительской директории (а не первичную группу пользователя, который файл создал).
- **Пример в проде:** Общая папка для команды разработчиков или каталог веб-сервера (`/var/www/html`), где пишут и `nginx`, и `deploy-user`.
- **Установка:** `chmod 2775 dir` или `chmod g+s dir`.

### 3. Sticky Bit (Липкий бит) — Восьмеричная маска `1000` (Символ `t` вместо `x` у остальных)

- **Механика:** Запрещает пользователям удалять или переименовывать файлы внутри директории, если они не являются **прямыми владельцами** этих файлов (даже если у самой директории стоят права на запись `0777`).
- **Пример в проде:** Системный каталог временных файлов `/tmp`. Все могут писать туда, но никто не может стереть чужие временные сессии.
- **Установка:** `chmod 1777 dir` или `chmod +t dir`.

## Практический справочник (Cheat Sheet)

|Тип|Символы|Oct|Применение|
|---|---|---|---|
|**Общее**|`rwxrwxrwx`|`0777`|Временные общие папки. **Опасно**.|
|**Bin**|`rwxr-xr-x`|`0755`|Исполняемые файлы, скрипты.|
|**App**|`rwxr-x---`|`0750`|Сервисные каталоги приложений.|
|**Config**|`rw-r--r--`|`0644`|Публичные конфиги, статика Nginx.|
|**Secret**|`rw-r-----`|`0640`|Конфиги с паролями (для группы).|
|**Key**|`rw-------`|`0600`|SSH-ключи, `.kube/config`.|
|**Home**|`rwx------`|`0700`|Домашние директории (`/root`).|
|**Shared**|`rwxr-s---`|`2750`|Каталог с автонаследованием группы (SGID).|
|**Tmp**|`drwxrwxrwt`|`1777`|Обменник с защитой (Sticky Bit).|

## Критические ловушки VFS продакшена

### 1. Ловушка удаления (`o-w` не защищает)

Запрет записи на файл (`chmod 640 file`) не защищает его от удаления. Права на удаление определяются **родительской директорией**. Если у папки `777`, любой процесс может удалить файл внутри, даже если сам файл `000`.

### 2. Ловушка рекурсии (`X` против `x`)

При `chmod -R +x` исполняемыми станут и файлы (картинки, конфиги), что небезопасно.  
**Решение:** Используйте `+X` (заглавная) — права на исполнение получат **только директории** и файлы, уже имеющие права `x`.

## Синтаксис управления (Шелл и Ansible)

**Символьный режим (`chmod`):**

- `chmod g+rx file` — добавить права группе.
- `chmod o-w file` — убрать запись у остальных.
- `chmod u=rwx,go= file` — жестко задать права владельцу, убрать у остальных.

**Ansible (Автоматизация):**  
Всегда используйте одинарные кавычки для режимов:

```yaml
mode: '0640' # ✅ Верно, с ведущим нулем
```
