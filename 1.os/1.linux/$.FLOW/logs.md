## Карта хранения логов в файловой системе

Подавляющее большинство текстовых логов в Linux аккумулируется в директории `/var/log/`. Чтение файлов подсистем и аутентификации требует прав `root` или членства в группе `adm`/`systemd-journal`.

| Путь к файлу                              | Назначение и тип данных                                                        |
| ----------------------------------------- | ------------------------------------------------------------------------------ |
| `/var/log/syslog`                         | Общие сообщения ядра и служб (Debian / Ubuntu).<br>                            |
| `/var/log/messages`                       | Общие системные события (RHEL / CentOS / Rocky Linux).<br>                     |
| `/var/log/auth.log`                       | События аутентификации, SSH, вызовы `sudo` (Debian / Ubuntu).<br>              |
| `/var/log/secure`                         | Аналог `auth.log` для систем семейства Red Hat.<br>                            |
| `/var/log/kern.log`                       | Сообщения ядра Linux и события аппаратного уровня.<br>                         |
| `/var/log/dmesg`                          | Кольцевой буфер сообщений ядра при загрузке системы.<br>                       |
| `/var/log/nginx/`, `/var/log/apache2/`    | Access- и Error-логи веб-серверов.<br>                                         |
| `/var/log/mysql/`, `/var/log/postgresql/` | Журналы работы СУБД.<br>                                                       |
| `/var/log/cloud-init.log`                 | Логи первоначальной инициализации в облачных средах (AWS, GCP, OpenStack).<br> |

## Инструменты чтения и интерактивного просмотра

```Plaintext
                  Выбор инструмента чтения файлов логов
                                     │
           ┌─────────────────────────┼─────────────────────────┐
           ▼                         ▼                         ▼
   [ Постраничный поиск ]   [ Отслеживание в реальном   [ Быстрый вывод конца ]
         `less`                   времени]                    `tail`
                                 `tail -f`
```

### Статический просмотр (`cat`, `head`, `tail`)

- **`head` / `tail`:** Просмотр с начала или конца файла:

```bash
sudo head -n 20 /var/log/syslog
udo tail -n 50 /var/log/syslog
```
 
 >**Важно:** Избегайте выполнения `cat` на гигабайтных файлах логов — это вызовет избыточную нагрузку на ввод-вывод (I/O) и замусорит терминал.

### Мониторинг в реальном времени (`tail -f`)

Для отслеживания поступающих событий используйте флаг `-f`:

```Bash
# Мониторинг одного файла с выводом последних 50 строк
sudo tail -n 50 -f /var/log/syslog

# Отслеживание нескольких файлов одновременно
sudo tail -f /var/log/auth.log /var/log/kern.log
```

### Постраничный поиск и навигация (`less`)

Инструмент `less` оптимален для больших файлов, так как подгружает данные в память по мере надобности:

```Bash
sudo less /var/log/syslog
```

**Шпаргалка горячих клавиш `less`:**

- `G` — перейти в конец файла.
 
- `g` — перейти в начало файла.
  
- `/pattern` — поиск вперед по шаблону.

- `n` / `N` — следующее / предыдущее совпадение.

- `F` — переключить `less` в режим отслеживания в реальном времени (аналог `tail -f`).

- `q` — выход.

## Фильтрация и чтение ротированных (сжатых) архивов

### Фильтрация через `grep`

```sh
# Регистронезависимый поиск ошибок
grep -i "error" /var/log/syslog

# Исключение лишних строк (-v)
grep -v "info" /var/log/syslog

# Комбинирование потока с фильтром
sudo tail -f /var/log/syslog | grep --line-buffered "sshd"
```

### Работа со сжатыми логами (`logrotate`)

Служба `logrotate` архивирует старые логи в `.gz`. Для работы с ними без ручной распаковки применяются утилиты семейства **`z-tools`**:

```sh
# Просмотр сжатого архива
zcat /var/log/syslog.1.gz

# Постраничный просмотр архива
zless /var/log/syslog.1.gz

# Поиск по шаблону в архиве
zgrep -i "failed" /var/log/syslog.1.gz
```

## Продвинутая работа с бинарным журналом `journalctl` (systemd)

В современных дистрибутивах `systemd-journald` собирает события в бинарные журналы со строгой индексацией и метаданными.


```
                  Примеры ключевых выборок journalctl
                                   │
  ┌─────────────────┬──────────────┴──────┬──────────────────┐
  ▼                 ▼                     ▼                  ▼
По службе (-u)   За бут (-b)         По времени         Следить (-f)
 -u nginx.service   -b 0 (текущий)      --since "2h ago"       -f
```

### Основные сценарии выборки

- **Просмотр логов текущей загрузки:**

```
sudo journalctl -b
```

- **Мониторинг службы в реальном времени:**

```
sudo journalctl -f -u nginx.service
```

- **Выборка по уровню важности (Priority / Severity):** Уровни: `emerg` (0), `alert` (1), `crit` (2), `err` (3), `warning` (4), `notice` (5), `info` (6), `debug` (7).

```
sudo journalctl -p err..emerg
```

- **Выборка по интервалу времени:**

```
sudo journalctl --since "2026-09-24 10:00:00" --until "2026-09-25 12:00:00"
sudo journalctl --since "1 hour ago"
```

- **Вывод в формате обычного `syslog` или JSON:**

```
sudo journalctl -o cat
sudo journalctl -u nginx -o json-pretty
```

## Визуализация и форматирование (`ccze`)

Для цветового выделения полей (IP-адреса, статус-коды, timestamp) применяется утилита `ccze`:

```sh
# Установка (при необходимости)
# Ubuntu/Debian: sudo apt install ccze
# RHEL/CentOS:   sudo dnf install ccze

# Перенаправление потока через ccze
sudo tail -f /var/log/syslog | ccze -A
```

## Оперативный анализ частых системных событий

Для быстрой диагностики состояния системы используется набор устоявшихся сценариев проверки логов через `journalctl`, `last` и традиционные файлы в `/var/log/`.

```Plaintext

                  Оперативная диагностика системных логов
                                     │
  ┌───────────────────┬──────────────┴──────────────┬───────────────────┐
  ▼                   ▼                             ▼                   ▼
[ Статус загрузок ] [ Безопасность / Вход ]     [ Сбои служб ]      [ Критичные ошибки ]
`last reboot`       `journalctl -u ssh`         `journalctl -xeu`   `dmesg -T --level=err`
`journalctl --list-boots`                       
```

### Аудит перезагрузок и истории выключений системы

Сведения о времени загрузки и выключения необходимы для расследования незапланированных падений или подтверждения плановых регламентных работ.

#### История загрузок и выключений через утилиту `last`

- **Просмотр истории всех перезагрузок:**
 
```Bash
last reboot
```

- **Просмотр истории всех выключений (shutdown):**
 
```Bash
last -x shutdown reboot
```

#### Анализ сессий загрузки через `journalctl`

Если включено сохранение журналов systemd (`Storage=persistent` в `/etc/systemd/journald.conf`):

- **Вывести список всех зафиксированных сессий загрузки:**
 
```Bash
journalctl --list-boots
```
 
 _Пример вывода:_
  
```sh
    -1 8f9a2b... Mon 2026-10-05 08:00:10 CEST — Mon 2026-10-05 10:30:00 CEST
     0 e1d3f4... Mon 2026-10-05 10:31:15 CEST — Mon 2026-10-05 11:00:00 CEST
```
  
- **Просмотреть логи предыдущей (прошлой) загрузки (`-b -1`):**

``` Bash
journalctl -b -1 -p err..emerg
```
 

### Экспресс-чеклист часто проверяемых событий

|**Сценарий проверки**|**Команда / Источник**|**Описание и цель проверки**|
|---|---|---|
|**Аудит SSH-авторизаций**|`journalctl -u ssh -n 100`<br><br>  <br><br>_(или `/var/log/auth.log` / `/var/log/secure`)_|Поиск неудачных попыток входа (Bruteforce), успешных входов под `root` или через `sudo`.|
|**Ошибки ядра и HW**|`dmesg -T --level=err,crit,emerg`|Аппаратные сбои, проблемы с дисковым поддиском (I/O errors), падения файловых систем.|
|**Срабатывание OOM Killer**|`journalctl -k \| grep -i "out of memory"`|Определение процессов, завершенных ОС из-за нехватки оперативной памяти.|
|**Падения и сбои служб**|`journalctl -xeu <service_name>`|Расширенная отладка упавшей службы с выводом последних контекстных строк.|
|**Ошибки монтирования/fstab**|`journalctl -b 0 -u systemd-fstab-generator`|Диагностика проблем с монтированием дисков при уходе системы в `emergency mode`.|

### Готовые команды-однострочники для ежедневного контроля

1. **Просмотр последних 50 ошибок уровня `Warning` и выше за текущий день:**

```Bash
journalctl --since today -p warning..emerg -n 50
```
 
2. **Мониторинг сбоев аутентификации в реальном времени:**
 
```Bash
journalctl -f -u ssh | grep -iE "failed|invalid|accepted"
```
  
3. **Быстрый поиск блокировок процессов и сбоев дисковой подсистемы:**

```Bash
dmesg -T | grep -iE "error|fail|blocked|corrupted"
```
