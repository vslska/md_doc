## Локальный вывод из домена
---

> _Цель: сбросить авторизацию на сервере, но НЕ удалять заготовленную учетную запись в Active Directory._

### Остановка доменных служб:

```bash
sudo systemctl stop sssd winbind smbd nmbd
```

###  Вывод  сервера локально (без удаления учетки в AD). 

> Если команда `net ads leave` ругается на синтаксис ключей, просто **жестко зачистите локальную память**:

```bash
# Очищаем кэш Kerberos и keytab машины
sudo kdestroy -A
sudo rm -f /etc/krb5.keytab

# Уничтожаем базу секретов Samba и кэш
sudo rm -f /var/lib/samba/private/secrets.tdb /var/lib/samba/secrets.tdb /etc/samba/secrets.tdb
sudo net cache flush
   
# Сбрасываем кэш SSSD (чтобы стерлись старые SID)
sudo rm -f /var/lib/sss/db/*
```

## Изменение имени (Hostname) и сети
---

>_Цель: прописать новое имя в системе, чтобы службы и сеть инициализировались правильно._

**Новый hostname системы:**

```bash
sudo hostnamectl set-hostname <НОВОЕ_ИМЯ_СЕРВЕРА>
```

> _(Например: `sudo hostnamectl set-hostname web-db`)_

**Обновляем локальное разрешение имен:**

```bash
sudo nano /etc/hosts
```

Ищем строку `127.0.1.1` (или строку с реальным статическим IP сервера). **Удаляем старое имя** и вписываем новое. 

**Пример:**

```bash
127.0.1.1    web-db.domain.local    web-db
```

## Проверка и обновление конфигурации Samba
---

> _Цель: исправить ловушку — жестко прописанное старое имя в конфиге._

**Открыть конфигурационный файл Samba:**

```
sudo nano /etc/samba/smb.conf
```

Найти секцию `[global]` и параметр **`netbios name`**.

**Изменить старое имя на **новое** (в верхнем или нижнем регистре, как принято в инфре):**

```
[global]
netbios name = web-db
workgroup = domain
realm = domain.local
```

Сохранить и закрыть

## Перезагрузка системы
---

> _Цель: применить новый hostname на уровне ядра и сетевых интерфейсов._

```bash
sudo reboot
```

> _После перезагрузки убедиться, что имя изменилось, выполнив команду `hostname`._


## Ввод в домен (Active Directory)
---

_Цель: привязать сервер к уже созданной админами новой УЗ в домене._

Выполнить чистый ввод в домен, явно указав рабочую группу и домен:

```bash
sudo net ads join -U <Имя_Администратора> -w domain -realm domain.local
```

_Если УЗ в конкретном контейнере (OU), использовать расширенную команду:_

```bash
sudo net ads join -U <Имя_Админа> -w GAZPROM-NEFT -realm GAZPROM-NEFT.LOCAL createcomputer="OU=Servers,DC=gazprom-neft,DC=local"
```

Убедиться, что в конце вывелось сообщение: **`Joined 'ИМЯ_СЕРВЕРА' to dns domain 'gazprom-neft.local'`**.

## Настройка SSSD и запуск служб
---

> _Цель: прописать доступы для доменных групп и запустить авторизацию._

**Открыть конфигурационный файл SSSD:**

```
sudo nano /etc/sssd/sssd.conf
```

Добавить нужные **доменные группы авторизации** в параметр `simple_allow_groups` (через запятую).

**Запустить все службы в правильном порядке:**

```bash
sudo systemctl start smbd nmbd winbind
sudo systemctl start sssd
```

**Добавить службы в автозагрузку (если они не были добавлены):**

```bash
sudo systemctl enable smbd nmbd winbind sssd
```

## Проверка работоспособности
---

Выполнение команд, чтобы убедиться, что всё работает идеально:

### **Проверка доверия домена:**
 
```
sudo net ads testjoin
```

> _Должно вернуть:_ `Join is OK`

### **Проверка чтения доменных групп/пользователей:**

```
id <любой_доменный_пользователь>
```

> _Должно выдать:_ UID, GID и список доменных групп пользователя.

### **Проверка билета Kerberos машины:**

```
sudo kinit -k <НОВОЕ_ИМЯ_СЕРВЕРА>$
```

 >_Должно отработать молча, без ошибок преаутентификации._
