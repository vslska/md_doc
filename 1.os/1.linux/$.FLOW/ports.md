## Ментальная модель сетевых портов и жизненного цикла сокетов

В сетевой модели TCP/IP порт представляет собой 16-битное число (от 1 до 65535), идентифицирующее конкретный процесс или службу на хосте. Связка IP-адреса, протокола (TCP/UDP) и номера порта образует сокет.

```text
Приложение (User Space)
   │
   ▼  System Calls: bind() / listen() / accept()
Ядро Linux (Kernel Space)
   │
   ├── Протокольный уровень (TCP / UDP)
   │      │
   │      ▼
   └── Сетевой стек и Netfilter / Firewall (Правила INPUT / FORWARD)
          │
          ▼
Сетевой интерфейс (NIC / Wire)
````

Жизненный цикл доступности порта на хосте зависит от выполнения трех условий:

1. **Приложение запущено и привязано (bound):** Процесс выполнил системный вызов `bind()` на нужный IP-адрес и порт.
2. **Процесс переведен в режим ожидания:** Выполнен вызов `listen()` (для TCP), переведя сокет в состояние `LISTEN`.
3. **Межсетевой экран (Firewall) и маршрутизация разрешают трафик:** Пакеты не отбрасываются правилами фильтрации Netfilter/iptables/nftables.

## Локальная диагностика: проверка прослушиваемых портов

Перед тем как проверять доступность порта с удаленной машины, необходимо убедиться, что служба локально запущена и действительно слушает сетевой интерфейс.

### Использование утилиты `ss`

Утилита `ss` входит в стандартный пакет `iproute2` и является современным стандартом для инспекции сокетов (заменившим устаревший `netstat`).

Команда для вывода всех прослушиваемых TCP и UDP портов с именами процессов:

```sh
ss -lntup
```

Расшифровка флагов:

- `-l` — показывать только слушающие (listening) сокеты;
- `-n` — выводить числовые адреса и порты (без резолва имен служб);
- `-t` — показывать TCP-сокеты;
- `-u` — показывать UDP-сокеты;
- `-p` — выводить информацию о процессах (PID и имя программы, требуются права root).

Пример анализа вывода `ss -lntup`:

```sh
State      Recv-Q Send-Q Local Address:Port       Peer Address:Port   Process
LISTEN     0      4096   0.0.0.0:80               0.0.0.0:*           users:(("nginx",pid=1234,fd=6))
```

Если в столбце `Local Address:Port` указан адрес `0.0.0.0:80` или `[::]:80`, служба принимает подключения на всех интерфейсах. Если указан `127.0.0.1:80`, служба доступна **исключительно локально** с самого хоста.

## Диагностика и тестирование доступности портов

Проверка доступности порта позволяет выявить проблемы с сетевыми экранами, маршрутизацией или зависшими сервисами.

### Тестирование через встроенный механизм Bash (`/dev/tcp`)

Оболочка Bash поддерживает прямую работу с сетевыми псевдофайлами. Это встроенный инструмент, не требующий установки стороннего программного обеспечения, что актуально для минималистичных или аварийных окружений.

Функция проверки TCP-порта:

```bash
check_tcp_port() {
    local host=$1
    local port=$2
    (echo > /dev/tcp/$host/$port) >/dev/null 2>&1 \
        && echo "Порт $port на хосте $host открыт" \
        || echo "Порт $port на хосте $host закрыт или заблокирован"
}

check_tcp_port 127.0.0.1 80
```

### Проверка с помощью Netcat (`nc`)

Netcat — стандартный универсальный инструмент для работы сокетами.

- **Проверка TCP-порта:**

```sh
nc -zv 192.168.1.50 443
```
 
> _При успешном соединении утилита выводит сообщение вида `Connection to 192.168.1.50 443 port [tcp/https] succeeded!` и возвращает код `0`._

- **Проверка UDP-порта:**

```sh
nc -zvu 192.168.1.50 53
``` 

### Глубокое сканирование с помощью `nmap`

Для сканирования диапазонов портов, определения типов служб и детального анализа фильтрации используется сканер `nmap`:

- Сканирование конкретного порта:

```sh
nmap -p 80 192.168.1.50
```

- Сканирование диапазона портов с определением версий служб:

```sh
nmap -sV -p 1-1024 192.168.1.50
```

## Архитектура управления межсетевыми экранами в Linux

Если локальный сервис запущен и слушает порт, но удаленные клиенты не могут подключиться, причиной является блокировка трафика межсетевым экраном. В современных дистрибутивах Linux управление правилами фильтрации реализуется через три основных инструмента:

```
Запрос из сети ──► [ UFW / Firewalld (User Space Interfaces) ]
                               │
                               ▼
                    [ Netfilter / nftables ]
                               │
                       ┌───────┴───────┐
                       ▼               ▼
                 [ DROP / REJECT ]  [ ACCEPT ] (Передача ядру/приложению)
```

1. **UFW (Uncomplicated Firewall):** Простой интерфейс управления iptables/nftables, используемый по умолчанию в Ubuntu и Debian.
2. **Firewalld:** Динамический менеджер межсетевого экрана с поддержкой зон, используемый в Red Hat, CentOS, Fedora, Astra Linux.
3. **iptables / nftables:** Низкоуровневые подсистемы ядра для прямой фильтрации пакетов.

## Пошаговое руководство по открытию портов

### Определение активного межсетевого экрана

Перед внесением изменений проверьте, какая служба управления правилами активна в системе:

```sh
# Проверка UFW
sudo ufw status

# Проверка Firewalld
sudo systemctl status firewalld
```

### Открытие порта в UFW (Ubuntu / Debian)

Если в системе используется UFW, открытие порта выполняется встроенными командами управления.

1. **Разрешить входящие соединения на TCP-порт (например, 80):**

```sh
sudo ufw allow 80/tcp
```

2. **Разрешить порт для конкретного IP-адреса или подсети:**

```bash
sudo ufw allow from 192.168.1.100 to any port 80 proto tcp
```

3. **Перезагрузить правила UFW:**
 
```bash
sudo ufw reload
```

4. **Проверка успешности:** Выполните команду `sudo ufw status verbose`. В списке разрешенных правил должен присутствовать целевой порт со статусом `ALLOW`.

### Открытие порта в Firewalld (CentOS / RHEL / Fedora / Astra)

В средах с `firewalld` правила привязываются к сетевым зонам (по умолчанию используется зона `public`).

1. **Добавить порт на постоянной основе (--permanent):**

```sh
sudo firewall-cmd --permanent --add-port=80/tcp
```

2. **Применить изменения без перезапуска службы:**

```sh
sudo firewall-cmd --reload
```

- **Проверка успешности:** Выполните `sudo firewall-cmd --list-ports`. Добавленный порт должен отображаться в выводимом списке (например, `80/tcp`).

### Настройка через классический `iptables`

При работе с минималистичными системами без высокоуровневых оберток правила добавляются напрямую в цепочку `INPUT` таблицы `filter`.

> ⚠️ **Важно:** `iptables` обрабатывает правила **строго сверху вниз** до первого совпадения. Если в конце вашей цепочки уже стоит запрещающее правило (например, `DROP all`), добавление через флаг `-A` (в конец списка) не сработает. В таких случаях используйте флаг `-I` для вставки правила в самое начало.


1.  **Проверить парвила**
```sh
sudo iptables -L -v -n --line-numbers
```

2. **Разрешить входящий трафик на TCP-порт:**

- _Вариант А: Добавить в конец списка (если нет блокирующих правил выше):_

```sh
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
```

- _Вариант Б: Вставить на первую позицию (гарантированный приоритет):_

```sh
sudo iptables -I INPUT 1 -p tcp --dport 80 -j ACCEPT
```


2. **Сохранение правил (зависит от дистрибутива):**

- _Debian / Ubuntu с пакетом iptables-persistent:_

```sh
sudo netfilter-persistent save
```

- _RHEL / CentOS / Rocky Linux:_

```sh
sudo service iptables save
```

- **Проверка успешности:** Выполните команду `sudo iptables -L INPUT -v -n --line-numbers`. В выводе вы увидите порядковый номер правила, действие `ACCEPT` и целевой порт (`dpt:80`).

## Диагностика сбоев: Анализ трафика с помощью `tcpdump`

Если порт открыт в фаерволе и служба запущена, но соединение не устанавливается, применяется низкоуровневый перехват пакетов для подтверждения дохождения трафика до хоста:

```sh
sudo tcpdump -nnvv -i any port 80
```

Анализ флагов пакетов:

- Наличие поступающих пакетов с флагом `[S]` (SYN) означает, что сеть и фаервол пропускают трафик.
- Отсутствие ответа `[S.]` (SYN-ACK) от сервера указывает на то, что локальная служба не принимает соединения или сбрасывает их на уровне приложения.

## Справочник команд для диагностики и управления портами

|**Задача**|**Инструмент / Команда**|**Описание**|
|---|---|---|
|**Просмотр локальных портов**|`ss -lntup`|Вывод всех слушающих TCP/UDP сокетов с PID процессов|
|**Быстрая проверка TCP**|`nc -zv <IP> <PORT>`|Проверка доступности удаленного/локального TCP-порта|
|**Проверка без утилит**|`echo > /dev/tcp/<IP>/<PORT>`|Проверка соединения средствами оболочки Bash|
|**Сканирование сети**|`nmap -p <PORT> <IP>`|Глубокое сканирование и определение статуса порта|
|**Открытие в UFW**|`sudo ufw allow <PORT>/tcp`|Разрешение порта в UFW|
|**Открытие в Firewalld**|`sudo firewall-cmd --permanent --add-port=<PORT>/tcp`|Добавление порта в Firewalld|
|**Анализ трафика**|`sudo tcpdump -nnvv -i any port <PORT>`|Перехват сетевых пакетов на уровне ядра|
