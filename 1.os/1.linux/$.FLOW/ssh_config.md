## Архитектура клиентской конфигурации SSH

Для оптимизации работы с удаленными серверами вместо прямого ввода громоздких IP-адресов, длинных имен пользователей и путей к ключам используется локальный файл конфигурации клиента SSH — `~/.ssh/config`.

При вызове команды:

```bash
ssh node1
```

клиент SSH обращается к конфигурационному файлу, автоматически подставляя сохраненные параметры подключения (IP-адрес, порт, имя пользователя, путь к закрытому ключу).

## Структура файла конфигурации `~/.ssh/config`

Файл располагается в домашнем каталоге пользователя по пути `~/.ssh/config`. Права доступа к нему должны быть строго ограничены (`chmod 600`), иначе клиент SSH проигнорирует его настройки из соображений безопасности.

### Базовый пример конфигурации

```Ini, TOML
# Глобальные параметры для всех хостов по умолчанию
Host *
    ServerAliveInterval 60
    ServerAliveCountMax 3
    AddKeysToAgent yes

# Конфигурация для конкретного узла
Host node1
    HostName 192.168.122.10
    User fedora
    IdentityFile ~/.ssh/id_rsa
    Port 22

# Конфигурация для второго узла с нестандартным портом
Host node2
    HostName 192.168.122.11
    User fedora
    Port 2222
```

### Основные директивы конфигурации

- **`Host`** — мнемоническое имя псевдонима, используемое при подключении (например, `ssh node1`). Поддерживает шаблоны (например, `Host 192.168.*` или `Host *`).
- **`HostName`** — реальный IP-адрес или доменное имя целевого сервера.
- **`User`** — имя пользователя, от чьего имени выполняется подключение.
- **`Port`** — сетевой порт SSH-сервера (по умолчанию 22).
- **`IdentityFile`** — путь к файлу закрытого криптографического ключа (`private key`) для аутентификации.
- **`ProxyJump`** — настройка проброса соединения через промежуточный узел ( bastion / jump host).

## Продвинутые возможности SSH Config

### Использование Jump Host (Проксирование соединений)

Если целевая нода находится в закрытой подсети и доступна только через сервер-посредник, конфигурация принимает следующий вид:

```Ini, TOML
Host bastion
    HostName 203.0.113.50
    User admin
    IdentityFile ~/.ssh/id_bastion

Host internal-node
    HostName 10.0.0.15
    User admin
    ProxyJump bastion
    IdentityFile ~/.ssh/id_internal
```

Подключение к изолированному серверу выполняется одной командой:

```bash
ssh internal-node
```

Клиент SSH автоматически установит защищенное соединение через узел `bastion`.

### Шаблоны и подстановочные знаки (Wildcards)

Директива `Host *` позволяет применять параметры ко всем соединениям. Также можно группировать настройки для определенных подсетей:

```Ini, TOML
Host 10.10.*.*
    User deployer
    IdentityFile ~/.ssh/id_internal_net
```

## Управление ключами и аутентификация

### Генерация пары ключей

Для безопасной беспарольной аутентификации создается криптографическая пара ключей (рекомендуется алгоритм `ed25519`):

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519
```

### Копирование публичного ключа на сервер

Перенос открытого ключа на удаленный хост для авторизации:

```Bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@192.168.122.10
```

## Туннелирование и проброс портов (Port Forwarding)

SSH позволяет организовывать защищенные каналы для передачи трафика поверх установленного соединения.

### Локальный проброс портов (`-L`)

Перенаправление порта с локальной машины на удаленную:

```Bash
ssh -L 8080:127.0.0.1:80 user@node1
```

>_Запрос на локальный порт `8080` будет перенаправлен на порт `80` целевого сервера._

### Удаленный проброс портов (`-R`)

Предоставление доступа из внешней сети к локальному сервису:

```Bash
ssh -R 9090:127.0.0.1:3000 user@node1
```

## Диагностика и отладка подключений

При возникновении проблем с подключением используется режим подробного логирования (`verbose`):

```Bash
ssh -v node1
# Или максимальная детализация:
ssh -vvv node1
```
