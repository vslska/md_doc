# Создание, монтирование и горячее расширение томов LVM на новом диске

> Развертывание и масштабирование хранилищ в виртуальных машинах (VM) и на физических серверах, администрирование дисковых подсистем Linux.
> 
> **Предпосылки:**
> - Добавлен или расширен блочный диск (например, `/dev/sdb`);
> - Работа выполняется под учетной записью `root` или через `sudo`;
> - Используется стек **Physical Volume (PV) → Volume Group (VG) → Logical Volume (LV) → Файловая система (FS)**;
> - Не используется шифрование (LUKS) и не требуется загрузочный раздел (`/boot`).

## Архитектура и цепочка объектов LVM

```Plaintext
  [ Блочное устройство ] ──► /dev/sdb (Физический диск)
                                  │
                                  ▼ (pvcreate / pvresize)
  [ Physical Volume ]    ──► /dev/sdb (PV)
                                  │
                                  ▼ (vgcreate / vgextend)
  [ Volume Group ]       ──► vg_data (VG - пул ресурсов)
                                  │
                  ┌───────────────┴───────────────┐
                  ▼ (lvcreate / lvextend)         ▼ (lvcreate / lvextend)
  [ Logical Volume ]     ──► lv_home                     ──► lv_media
                          (20 GiB)                        (100% FREE)
                                  │                               │
                                  ▼                               ▼ 
                        (mkfs / resize2fs)            (mkfs / xfs_growfs)
  [ Filesystem ]          ──► ext4                               ──► xfs
                                  │                               │
                                  ▼ (mount /etc/fstab)            ▼ (mount /etc/fstab)
  [ Mount Point ]                ──► /mnt/home                 ──► /mnt/media
```

## FLOW 1: Первичная инициализация диска и развертывание LVM

### Подготовка и инспекция блочных устройств

1. Проверьте наличие нового устройства в системе:

```Bash
lsblk
```

2. Убедитесь в отсутствии существующих таблиц разделов или старых сигнатур ФС:

```sh
sudo fdisk -l /dev/sdb
```

3. При необходимости выполните полную очистку метаданных с диска:

```sh
sudo wipefs -a /dev/sdb
```

 >**Замечание:** Альтернативный способ низкоуровневой очистки первых мегабайт диска:
>`sudo dd if=/dev/zero of=/dev/sdb bs=1M count=10 status=progress`
 

### Инициализация физического тома (Physical Volume)

1. Разметьте дисковое устройство как PV:

```sh
sudo pvcreate /dev/sdb
```
  
2. Проверьте статус физических томов:

```sh
sudo pvs
# Или развернутая информация:
sudo pvdisplay /dev/sdb
```
  
### Создание группы томов (Volume Group)

1. Объедините физический том в группу томов `vg_data`:
 
```sh
sudo vgcreate vg_data /dev/sdb
```
  
2. Для создания группы из нескольких дисков передайте их списком:

``` Bash
sudo vgcreate vg_main /dev/sdb /dev/sdc
```

3. Проверьте состояние группы томов:
 
```sh
sudo vgs
```
 
### Нарезка логических томов (Logical Volume)

Создадим два логических тома в группе `vg_data`:

- `lv_home`: фиксированным размером **20 ГБ**;
- `lv_media`: на **все оставшееся свободное пространство**.  

1. Выполните команды создания LV:

```sh
 sudo lvcreate -L 20G -n lv_home vg_data
 sudo lvcreate -l 100%FREE -n lv_media vg_data
```
 
2. Проверьте список логических томов:
  
```sh
sudo lvs
```


> **Справочник ключей `lvcreate`:**
> - `-L 20G` — точный размер в единицах измерения (M, G, T);
> - `-l 100%FREE` — процент от свободного пространства VG;
> - `-l +50%FREE` — 50% от текущего нераспределенного объема VG;
> - `-n <name>` — имя создаваемого тома.


### Создание файловых систем и монтирование

1. Сформируйте файловые системы `ext4` и `xfs` на логических томах:

```sh
sudo mkfs.ext4 /dev/vg_data/lv_home
sudo mkfs.xfs /dev/vg_data/lv_media
```

>**Сравнение ФС:**
> - **`ext4`**: универсальная, надежная, поддерживает как увеличение, так и уменьшение размера в режиме offline (`resize2fs`).     
> - **`x  fs`**: оптимизирована для высоконагруженных операций и работы с большими файлами. _Уменьшение размера XFS не поддерживается._


2. Создайте целевые каталоги монтирования:
  
```sh
 sudo mkdir -p /mnt/{home,media}
```

3. Выполните временное монтирование и проверку:

```sh
sudo mount /dev/vg_data/lv_home /mnt/home
sudo mount /dev/vg_data/lv_media /mnt/media
df -hT /mnt/home /mnt/media
```

### Конфигурирование постоянного монтирования (`/etc/fstab`)

1. Получите уникальные идентификаторы `UUID` созданных томов:

```sh
sudo blkid /dev/vg_data/lv_home
sudo blkid /dev/vg_data/lv_media
```
 
2. Добавьте соответствующие записи в файл `/etc/fstab`:

```sh
UUID=xxxx-xxxx-xxxx  /mnt/home  ext4  defaults,noatime  0  2
UUID=yyyy-yyyy-yyyy  /mnt/media xfs   defaults,noatime  0  2
```
 
3. Проверьте корректность конфигурации `/etc/fstab` без перезагрузки системы:

```sh
sudo umount /mnt/home /mnt/media
sudo mount -a
mount | grep mnt
```

## FLOW 2: Горячее пересканирование и расширение тома (Hot-Resize & Rescan)

Если размер диска `/dev/sdb` был увеличен на лету на стороне гипервизора (Proxmox, VMware, Hyper-V, KVM) или SAN, выкатывать изменения в ядро и LVM нужно по следующей цепочке:

### Перечитка геометрии ядром (Rescan)

1. Отправьте сигнал принудительной перечитки конкретного диска:

```sh
echo 1 | sudo tee /sys/class/block/sdb/device/rescan
```
 
**Если добавлен СОВЕРШЕННО НОВЫЙ диск (не виден в `lsblk`):**

Выполните сканирование шинного контроллера SCSI:

```sh
for host in /sys/class/scsi_host/host*/scan; do echo "- - -" | sudo tee "$host"; done
```

2. Убедитесь, что ядро зафиксировало новый объем блочного устройства:

```sh
lsblk /dev/sdb
```

### Обновление слоя LVM (PV & VG)

1. Обновите размер Physical Volume:

```sh
sudo pvresize /dev/sdb
```

2. Убедитесь, что в Volume Group появилось свободное пространство (столбец `VFree`):

```sh
sudo vgs
```

### Расширение LV и файловой системы

Выполните расширение нужного тома и растягивание ФС (выберите вариант в зависимости от типа ФС):

- **Вариант А: Фиксированное расширение (например, +10 GiB для ext4)**
 
```sh
sudo lvextend -L +10G /dev/vg_data/lv_home && sudo resize2fs /dev/vg_data/lv_home
```

- **Вариант Б: Расширение на ВСЁ свободное место (для XFS)**

```sh
sudo lvextend -l +100%FREE /dev/vg_data/lv_media && sudo xfs_growfs /mnt/media
```

## Сводная шпаргалка по командам

|**Операция**|**Команда**|
|---|---|
|**Перечитка диска ядром**|`echo 1 > /sys/class/block/sdb/device/rescan`|
|**Обновление размера PV**|`sudo pvresize /dev/sdb`|
|**Расширение LV (ext4)**|`sudo lvextend -L +10G /dev/vg_data/lv_home && sudo resize2fs /dev/vg_data/lv_home`|
|**Расширение LV (XFS)**|`sudo lvextend -l +100%FREE /dev/vg_data/lv_media && sudo xfs_growfs /mnt/media`|
|**Добавить диск в VG**|`sudo pvcreate /dev/sdc && sudo vgextend vg_data /dev/sdc`|
|**Инспекция структуры**|`sudo pvs && sudo vgs && sudo lvs && lsblk`|

## Распространенные ошибки администрирования и защита от сбоев

### Ошибка при замене/миграции дисков в виртуализации (`PV` / `VG`)

```plaintext
       ОШИБКА: Добавление нового PV в VG с последующим отключением старого
                                      │
  ┌───────────────────────────────────┴───────────────────────────────────┐
  ▼                                                                       ▼
[ Сценарий сбоя ]                                       [ Корректный подход ]
1. К VG добавляется новый PV (Virtual Disk 2).          1. Создать ОТДЕЛЬНУЮ VG (например, `vg_data_v2`).
2. Старый PV (Virtual Disk 1) отключается в hypervisor. 2. Создать LV, отформатировать и смонтировать.
3. Метаданные VG повреждаются / части LVM недоступны.   3. Перенести данные (rsync/pvmove).
4. Итог: Критическая ошибка при загрузке (emergency).  4. Обновить `/etc/fstab` и безопасно удалить старую VG.
```

#### Описание критической ошибки

При работе в виртуальной среде частой ошибкой является попытка заменить старый виртуальный диск новым путем добавления нового `PV` в существующую `VG` и последующим жестким удалением/отключением старого диска в гипервизоре.

**Почему это приводит к краху:**

1. Метаданные `VG` и данные логических томов (`LV`) распределяются по всем активным `PV` группы.
 
2. Отключение физического диска (или файла виртуального диска) без предварительного корректного вывода из `VG` переводит группу томов в состояние `partial` (неполная).

3. При следующей перезагрузке инициализатор `systemd-fstab-generator` не сможет смонтировать файловые системы, что приведет к **падению операционной системы в `emergency mode`**.

#### Как правильно делать

##### Вариант А: Замена диска внутри одной VG (Без создания новой VG)

Если необходимо сохранить имя группы томов (`VG`), используйте штатную процедуру миграции блоков `pvmove` **до** физического удаления диска:

1. Подключите новый диск и создайте `PV`:

```sh
pvcreate /dev/sdb
vgextend vg_data /dev/sdb
```

2. **Перенесите экстенты (данные)** со старого диска (`/dev/sda`) на новый (`/dev/sdb`):

```sh
pvmove /dev/sda /dev/sdb
```

3. Исключите старый диск из `VG` и удалите его маркер `PV`:

```
vgreduce vg_data /dev/sda
pvremove /dev/sda
```

4. **Только после этого** отключайте старый диск в гипервизоре.

##### Вариант Б: Выделение нового диска в отдельную VG (Рекомендуемый для изолированной миграции)

Если планируется полное переформирование хранилища:

1. **Не добавляйте новый диск в старую VG.** Создайте независимую группу томов:

```sh
pvcreate /dev/sdb
vgcreate vg_data_v2 /dev/sdb
lvcreate -l 100%FREE -n lv_data_v2 vg_data_v2
```

2. Создайте файловую систему и скопируйте данные (например, через `rsync`).

3. **Обновите записи в `/etc/fstab`:** замените старый UUID / путь монтирования на новый `LV`.

4. Проверьте корректность монтирования (`mount -a`).

5. Корректно демонтируйте, удалите старую `VG` (`vgremove vg_data_old`) и только затем отключайте виртуальный диск в гипервизоре.


### Чек-лист контроля конфигурации `/etc/fstab`

> **Критическое правило:** Любые манипуляции с `PV`, `VG` и `LV` обязательно должны сопровождаться актуализацией файла `/etc/fstab` **до** перезагрузки сервера.

1. **Используйте UUID для монтирования:** Получить UUID нового логического тома:

```
blkid /dev/mapper/vg_data_v2-lv_data_v2
```

2. **Безопасные опции монтирования для некритичных томов:** Для дополнительных дисков данных рекомендуется использовать опции `nofail` и `x-systemd.device-timeout=10s`, чтобы в случае отсутствия диска система не уходила в `emergency mode`, а продолжала загрузку:

```sh
UUID=xxxx-xxxx-xxxx    /mnt/data    ext4    defaults,nofail,x-systemd.device-timeout=10s    0 2
```

3. **Тестирование конфигурации без перезагрузки:** После внесения изменений в `/etc/fstab` обязательно выполните:
 
```sh
systemctl daemon-reload
mount -a
```

>_Если команда `mount -a` завершается без ошибок — конфигурация корректна._
