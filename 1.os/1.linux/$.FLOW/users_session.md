## Ментальная модель пользовательской активности в ОС Linux

В многопользовательской среде Linux изоляция и учет сессий строятся на взаимодействии нескольких подсистем ядром и пространством пользователя:

```text
               Учетные записи (Local / Domain via SSSD)
                                  │
                                  ▼
                   Session Manager (systemd-logind)
                                  │
                 ┌────────────────┴────────────────┐
                 ▼                                 ▼
      Интерактивные сессии             Фоновые службы / Daemons
      (TTY, PTS, SSH, GUI)             (systemd service scopes)
                 │                                 │
                 └────────────────┬────────────────┘
                                  │
                                  ▼
                     Процессы (PID / UID / EUID)
                                  │
         ┌────────────────────────┼────────────────────────┐
         ▼                        ▼                        ▼
  Сетевые сокеты           Открытые файлы           Потребление RAM / CPU
  (ss / lsof -i)          (lsof -u <user>)         (ps / cgroups v2)
````

Администратору необходимо разделять статические учетные записи (базы `/etc/passwd` и доменные кеши SSSD) и динамические контексты выполнения (активные сессии, запущенные процессы и удерживаемые сетевые ресурсы).

## Аудит активных сессий пользователей

Для выявления того, кто в данный момент работает в системе (локально через консоль/GUI или удаленно по протоколу SSH), применяются системные утилиты учета сессий.

### Утилита `w` и `who`

Команда `w` выводит сводную информацию о пользователях, вошедших в систему, времени их сессий и выполняемых ими процессах:

```sh
w
```

Пример анализа вывода:

```sh
 12:00:00 up 10 days,  4:15,  3 users,  load average: 0.15, 0.08, 0.03
USER     TTY      FROM             LOGIN@   IDLE   JCPU   PCPU WHAT
root     pts/0    192.168.1.50     11:30    1.00s  0.05s  0.01s sshd: root[priv]
ivanov   pts/1    10.10.10.25      11:45    5.00s  0.02s  0.00s -bash
```

### Аудит через `loginctl` (Менеджер сессий systemd)

Современные дистрибутивы Linux используют `systemd-logind` для управления сессиями. Это позволяет получать точные данные как о локальных, так и о доменных пользователях:

- **Список всех активных сессий в системе:**

```sh
loginctl list-sessions
```

- **Детальная информация по конкретной сессии (например, с ID `2`):**
 
```bash
loginctl show-session 2
```

Поля вывода содержат ключевые параметры: `Name` (имя пользователя), `Remote` (признак удаленного подключения), `RemoteHost` (IP-адрес клиента) и `Service` (модуль PAM, через который выполнена аутентификация, например `sshd` или `gdm-password`).

## Аудит доменных пользователей (SSSD / Active Directory)

Если сервер интегрирован в домен (Active Directory или FreeIPA) через **SSSD**, доменные пользователи могут не иметь записей в локальном файле `/etc/passwd`. Проверка их активности требует учета особенностей подсистемы кэширования.

### Проверка статуса SSSD и кэша домена

1. **Проверка работоспособности службы SSSD:**

```bash
systemctl status sssd
```

2. **Проверка доступности доменного пользователя через NSS (Name Service Switch):**

```bash
getent passwd username@domain.local
```

3. **Проверка групп и членства доменного пользователя (включая группы безопасности AD):**

```bash
id username@domain.local
```

4. **Аудит активных процессов доменного пользователя:**

Так как идентификаторы (UID) доменных пользователей маппятся SSSD динамически (или через алгоритм `getID`), фильтрацию процессов надежнее производить по имени пользователя, а не по числовому UID:

```bash
ps -u username@domain.local -eo pid,ppid,%cpu,%mem,comm,args
```

## Инспекция процессов и потребления ресурсов

Для аудита того, какие задачи, скрипты или фоновые процессы запущены от имени конкретного пользователя, используется утилита `ps` с расширенным форматированием.

### Вывод процессов конкретного пользователя

```bash
ps -u username -eo pid,ppid,%cpu,rss,comm,args --sort=-rss
```

Параметры фильтрации:

- `%cpu` — текущая утилита процессора;

- `rss` — объем физической оперативной памяти (Resident Set Size) в килобайтах, занимаемый процессом;

- `comm` — имя исполняемого файла.


### Суммарное потребление памяти пользователями

Для расчета общего объема RAM, выделенного под все процессы конкретного пользователя, применяется конвейер с `awk`:

```bash
ps -e -o user,rss | awk '{arr[$1]+=$2} END {for (u in arr) print u, arr[u]/1024 " MB"}' | sort -k2 -nr
```

## Аудит сетевых соединений и открытых портов пользователей

Связывание запущенных пользовательских процессов с сетевыми сокетами позволяет выявить, какие внешние или внутренние ресурсы они используют.

### Сопоставление сокетов с процессами и пользователями

Использование утилиты `ss` с флагами вывода процессов и пользователей (`-p` и `-u`/`-t`):

```bash
sudo ss -tulpn
```

В выводе команды в столбце `users` явно указывается имя процесса, его PID и UID владельца сокета.

### Глубокий аудит открытых файлов и сетевых дескрипторов (`lsof`)

Утилита `lsof` (List Open Files) незаменима для детального расследования активности конкретной учетной записи. Она показывает все открытые пользователем файлы, логи, сокеты и каналы.

1. **Вывод всех открытых сетевых соединений и сокетов для пользователя:**

```bash
lsof -u username -i -P -n
```

2. **Поиск всех файлов и логов, открытых процессами пользователя:**

```bash
lsof -u username -d ^mem -d ^txt
```

>_(Флаг `-d ^mem -d ^txt` исключает служебные бинарники и библиотеки, оставляя только рабочие файлы и логи)._

## Практические операционные регламенты (Runbooks)

### Runbook: «Расследование подозрительной сетевой активности пользователя»

При обнаружении аномального сетевого трафика с локальной учетной записи или доменного пользователя выполняется следующий регламент:

```bash
# 1. Выявить активные сессии пользователя
w | grep username
loginctl list-sessions | grep username

# 2. Перечислить все запущенные процессы пользователя с их PID
ps -u username -eo pid,ppid,cmd --forest

# 3. Проверить открытые сетевые сокеты процессов данного пользователя
sudo lsof -u username -i -P

# 4. При необходимости принудительно завершить все сессии и процессы пользователя
sudo pkill -u username
```

## Справочник команд аудита сессий и ресурсов

| **Задача**                   | **Команда**                        | **Описание**                                       |
| ---------------------------- | ---------------------------------- | -------------------------------------------------- |
| **Список активных сессий**   | `w`                                | Вывод подключенных пользователей и их терминалов   |
| **Детали сессий systemd**    | `loginctl list-sessions`           | Инспекция активных сессий через systemd            |
| **Проверка доменного юзера** | `getent passwd user@domain`        | Запрос параметров пользователя через SSSD          |
| **Процессы пользователя**    | `ps -u username -eo pid,comm,%mem` | Вывод процессов конкретной учетной записи          |
| **Сетевые сокеты процессов** | `sudo ss -tulpn`                   | Привязка сокетов к процессам и UID                 |
| **Открытые файлы и сокеты**  | `lsof -u username -i`              | Полный срез открытых сетевых ресурсов пользователя |
