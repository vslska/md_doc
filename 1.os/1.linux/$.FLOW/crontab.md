# Crontab

> **`crontab` (cron table)** — это встроенный в Linux/Unix инструмент для планирования автоматического выполнения задач в фоновом режиме по расписанию.

## Основные команды управления

Все команды выполняются в терминале:

- `crontab -e` — **Редактировать** файл расписания (создает его, если файла еще нет). При первом запуске система предложит выбрать текстовый редактор (рекомендуется `nano`).
- `crontab -l` — **Вывести список** всех текущих задач на экран.
- `crontab -r` — **Удалить** все текущие задачи (очистить cron-файл). _Внимание: выполняется без подтверждения, используйте осторожно._
- `crontab -u username -e` — Редактировать cron для **конкретного пользователя** (требуются права `sudo`).

## Синтаксис и структура

Каждая строка в `crontab` — это отдельная задача. Она состоит из двух частей: **расписания** (5 звезд/значений) и **пути к команде/скрипту**.

```
.---------------- минута (0 - 59)
|  .------------- час (0 - 23)

|  |  .---------- день месяца (1 - 31)
|  |  |  .------- месяц (1 - 12)
|  |  |  |  .---- день недели (0 - 7) (0 и 7 — это воскресенье)
|  |  |  |  |
*  *  *  *  *  /path/to/command
```

Специальные символы:

- `*` (Звездочка) — Любое значение. Например, `*` на месте минут означает «каждую минуту».
- `,` (Запятая) — Перечисление значений. `1,15,30` — выполнять в 1-ю, 15-ю и 30-ю минуты.
- `-` (Дефис) — Диапазон значений. `1-5` в поле дня недели означает «с понедельника по пятницу».
- `/` (Слэш) — Шаг/интервал. `*/10` в поле минут означает «каждые 10 минут».

## Шпаргалка по популярным интервалам

|Расписание|Что означает|Пример|
|---|---|---|
|`* * * * *`|**Каждую минуту**|Любой частый мониторинг|
|`*/5 * * * *`|**Каждые 5 минут**|Проверка почты или логов|
|`0 * * * *`|**Каждый час** (в 00 минут)|Ротация логов|
|`0 0 * * *`|**Каждую полночь** (в 00:00)|Ежедневный бэкап|
|`0 3 * * *`|**Каждую ночь в 03:00**|Тяжелые задачи, пока нет пользователей|
|`0 0 * * 1`|**Каждый понедельник** в 00:00|Еженедельные отчеты|
|`0 0 1 * *`|**Первого числа каждого месяца**|Ежемесячная статистика|

### Быстрые текстовые макросы (алиасы):

Вместо пяти звезд можно использовать готовые ключевые слова:

- `@reboot` — Выполнить команду один раз **при загрузке системы**.
- `@daily` (или `@midnight`) — Раз в день в полночь (`0 0 * * *`).
- `@hourly` — Раз в час (`0 * * * *`).
- `@weekly` — Раз в неделю в полночь воскресенья (`0 0 * * 0`).

## Практические примеры

1. **Запуск PHP-скрипта каждые 15 минут:**

```sh
*/15 * * * * /usr/bin/php /var/www/project/cron.php
```

2. **Запуск Bash-скрипта по будням в 18:30:**

```sh
30 18 * * 1-5 /home/user/scripts/backup.sh
```

3. **Очистка кэша дважды в день (в 4:00 и в 16:00):**

```sh
0 4,16 * * * /home/user/scripts/clear_cache.sh
```

## Важные правила и подводные камни (Почему cron не работает?)

1. **Всегда используйте абсолютные пути.** `cron` не знает, где лежат ваши программы. Вместо `python script.py` пишите `/usr/bin/python3 /home/user/script.py`.
    - Узнать путь к интерпретатору можно командой `which python3` или `which php`.
2. **Переменные окружения.** У `cron` очень ограниченный `$PATH`. Если скрипту нужны переменные из `.bashrc` или `.env`, подгружайте их внутри самого скрипта или пишите:

```
* * * * * source /home/user/.bashrc && /home/user/script.sh
```
 
1. **Логирование ошибок.** По умолчанию `cron` отправляет вывод ошибок на внутреннюю почту пользователя. Если вы хотите записывать результаты работы в файл, перенаправляйте потоки:
    - `>> /home/user/cron.log 2>&1` — сохранит и обычный вывод, и ошибки в файл `cron.log`.
    - `> /dev/null 2>&1` — полностью «заглушит» вывод и ошибки (игнорировать всё).
2. **Права на выполнение.** Убедитесь, что ваш скрипт имеет права на запуск: `chmod +x /home/user/script.sh`.
3. **Пустая строка в конце.** Файл `crontab` обязательно должен заканчиваться пустой строкой (нажмите Enter после последней задачи), иначе последняя задача может не выполниться.
