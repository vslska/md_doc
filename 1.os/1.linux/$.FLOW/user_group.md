## Базовые команды Linux (автономные серверы)

Приведенные команды предназначены для управления локальными пользователями и проверки стандартных прав доступа POSIX.

### Просмотр пользователей и групп

|Задача|Команда Bash|Примечание|
|---|---|---|
|Список всех локальных пользователей|`getent passwd`|Чтение базы данных `/etc/passwd`|
|Проверка идентификаторов и групп пользователя|`id [имя_пользователя]`|Вывод UID, GID и списка всех вспомогательных групп|
|Список участников группы|`getent group [имя_группы]`|Чтение базы данных `/etc/group`|
|Проверка принадлежности к группам администрирования|`groups [имя_пользователя]`|Проверка наличия группы `sudo` (Debian/Ubuntu) или `wheel` (RHEL/CentOS)|

### Права доступа к файлам (`ls -l`)

Утилита `ls` с флагом `-l` является основным инструментом для проверки разрешений файлов и каталогов.

```sh
ls -l [путь_к_объекту]
ls -ld [путь_к_каталогу] # Проверка прав самого каталога
```

**Пример вывода:**

```sh
`-rw-r--r-- 1 user group 4096 Apr 14 09:00 filename.txt`
```

|Позиция|Описание|
|---|---|
|Символ 1|Тип объекта (`-` — обычный файл, `d` — каталог, `l` — символическая ссылка)|
|Символы 2–4|Права владельца (`user`: `r` — чтение, `w` — запись, `x` — исполнение)|
|Символы 5–7|Права группы (`group`)|
|Символы 8–10|Права остальных пользователей (`others`)|

## Управление доступами в доменных средах (SSSD, Active Directory, LDAP)

При интеграции сервера в домен (Active Directory или FreeIPA) с использованием системной службы SSSD (System Security Services Daemon) утилита `getent` обращается как к локальным файлам (`/etc/passwd`, `/etc/group`), так и к централизованной базе данных NSS.

### Диагностика службы SSSD

Проверка статуса службы SSSD:

```sh
systemctl status sssd
```

Принудительная очистка кэша SSSD (применяется при задержке обновления прав или состава групп из Active Directory):

```sh
sudo sssd_cache -E
sudo systemctl restart sssd
```

### Чтение данных доменных пользователей и групп

При обращении к доменным объектам применяется следующий синтаксис:

```sh
# Получение информации о доменном пользователе
getent passwd [имя_пользователя]@[имя_домена]

# Получение информации о доменной группе
getent group [имя_группы]@[имя_домена]

# Проверка всех групп доменного пользователя
id [имя_пользователя]@[имя_домена]
```

### Проверка членства в доменных группах

В доменных инфраструктурах разрешения на уровне файловой системы назначаются доменным группам. Служба SSSD выполняет сопоставление (маппинг) идентификаторов безопасности Active Directory (SID) в локальные идентификаторы Linux (POSIX GID/UID).

Если доступ к файлу отсутствует, требуется с помощью команды `id` убедиться в наличии соответствующей доменной группы в списке текущих активных групп пользователя в системе.

## Расширенные списки контроля доступа (ACL)

Списки ACL (Access Control Lists) предназначены для разграничения прав доступа, выходящего за рамки стандартной модели POSIX (Владелец / Группа / Остальные).

Просмотр ACL для файла или каталога:

```sh
getfacl [путь_к_объекту]
```

Назначение или изменение ACL (пример предоставления прав на чтение и запись пользователю `user_x`):

```sh
setfacl -m u:user_x:rw [путь_к_файлу]
```
