# Глоббинг, подстановка путей (Globbing / Pattern Matching) в Bash

**Globbing (Pathname Expansion)** — это встроенный в командную оболочку механизм автоматической подстановки имён файлов и директорий по заданным шаблонам, выполняемый _строго до_ запуска целевой команды.

### ⚠️ Главное архитектурное правило

Раскрытием шаблонов занимается **исключительно Shell**, а не вызываемая утилита. Когда вы выполняете `rm *.tmp`, бинарник `/usr/bin/rm` никогда не видит символ `*`. Шелл сканирует директорию через системные вызовы `opendir()` и `readdir()`, формирует массив строк из подошедших файлов и передает этот массив в системный вызов `execve()`.
- **Ловушка лимитов (`ARG_MAX`):** Если в папке находится 500 000 файлов, маска `*` раскроется в гигантскую строку. Система вернет ошибку `Argument list too long`. В таких сценариях глоббинг использовать нельзя — обработку нужно переводить на потоковый `find ... -exec` или `xargs`.

---

## Базовые спецсимволы подстановки

|Символ|Назначение|Область действия / Ограничения|
|---|---|---|
|`*`|Любое количество любых символов (включая ноль)|Запрещено сопоставление с разделителем пути `/` и скрытыми файлами (`.`)|
|`?`|Строго один любой символ|Не совпадает с разделителем `/` и начальной точкой скрытого файла|
|`[...]`|Класс (набор) символов|Совпадает ровно с **одним** символом из указанного внутри перечня|
|`[!...]` или `[^...]`|Инвертированный класс|Совпадает ровно с **одним** символом, **не входящим** в указанный набор|
|`{a,b,c}`|Фигурные скобки (Brace Expansion)|**Внимание:** Не является глоббингом. Выполняется _раньше_ и подставляет строки независимо от наличия файлов|

Практические примеры и скрытые ловушки

Использование `*` и `?`

bash

```
# Выведет все файлы с расширением .txt в текущей директории
ls *.txt

# Ищет файлы с фиксированной длиной имени: ровно 3 символа и расширение .c (например, foo.c)
ls ???.c
```

Use code with caution.

⚠️ Ловушка регулярных выражений в классах `[...]`

Символы внутри `[...]` — это **не регулярные выражения**. Конструкция `[a-z]` зависит от текущих настроек локали (`LC_COLLATE`). В современных дистрибутивах Linux с UTF-8 порядок сортировки часто выглядит как `aAbBcCdD...`. Из-за этого маска `[A-Z]` внезапно совпадет со строчными буквами, а `[a-z]` — со всеми заглавными, кроме `A`.

**Решение (POSIX-классы):** Чтобы скрипты работали стабильно на любых серверах, всегда используйте стандартизированные POSIX-классы (пишутся внутри квадратных скобок: `[[...]]`):

bash

```
# Безопасный поиск файлов, начинающихся строго с заглавной буквы
ls [[:upper:]]*

# Поиск логов, имя которых начинается с цифрового символа
ls [[:digit:]]*.log
```

Use code with caution.

**Ключевые POSIX-классы:**

- `[:alnum:]` — буквенно-цифровые символы
- `[:alpha:]` — строго буквы
- `[:digit:]` — строго цифры
- `[:space:]` — пробелы, табы, переводы строк 
Механизм Brace Expansion `{...}`

Оболочка раскрывает фигурные скобки математически, ей не важно, существуют ли такие пути на диске:

bash

```
# Быстрое создание резервной копии конфигурации. Развернется в: cp nginx.conf nginx.conf.bak
cp nginx.conf{,.bak}

# Генерация пустых файлов с инкрементом и автодополнением нулями
touch img_{001..010}.png
```

Use code with caution.

Полноценный тюнинг поведения глоббинга (`shopt`)

Управлять поведением раскрытия масок внутри шелла можно с помощью встроенной команды `shopt` (Shell Options):

bash

```
shopt -s globstar # Включить рекурсивный поиск ** (например, **/*.py найдет все скрипты во всех подпапках)
shopt -s dotglob  # Заставляет маску `*` включать скрытые файлы, начинающиеся с точки
```

Use code with caution.

⚠️ Смертоносная ловушка маски `.*` и опции `nullglob`

1. **Никогда не используйте маску `.*` для работы со скрытыми файлами.**  
    Конструкция `rm -rf .*` совпадет со скрытыми файлами, но также совпадет с директориями `.` (текущая) и `..` (родительская). В результате команда **удалит все данные в родительском каталоге**, к которому у процесса есть доступ.  
    _Правильный подход:_ Включить `shopt -s dotglob` и использовать обычную маску `*`. 
2. **Опасность глобального включения `shopt -s nullglob`.**  
    По умолчанию, если файлов по маске не найдено, шелл оставляет маску как есть (например, `ls *.xyz` вернет ошибку `No such file`). Опция `nullglob` заставляет маску полностью исчезать, если совпадений нет._Где сокрыта авария:_ Вы выполняете команду проверки `ls *.xyz`. Если файлов нет, маска стирается, команда превращается в чистый `ls` и **выводит весь список файлов текущей директории**, дезинформируя вас. Еще хуже в скриптах автоматизации: `rm -rf *.xyz` при отсутствии файлов превратится в `rm -rf` без аргументов (что в некоторых шеллах или условиях может отработать непредсказуемо).  
    _Правильный подход:_ Используйте `shopt -s failglob` (возвращает ошибку шелла, блокируя выполнение команды, если файлы не найдены) либо включайте `nullglob` локально внутри скрипта строго на время выполнения конкретного цикла.

Расширенные шаблоны (Extended Globbing)

Для активации продвинутого сопоставления (аналог регулярных выражений, но силами шелла) необходимо включить опцию `extglob`:

bash

```
shopt -s extglob
```

Use code with caution.

Синтаксис `extglob`

|Шаблон|Эквивалент в Regular Expressions|Описание логики|
|---|---|---|
|`?(pattern)`|`(pattern)?`|0 или 1 совпадение с шаблоном|
|`*(pattern)`|`(pattern)*`|0 или более совпадений|
|`+(pattern)`|`(pattern)+`|1 или более совпадений|
|`@(pattern)`|`(pattern)`|Строго 1 точное совпадение|
|`!(pattern)`|`^((?!pattern).)*$`|**Самый полезный флаг:** Всё, кроме указанного шаблона|

Разделителем альтернатив внутри круглых скобок выступает символ вертикальной черты `|`.
Примеры использования `extglob` в проде:

bash

```
# Удалить все файлы в директории, кроме конфигурационных файлов .conf
rm -f !(*.conf)

# Поиск архивов с вариативным именованием (найдет: backup-v1.tar, backup-v2.tar, но проигнорирует backup-media.tar)
ls backup-+(v1|v2).tar

# Поиск опциональных префиксов данных (найдет: report.csv, region1-report.csv, region2-report.csv)
ls ?(region1-|region2-)report.csv
```
