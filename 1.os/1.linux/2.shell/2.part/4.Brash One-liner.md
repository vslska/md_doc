# Конвейеры и генерация данных: Методология проектирования дерзких однострочников Bash

**Дерзкий однострочник (Brash One-liner)** — это компактная, многоуровневая цепочка утилит, решающая нетривиальную системную задачу за один запуск без создания временных файлов на диске и написания тяжелых скриптов.

---

## Методология безопасного проектирования пайплайнов

Сложные конвейеры никогда не пишутся вслепую. Сборка идет по строгому шаблону: **Генерация → Форматирование → Валидация (Dry-run) → Исполнение**.

```text
  [ Шаг 1. Исходный поток ] ──► ( find / seq ) 
              ▼
  [ Шаг 2. Трансформация  ] ──► ( sed / awk / paste ) 
              ▼
  [ Шаг 3. Безопасный аудит] ──► ( | less / head -n3 / добавить echo ) 
              ▼
  [ Шаг 4. Боевой запуск  ] ──► ( | bash )
```

Набор инструментов отладки конвейера «на лету»

- `... | head -n 3` — проверка структуры первых трех строк.
- `... | less` — интерактивный просмотр всего сгенерированного объема данных.
- `... | sed 's/^/echo /' | bash` — безопасный холостой прогон (**Dry-run**).
- `... | tee /tmp/debug.log | ...` — ответвление потока для фиксации промежуточного результата без прерывания конвейера.

## Боевой кейс 1: Массовое переименование со сдвигом номеров

В каталоге лежат файлы: `item03.txt`, `item04.txt`, ..., `item10.txt`. Нужно вставить новый элемент на позицию `03`, сдвинув все существующие файлы на один шаг вперед (`03 -> 04`, `10 -> 11`).

### ⚠️ Архитектурная ловушка прямого порядка

Если начать переименование с начала (`03 -> 04`), то файл `item03.txt` намертво перезапишет собой оригинальный `item04.txt` еще до того, как тот будет обработан. Данные будут безвозвратно потеряны. Сдвиг всегда обязан выполняться **строго в обратном порядке**.

### Решение через конвейер и Process Substitution

```bash
paste <(seq -w 10 -1 3 | sed 's/.*/item&.txt/') \
      <(seq -w 11 -1 4 | sed 's/.*/item&.txt/') \

| sed 's/^/mv -n /' | bash
```

- `seq -w 10 -1 3` — генерирует числа сверху вниз с ведущими нулями: `10, 09, ..., 03`.
- `paste <(...) <(...)` — сливает два вертикальных потока в пары: `item10.txt item11.txt`.
- `sed 's/^/mv -n /'` — превращает каждую пару в готовую команду перемещения (флаг `-n` защищает от случайной перезаписи).

### Безопасная альтернатива на чистом Bash (Без внешних процессов)

Если файлов миллионы, запуск через `paste` может упереться в лимиты дескрипторов. Оптимальный вариант — внутренний цикл CFS:

```bash
for i in {10..3}; do
    printf -v old_f "item%02d.txt" $i
    printf -v new_f "item%02d.txt" $((i + 1))
    [[ -f "$old_f" ]] && mv -n "$old_f" "$new_f"
done
```

## Боевой кейс 2: Поиск непарных файлов (Аудит целостности)

### Задача

В папке лежат пары файлов: `photo1.jpg` (изображение) и `photo1.txt` (метаданные). Нужно мгновенно вычислить "сирот" — `.jpg` без `.txt` и наоборот.

### Решение через дедупликацию потока (`uniq -c`)

```bash
printf '%s\n' *.{jpg,txt} \
| sed 's/\.[^.]*$//' \
| sort \
| uniq -c \
| awk '$1 == 1 {print $2 "*"}' \
| xargs -I {} ls -l {}
```

- `printf '%s\n' *.{jpg,txt}` — безопасный вывод всех файлов по одной строке (не ломается на пробелах в отличие от `ls`).
- `sed 's/\.[^.]*$//'` — ювелирно отрезает расширение файла после последней точки (превращает `vacation.beach.jpg` в `vacation.beach`).
- `uniq -c` — подсчитывает количество вхождений базового имени. Если имя встретилось 2 раза — пара цела. Если 1 раз — файл одинок.
- `awk '$1 == 1 ...'` — выделяет имена "сирот" и формирует маску для вызова `ls`.

## Боевой кейс 3: Динамическая автоматизация путей через `CDPATH`

Переменная `CDPATH` позволяет оператору делать быстрый переход в глубокие подкаталоги домашней папки без ввода полных путей (например, написать `cd Work` из любой локации системы и сразу оказаться в `~/Work`).

### ⚠️ Ловушка безопасности Path Traversal

Если сгенерировать строку `CDPATH` некорректно и поставить путь `$HOME` на первое место, шелл потеряет приоритет текущей папки. Находясь в каталоге проекта и пытаясь перейти в локальную папку `cd Имя`, шелл утащит вас в домашний каталог хоста.

**Правило:** Текущая точка (`.`) всегда обязана идти первым элементом в строке путей.

### Автоматическая генерация строки для `~/.bashrc`

```bash
echo "export CDPATH=.:\$HOME:\$(cd && ls -d */ 2>/dev/null | sed 's@/$@@' | sed 's@^@\$HOME/@' | tr '\n' ':').." >> ~/.bashrc
```

_Как это работает:_ Подоболочка `(cd)` переходит в корень пользователя, забирает список папок через `ls -d */`, отрезает завершающие слэши, подставляет префикс `$HOME/` и склеивает всё в единую строку через двоеточие.

## Боевой кейс 4: Генерация тестовых датасетов (Стресс-тестирование)

При отладке высоконагруженных систем часто требуется быстро сгенерировать тысячи файлов случайного размера со случайным содержимым для проверки квот, лимитов inode или парсеров.

### 1. Генерация 1000 текстовых файлов со случайным наполнением

```
yes 'shuf -n $RANDOM /usr/share/dict/words > $(pwgen -N1 10).txt' | head -1000 | bash
```

- **⚠️ Критическая ловушка экранирования:** Обратите внимание на одинарные кавычки `'...'` внутри `yes`. Если поставить двойные кавычки `"..."`, подстановка команды `$(pwgen ...)` вычислится ровно **один раз до старта конвейера**. В результате `yes` сгенерирует 1000 абсолютно одинаковых строк, и утилита `bash` просто перезапишет один и тот же файл 1000 раз. Одинарные кавычки заставляют шелл вычислять `pwgen` и `$RANDOM` заново на каждой итерации цикла `bash`.

### 2. Генерация тестовых бинарных файлов фиксированного размера

```bash
# Создать 50 изолированных бинарных файлов по 10 МБ со случайными байтами внутри
for i in {1..50}; do 
    dd if=/dev/urandom of=test_pool_"$i".bin bs=1M count=10 status=none
done
```

## Инженерные правила применения однострочников

1. **Разовость применения:** Однострочники идеальны для быстрой аналитики, расследования инцидентов и разовой модификации данных на проде.
2. **Запрет в Production-автоматизации:** Никогда не вставляйте сложные "дерзкие" конвейеры внутрь постоянных скриптов автоматизации, крона или CI/CD пайплайнов. Они хрупки, не имеют обработки ошибок (error trapping) и сложны в чтении для других членов команды. Для постоянной логики пишите явные, читаемые скрипты с флагом `set -euo pipefail`.
