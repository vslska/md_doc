# POSIX обработка структурированного текста: Текстовые базы данных, индексация и автоматизация

В Unix-системах структурированный текст является универсальным интерфейсом обмена данными между ядром, системными конфигурациями и пользовательскими процессами. Использование атомарных утилит обработки потоков (`awk`, `grep`, `sed`, `sort`) позволяет разворачивать отказоустойчивые системы мониторинга и базы данных без привлечения тяжелых языков программирования.

---

## 1. Проектирование текстовых баз данных: Выбор разделителя

При проектировании локальных текстовых хранилищ критически важен выбор разделителя полей (Delimiter).

- **❌ CSV (Comma-Separated):** Запятая хрупка. Если внутри текстового поля (например, в примечании или адресе) попадется запятая, парсинг через `cut` или `awk` сломает геометрию таблицы.
- **✅ TSV (Tab-Separated):** Символ табуляции (`\t`) практически никогда не встречается внутри пользовательских данных. Это делает TSV промышленным стандартом для текстовых баз данных в Linux.

### ⚠️ Архитектурный стандарт потокового чтения `while read`

Обычный цикл `for line in $(cat file)` полностью уничтожает структуру данных, если в строках есть пробелы. Единственный безопасный способ построчной обработки файлов — потоковый цикл `while` с принудительным сбросом внутреннего разделителя полей (`IFS`):

```bash
# Обнуление IFS= гарантирует, что read прочитает строку абсолютно буквально без обрезки пробелов
while IFS= read -r domain; do
    [[ -n "$domain" ]] && ./check-expiry.sh "$domain"
done < domains.txt
```

## 2. Боевой кейс: Мгновенный поиск через атомарный индекс файлов

### Задача

Поиск файлов через `find` по гигантским дисковым массивам (миллионы файлов) утилизирует слишком много I/O диска. Необходимо реализовать мгновенный персонализированный поиск.

### Решение: Атомарная генерация статического индекса

Создавать индекс напрямую в рабочий файл `> ~/.ALLFILES` запрещено: во время долгой работы `find` файл будет заблокирован или обнулен. Сборка индекса должна быть **атомарной** на уровне ядра (через системный вызов `rename()`):

```bash
# Скрипт генерации индекса (добавляется в每周 крон)
find "$HOME" -type f -print > "$HOME/.ALLFILES.tmp" && mv "$HOME/.ALLFILES.tmp" "$HOME/.ALLFILES"
```

### Поисковый скрипт-обертка (`~/bin/ff`)

```bash
#!/bin/bash
# Защита от пустого ввода
[[ -z "$1" ]] && { echo "Usage: ff <search_pattern>" >&2; exit 1; }

# Мгновенный полнотекстовый поиск по индексу с поддержкой регулярных выражений
grep -E "$1" "$HOME/.ALLFILES"
```

## 3. Боевой кейс: Автоматизированный мониторинг доменов (whois)

Отслеживать даты окончания регистрации пула доменов, выявлять "горячие" зоны (истекающие менее чем через 14 дней) и отправлять отчет на почту.

### Скрипт парсинга и нормализации даты (`check-expiry.sh`)

```bash
#!/bin/bash
domain="$1"
# Извлекаем дату, отсекаем возможные шумы и приводим к ISO-стандарту YYYY-MM-DD
exp=$(whois "$domain" 2>/dev/null | awk -F ': *' '/Registry Expiry Date|Expiry Date|Expiration Date/ {print $2; exit}')

if [[ -n "$exp" ]]; then
    date --date="$exp" '+%Y-%m-%d' 2>/dev/null || echo "INVALID"
else
    echo "UNKNOWN"
fi
```

### Конвейер агрегации и выявления рисков

```bash
while IFS= read -r domain; do
    [[ -z "$domain" || "$domain" =~ ^# ]] && continue
    echo "$(./check-expiry.sh "$domain") $domain"
    sleep 3 # Жесткое правило: защита от бана со стороны whois-серверов за флуд
done < domains.txt \
| sort -k1,1 \
| awk -v alert_date="$(date -d '+14 days' +%Y-%m-%d)" '$1 <= alert_date'
```

## 4. Боевой кейс: CLI-менеджер паролей с шифрованием (pman)

### Структура базы данных (`~/etc/vault`)

Формат строго **TSV**. Поля: `Логин \t Пароль \t Ключ-Тег \t Примечания`.

```bash
sally	fake_pass1	google	personal account
ssmith	fake_pass2	aws	production root key
```

### Безопасное развертывание и шифрование (GPG)

Оставлять пароли в открытом виде или генерировать их через `echo "..." > file` запрещено (данные осядут в истории `.bash_history`).

```bash
# 1. Создаем пустой файл и мгновенно закрываем к нему доступ всем, кроме владельца
touch ~/etc/vault && chmod 600 ~/etc/vault

# 2. Редактируем базу строго внутри Vim/Nano, после чего шифруем промышленным ключом GPG
gpg -e -r your-email@domain.com ~/etc/vault
shred -u ~/etc/vault # Надежное посекторное уничтожение открытого файла с диска
```

### Финальный автоматизированный скрипт поиска (`~/bin/pman`)

```bash
#!/bin/bash
PROGRAM=$(basename "$0")
DATABASE="$HOME/etc/vault.gpg"

[[ $# -ne 1 ]] && { echo "Usage: $PROGRAM <search-term>" >&2; exit 1; }
searchstring="$1"

# 1. Расшифровываем базу в RAM и одной командой AWK убираем комментарии и ищем точное совпадение по Тегу (3-е поле)
match=$(gpg -d -q "$DATABASE" 2>/dev/null | awk -F'\t' -v key="$searchstring" '$0 !~ /^#/ && $3 == key {print $0}')

# 2. Если точного совпадения по ключу нет — выполняем нечеткий полнотекстовый поиск по всей базе
if [[ -z "$match" ]]; then
    match=$(gpg -d -q "$DATABASE" 2>/dev/null | awk -v pat="$searchstring" '$0 !~ /^#/ && $0 ~ pat {print $0}')
fi

[[ -z "$match" ]] && { echo "$PROGRAM: Нет совпадений для '$searchstring'" >&2; exit 1; }

# 3. Извлекаем пароль (2-е поле) и асинхронно закидываем в буфер обмена с автоочисткой через 15 секунд
password=$(echo "$match" | cut -f2)
echo -n "$password" | xclip -selection clipboard

echo "Пароль для '$searchstring' скопирован в буфер. Очистка через 15 секунд..."
(sleep 15 && echo -n "" | xclip -selection clipboard) >/dev/null 2>&1 &
```

## Продвинутые фишки работы с плоским текстом

### Генерация структурированных таблиц из AWK

Для красивого вывода текстовых баз в терминал используйте встроенную функцию форматирования `printf` утилиты `awk` вместо системного `echo`:

```bash
# Выровнять три столбца базы по левому краю с фиксированной шириной колонок
awk -F'\t' '{printf "%-15s %-15s %-30s\n", $1, $2, $3}' ~/data/areacodes.tsv
```

### Экспорт текстовой базы в легитимный CSV для Excel

Если в текстовых полях есть пробелы, при конвертации в CSV их необходимо экранировать кавычками, иначе внешние парсеры разломают таблицу:

```bash
awk -F'\t' 'BEGIN{OFS=","} {print $1, $2, "\""$3"\""}' database.tsv > export.csv
```
