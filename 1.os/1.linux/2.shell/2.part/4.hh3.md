### Создание дерзких однострочников

**Дерзкий однострочник** (brash one-liners) — это компактная, часто многоуровневая команда, которая решает нетривиальную задачу за один запуск. Она выглядит как «магия», но на самом деле — результат чёткого мышления и глубокого знания инструментов.

> Это не ради хвастовства. Это тренировка:  
> -   умения разбивать задачу на шаги,  
> -  понимания потоков данных,  
> - владения конвейерами и подстановками.

#### Пример
``` bash
paste <(echo {1..10}.jpg | sed 's/ /\n/g') \
      <(echo {0..9}.jpg  | sed 's/ /\n/g') \
| sed 's/^/mv /' \
| bash
```

> **Цель**: переименовать `1.jpg → 0.jpg`, `2.jpg → 1.jpg`, ..., `10.jpg → 9.jpg`.

**По шагам**:
1. `{1..10}.jpg` → `1.jpg 2.jpg ... 10.jpg` (одна строка)
2. `sed 's/ /\n/g'` → превращает в столбец
3. `paste` соединяет два столбца:
```bash
1.jpg  0.jpg
2.jpg  1.jpg
...
```
4. `sed 's/^/mv /'` → делает из каждой строки команду:  
    `mv 1.jpg 0.jpg`
5. `| bash` — выполняет сгенерированные команды.

> Всё в одной строке. Никаких циклов. Никаких временных файлов.

---
### Методология создания однострочников

#### 1. **Начну с исходных данных**

Что у меня есть?

- Список файлов? → `ls`, `find`
- Диапазон чисел? → `{1..100}`
- Дата? → `date`
- Содержимое файла? → `cat`, `grep`

**Пример**: найти 17-ю букву алфавита:
```bash
echo {A..Z} | tr ' ' '\n' | sed -n '17p'
# или
echo {A..Z} | awk '{print $17}'
```

#### 2. **Преобразуй данные по шагам**

Используй конвейер:

- `tr`, `sed` — форматирование
- `awk`, `cut` — извлечение
- `sort`, `uniq`, `head`/`tail` — фильтрация
- `xargs`, `paste` — перекомпоновка

#### 3. **Проверяй каждый этап**

Не пишу всё сразу. Собираю по кирпичикам:
```
# Шаг 1
echo {1..5}

# Шаг 2
echo {1..5} | tr ' ' '\n'

# Шаг 3
paste <(echo {1..5}) <(echo {6..10})

# Шаг 4 — готово!
paste <(echo {1..5}) <(echo {6..10}) | sed 's/^/echo pair: /'
```

#### 4. **Безопасное выполнение**
Перед `| bash` всегда проверю:
```bash
# ❌ Опасно
... | bash

# ✅ Безопасно
... | less        # смотрим
... | head -n3    # проверяем начало
... | sed 's/^/echo /' | bash  # dry-run
```

---
### Инструменты для отладки
| Приём                   | Зачем                                              |
| ----------------------- | -------------------------------------------------- |
| `echo перед командой`   | Dry-run для `rm`, `mv`, `cp`                       |
| `tee debug.txt`         | Посмотреть промежуточный вывод в длинном пайплайне |
| `set -x`                | Включить трассировку в скрипте                     |
| История (`↑`, `Ctrl-R`) | Быстро повторять и править команды                 |

```bash
find . -name "*.log" \
| tee /tmp/logs_found.txt \
| xargs -r rm
# Теперь можно проверить: cat /tmp/logs_found.txt
```

### Фишки и альтернативные подходы

#### Гибкость — ключ

Задача: показать все `.jpg` файлы.

Можно **многими способами**:
```bash
ls *.jpg
ls | grep '\.jpg$'
find . -maxdepth 1 -name "*.jpg"
compgen -G "*.jpg"          # только имена, без ls
printf '%s\n' *.jpg         # безопаснее, если файлов много
```

Выбирай **под контекст**:

- `*.jpg` ломается при большом числе файлов → используй `find`
- Нужны только имена без метаданных → `printf` или `compgen`

#### Генерация команд через `awk`

Хочу создать 10 команд `touch file1.txt ... file10.txt`?

```bash
seq 10 | awk '{print "touch file" $0 ".txt"}' | bash
```

#### Использование `xargs -I` для сложных шаблонов
```bash
find . -name "*.bak" -print0 | xargs -0 -I {} sh -c 'echo "Удаляю: {}"; rm "{}"'
```

### Когда НЕ стоит писать однострочник

- Логика сложная (ветвления, циклы с условиями) → пиши скрипт.
- Команда будет использоваться часто → вынеси в функцию или скрипт.
- Безопасность критична → лучше явный, читаемый код.

> **Правило**:  
   Если мне самому через неделю будет непонятно, что делает команда — она слишком «дерзкая».
### Итог

Дерзкие однострочники — это:

- **Искусство композиции** стандартных утилит,
- **Тренировка системного мышления**,
- **Инструмент быстрого прототипирования**.



### Пример 1. Массовое переименование файлов с сдвигом номеров

**Задача**:  
У вас есть файлы с числовыми суффиксами:  
`item03.txt`, `item04.txt`, ..., `item10.txt`.  
Вы хотите **вставить новый элемент** между `02` и `03`, поэтому все существующие файлы с `03` по `10` должны стать `04`–`11`.

**Решение**:
```bash
paste <(seq -w 10 -1 3 | sed 's/.*/item&.txt/') \
      <(seq -w 11 -1 4 | sed 's/.*/item&.txt/') \
| sed 's/^/mv /' \
| bash
```
#### Как это работает?

1. `seq -w 10 -1 3` → генерирует числа **в обратном порядке**: `10`, `09`, ..., `03`  
    → Обратный порядок **обязателен**, чтобы не перезаписать `item04.txt` до того, как он будет перемещён.
2. `sed 's/.*/item&.txt/'` → превращает `10` в `item10.txt`
3. `paste` соединяет два списка в пары:

```bash
item10.txt item11.txt
item09.txt item10.txt
...
item03.txt item04.txt
```

4.  `sed 's/^/mv /'` → делает из каждой строки команду: `mv item10.txt item11.txt`
5. `| bash` — выполняет все команды

> **Почему именно так?**  
> Это **универсальный шаблон** для любых задач, где нужно сдвинуть нумерацию: логи, бэкапы, сканы, фото и т.д.

> **Важно**:  
> Никогда не делайте такое в прямом порядке (`03 → 04`, потом `04 → 05`) — вы потеряете файл!

#### Альтернатива (если поддерживается):
```bash
# В Bash можно использовать массивы и цикл (без внешних вызовов)
for i in {10..3}; do
    mv "item$(printf "%02d" $i).txt" "item$(printf "%02d" $((i+1))).txt"
done
```

### Пример 2. Поиск непарных файлов (например, `.jpg` без `.txt`)

**Задача**:  
В каталоге лежат файлы вида:

- `photo1.jpg`, `photo1.txt`
- `photo2.jpg` ← **нет описания**
- `report.txt` ← **нет изображения**

Нужно найти **все файлы, у которых нет пары**.

#### Решение 1: через `diff`
```bash
diff <(ls *.jpg | sed 's/\.[^.]*$//') \
     <(ls *.txt | sed 's/\.[^.]*$//') \
| grep '^[<>]' \
| awk '/^</{print $2 ".jpg"} /^>/{print $2 ".txt"}'
```

**Что делает `sed 's/\.[^.]*$//'`?**  
Удаляет **всё после последней точки**, даже если точек несколько:

- `vacation.beach.jpg` → `vacation.beach` ✅
- `cut -d. -f1` дало бы `vacation` ❌

#### Решение 2: через подсчёт (`uniq -c`)
```bash
ls *.{jpg,txt} \
| sed 's/\.[^.]*$//' \
| sort \
| uniq -c \
| awk '$1 == 1 {print $2 "*"}' \
| xargs -I{} ls {}
```

**Логика**:
- Если имя встречается **дважды** → есть и `.jpg`, и `.txt`
- Если **один раз** → файл без пары
- Добавляем `*` → получаем шаблон (`photo2*`)
- `xargs ls {}` → показывает реальные файлы

> **Плюсы второго способа**:> 
> - Не зависит от порядка файлов
> - Легко адаптируется под другие расширения (`*.log` + `*.yaml`, например)

> **Минус обоих**:  
> Использование `ls` небезопасно в скриптах (ломается при пробелах или отсутствии файлов).  
> Для production лучше использовать `find` или glob-массивы.

---
### Универсальные принципы

1.  **Генерируйте данные, а не пишите вручную**  
    → `seq`, `{1..10}`, `find` — ваши друзья.
2. **Преобразуйте по шагам**  
    Каждая команда в конвейере — фильтр:  
    `данные → форматирование → объединение → выполнение`
3.  **Тестируйте перед запуском**  
    Замените `| bash` на `| less` или добавьте `echo`:
```bash
... | sed 's/^/echo mv /' | head
```

4. **Обрабатывайте сложные имена**  
    Всегда предполагайте, что в имени файла могут быть:
    - пробелы,
    - точки,
    - спецсимволы (`$`, `(`, `[`).
5. **Избегайте `ls` в скриптах**  
    Вместо `ls *.jpg` используйте:
```bash
for f in *.jpg; do [[ -e "$f" ]] && echo "$f"; done
```

### Когда использовать такие однострочники?

✅ **Хорошо**:

- Разовые задачи (переименовать 50 файлов)
- Анализ данных в терминале
- Быстрая автоматизация без написания скрипта

❌ **Плохо**:

- Production-логика
- Сложная бизнес-логика
- Повторяющиеся задачи → лучше написать скрипт

Эти примеры — не «магия», а **системное применение базовых инструментов**. Освоив их, вы сможете решать десятки рутинных задач за секунды — без GUI, без Python, только с помощью оболочки.


### Создание `CDPATH` автоматически

**Цель**:  
Создать переменную `CDPATH`, которая позволяет переходить в подкаталоги домашней папки **без указания полного пути**:
```bash
cd Work      # вместо cd ~/Work
cd Linux     # вместо cd ~/Linux
```

Для этого нужно собрать строку вида:  
`PATH=$HOME:$HOME/Work:$HOME/Family:$HOME/Finances:$HOME/Linux:$HOME/Music:..`

#### Пошаговое построение однострочника

1. **Получить список подкаталогов в `$HOME`**
```bash
(cd && ls -d */)
```
> → `(cd ...)` гарантирует, что текущий каталог не изменится.

2. **Добавить `$HOME/` к каждому имени**  
   Используем `sed` с нестандартным разделителем (`@`), чтобы избежать экранирования `/`:
   ```bash
   sed 's@^@$HOME/@'
   ```

3. **Убрать завершающий `/`**  
   ```bash
   sed 's@/$@@'
   ```

4. **Объединить всё в одну строку через пробелы**  
   Подстановка команды сама создаёт подоболочку:
   ```bash
   echo $(cd && ls -d */ | sed -e 's@^@$HOME/@' -e 's@/$@@')
   ```

5. **Добавить `$HOME` в начало и `..` в конец**  
   ```bash
   echo '$HOME' $(...) ..
   ```

6. **Заменить пробелы на двоеточия**  
   ```bash
   tr ' ' ':'
   ```

7. **Добавить префикс `CDPATH=`**  
   ```bash
   echo "CDPATH=$(echo '$HOME' $(cd && ls -d */ | sed -e 's@^@$HOME/@' -e 's@/$@@') .. | tr ' ' ':')"
   ```

Или проще — сразу сформировать готовую строку для `.bashrc`:
```bash
echo 'CDPATH=$HOME:'$(cd && ls -d */ | sed -e 's@^@$HOME/@' -e 's@/$@@' | tr '\n' ':')'..'
```

---
###  Улучшенная версия (надёжнее)

Проблема оригинального подхода: `ls -d */` **ломается**, если в домашнем каталоге нет подкаталогов (ошибка). Также он не обрабатывает имена с пробелами корректно.

**Более надёжный способ — через glob и массивы (Bash):**
```bash
dirs=("$HOME" "$HOME"/ */ ..)
# Убираем слеши и формируем CDPATH
paths=()
for d in "${dirs[@]}"; do
    [[ -d "$d" ]] && paths+=("${d%/}")  # убираем завершающий /
done
IFS=:; echo "CDPATH=${paths[*]}"
```

Но если нужен именно **однострочник для терминала**, вот безопасный вариант:
```bash
( shopt -s nullglob; cd; printf '%s:' "$PWD" */ .. ) | sed 's/:\/$/:/' | sed 's/:$//'
```

→ `nullglob` гарантирует, что `*/` не останется как строка, если подкаталогов нет.

---

### Как использовать?

Добавьте в `~/.bashrc`:
```bash
export CDPATH=$(cd && echo -n "$HOME:"; ls -d */ 2>/dev/null | sed 's@/$@@' | sed "s@^@$HOME/@" | tr '\n' ':' ; echo "..")
```

Или проще — генерируйте один раз и вставляйте вручную:
```bash
echo "export CDPATH=\$(cd && echo -n '\$HOME:'; ls -d */ 2>/dev/null | sed 's@/$@@' | sed 's@^@\$HOME/@' | tr '\n' ':' ; echo '..')"
```

После перезагрузки `.bashrc`:
```bash
source ~/.bashrc
cd Music   # работает!
```

---

###  Важные нюансы

- **`CDPATH` влияет только на `cd`**, не на другие команды.
- Если имя каталога совпадает с именем в текущем каталоге — `cd` может выбрать не тот!  
  → Чтобы гарантированно перейти в текущий каталог: `cd ./имя`
- Не все оболочки поддерживают `CDPATH` (например, `fish` — нет). Работает в `bash`, `zsh`.

---

### Альтернатива: псевдонимы или функции

Если подкаталогов немного, проще создать псевдонимы:
```bash
alias cdl='cd ~/Linux'
alias cdw='cd ~/Work'
```

Или функцию:
```bash
c() { cd ~/"$1"; }
# c Work → cd ~/Work
```

→ Это читаемее и безопаснее, чем динамический `CDPATH`.

---

### Итог

Автоматическая генерация `CDPATH` — отличный пример того, как:
- использовать подоболочки для изоляции,
- комбинировать `sed`, `tr`, подстановку команд,
- решать рутинную задачу одной строкой.

Но помните:  
> **Удобство ≠ надёжность.**  
> Для production-окружений или сложных имён файлов лучше использовать явные пути или функции.



### Создание тестовых файлов: однострочники для генерации данных

Часто при разработке или отладке нужно **много файлов** — с разным содержимым, именами или размерами. Вместо ручного создания можно использовать мощь оболочки.
#### 1. Генерация случайных текстовых файлов

**Цель**: создать 1000 файлов со случайным количеством случайных слов.

**Инструменты**:
- `shuf` — перемешивает строки и выбирает N случайных
- `pwgen` — генерирует случайные имена (`apt install pwgen`, если нет)
- `$RANDOM` — встроенная переменная Bash (0–32767)

**Однострочник**:
```bash
yes 'shuf -n $RANDOM /usr/share/dict/words > $(pwgen -N1 10).txt' | head -1000 | bash
```

>  Почему `>` вместо `-o`?  
> Потому что `-o` требует имени файла **до выполнения**, а нам нужно, чтобы `pwgen` вызывался **каждый раз заново**. Через перенаправление `>` это работает.

**Как это работает**:
- `yes '...'` → бесконечно повторяет строку
- `head -1000` → берёт первые 1000 копий
- `| bash` → выполняет каждую как команду
- `$RANDOM` и `$(pwgen ...)` вычисляются **при каждом запуске**

> **Ловушка**:  
> Если написать `shuf -n $RANDOM -o $(pwgen...).txt ...`, то `$(pwgen...)` вычислится **один раз** до запуска `yes` → все файлы получат одно имя!  
> Поэтому используйте перенаправление `>` внутри строки.

---

#### 2. Генерация случайных изображений (если установлен ImageMagick)

```bash
yes 'convert -size 8x8 xc: +noise Random -scale 100x100 $(pwgen -N1 10).png' | head -1000 | bash
```

→ Создаёт 1000 PNG-файлов с шумом. Полезно для тестирования загрузчиков изображений, сканеров и т.д.

>  Установка:  
> ```bash
> sudo apt install imagemagick    # Debian/Ubuntu
> ```

#### 3. Создание пустых файлов

##### Простой способ — нумерованные имена:
```bash
touch file{0001..1000}.txt
```

##### Случайные имена из словаря:
```bash
grep '^[a-z]\+$' /usr/share/dict/words | shuf | head -1000 | xargs touch
```

>  Почему `grep '^[a-z]\+$'`?  
> Чтобы исключить слова с апострофами (`don't`), заглавными буквами или цифрами — такие имена могут сломать команды без кавычек.

>  **Проблема `xargs touch`**:  
> Если имя файла содержит пробел — команда упадёт.  
> **Безопасная версия** (Bash):
> ```bash
> mapfile -t words < <(grep '^[a-z]\+$' /usr/share/dict/words | shuf | head -1000)
> for w in "${words[@]}"; do touch -- "$w"; done
> ```

### Профессиональные фишки

#### Dry-run перед массовым созданием
Всегда проверяйте, что будет создано:
```bash
yes 'echo shuf -n $RANDOM ... > $(pwgen -N1 10).txt' | head -5
```
→ Увидите 5 примеров команд **без выполнения**.

#### Очистка после тестов
```bash
# Удалить все .txt в каталоге
rm *.txt

# Или безопаснее — через find
find . -name "*.txt" -delete
```

#### Генерация файлов заданного размера
```bash
# 10 файлов по 1 МБ
for i in {1..10}; do dd if=/dev/urandom of=file$i.bin bs=1M count=1; done
```

---

### Когда НЕ использовать такие однострочники?

- Если нужны **точные данные** (например, JSON с определённой структурой) → пишите скрипт на Python.
- Если важна **воспроизводимость** → зафиксируйте seed (`shuf -r --random-source=/dev/urandom` не поможет, лучше использовать `sort -R` с фиксированным `LC_ALL=C`).
- Если файлов **миллионы** → лучше использовать `parallel` или скрипт с прогресс-баром.

### Итог

Эти однострочники — не «магия», а **системное применение**:
- генераторов (`shuf`, `pwgen`),
- потоковой обработки (`yes`, `head`, `xargs`),
- динамического выполнения (`| bash`).

Они идеальны для:
- быстрой генерации тестовых данных,
- нагрузочного тестирования,
- демонстрации возможностей терминала.

Но помни:  
> **Однострочник — инструмент для разовых задач.**  
> Для повторяющегося использования — выносите логику в скрипт.
