# Консольный веб-скрейпинг и интеграция с буфером обмена в Linux

Интеграция сетевых текстовых потоков (HTML/API) с локальными инструментами обработки и графической подсистемой ОС позволяет собирать данные и автоматизировать рутину без использования тяжелых браузеров и внешних библиотек программирования.

---

## 1. Загрузка веб-контента: curl против wget

Обе утилиты работают на базе сетевого стека ядра, но имеют разное архитектурное назначение:

- **`curl`**: Ориентирован строго на работу с потоками данных. По умолчанию выводит скачанный контент напрямую в стандартный вывод (`stdout`). Идеален для конвейеров, API-запросов и передачи данных утилитам парсинга.
- **`wget`**: Ориентирован на работу с файловой системой. По умолчанию сохраняет скачанный контент в виде физического файла на диск. Поддерживает рекурсивный выкачивание сайтов целиком с сохранением структуры каталогов.

### Тюнинг сетевой безопасности и отказоустойчивости скриптов

В продакшн-скриптах запрещено запускать `curl`/`wget` без явного указания таймаутов, иначе залипший удаленный сервер намертво заблокирует выполнение всего пайплайна автоматизации:

```bash
# --connect-timeout: лимит на установление TCP-соединения (3 сек)
# --max-time: жесткий лимит на всю операцию скачивания файла (10 сек)
# -A: маскировка под User-Agent легитимного браузера для обхода базовых блокировок (WAF)
curl -s --connect-timeout 3 --max-time 10 -A "Mozilla/5.0" "https://site.com"
```

### Массовое параллельное скачивание файлов

Использование конструкции `| bash` хрупко. Для контролируемого многопоточного выкачивания пула файлов используйте `xargs` с жестким ограничением параллельных процессов (флаг `-P`), чтобы не исчерпать лимиты FD (`EMFILE`) и не получить бан от сетевых фильтров:

```bash
# Скачивание 20 изображений строго в 4 параллельных потока
seq 1 20 | xargs -n 1 -P 4 -I @ wget -q --timeout=5 "https://site.com"
```

## 2. Структурированный парсинг HTML по CSS-селекторам

Пытаться распарсить сложный HTML с помощью регулярных выражений в `sed` или `grep` — архитектурная ошибка (теги могут быть вложенными, перенесенными на новую строку и т.д.). Для извлечения данных из веб-страниц используется промышленный стек утилит `html-xml-utils`:

- `hxnormalize` — исправляет битый HTML, закрывает теги и приводит дерево к строгому стандарту XML.
- `hxselect` — вычленяет текстовое содержимое конкретных узлов на основе стандартных **CSS-селекторов**.

### Боевой пример: Извлечение телефонных кодов с веб-страницы в базу TSV

```bash
curl -s --connect-timeout 5 https://efficientlinux.com \
| hxnormalize -x \
| hxselect -c -s '\t' '#ac .ac, #ac .state, #ac .cities'
```

- `-x` — форсирует вывод в чистом XML-формате.
- `-c` — срезает сами HTML-теги, оставляя только чистый текст внутри узлов.
- `-s '\t'` — **Трюк:** Автоматически разделяет выгруженные столбцы символом табуляции, мгновенно формируя готовую структурированную базу данных TSV.

### Быстрый текстовый дамп страницы через Lynx

Если со страницы не нужно извлекать отдельные узлы, а требуется получить человекочитаемый текстовый слепок (например, для быстрого анализа документации или статьи через терминал):

```bash
# -dump: преобразует HTML в чистый форматированный текст, сноски и ссылки выносит в конец
lynx -dump "https://efficientlinux.com" > page_dump.txt
```

## 3. Работа с буфером обмена: Смена эпох X11 -> Wayland

В графической подсистеме Linux исторически сосуществуют два независимых буфера обмена:

1. **Primary Selection (Основное выделение):** Текст попадает туда автоматически в момент выделения мышью на экране. Вставка выполняется нажатием средней кнопки мыши (колесика).
2. **Clipboard (Глобальный буфер):** Текст попадает туда только при явном копировании (`Ctrl+C` / `Ctrl+Shift+C`). Вставка — через `Ctrl+V`.

### ⚠️ Критическая ловушка: Смена дисплейного сервера (X11 vs Wayland)

В современных дистрибутивах Linux (Ubuntu 22.04+, Arch, Fedora) по умолчанию активен графический сервер **Wayland**. Классические утилиты `xclip` и `xsel` внутри него **не работают**. Скрипты автоматизации необходимо адаптировать под текущую среду.

#### Вариант А: Ваша система работает на базе устаревшего сервера X11

Используем утилиту `xclip`:

```bash
# 1. Скопировать вывод конвейера в глобальный Clipboard
echo "secret_token" | xclip -selection clipboard

# 2. Выгрузить (вставить) данные из буфера обмена в поток
xclip -selection clipboard -o
```

#### Вариант Б: Ваша система работает на базе современного сервера Wayland

Используем нативный пакет `wl-clipboard`:

```bash
# 1. Скопировать текст в глобальный Clipboard Wayland
echo "secret_token" | wl-copy

# 2. Выгрузить (вставить) данные из буфера обмена
wl-paste
```

### Архитектурный стандарт безопасного копирования чувствительных данных

Когда вы копируете пароли или токены в буфер обмена из CLI-скриптов, процесс утилиты копирования по умолчанию продолжает удерживать данные в RAM. Чтобы защитить конфиденциальность, необходимо реализовывать **асинхронный сброс буфера строго по таймеру**:

```bash
# Пример для современного Wayland (wl-clipboard имеет встроенный флаг автоочистки):
# Копирует токен и автоматически бесследно сотрет его из памяти через 15 секунд
wl-copy --clear-after 15 "my_secure_password"

# Пример реализации для старого X11 (xclip) в фоновом режиме:
echo "my_secure_password" | xclip -selection clipboard
(sleep 15 && echo -n "" | xclip -selection clipboard) >/dev/null 2>&1 &
```
