### Использование текстовых файлов: данные как код

В Linux **всё — текст**:
- конфигурации (`/etc/*.conf`),
- системные базы (`/etc/passwd`, `/etc/group`),
- логи,
- исходный код,
- письма, заметки, списки задач.

Даже если сегодня всё «в облаке» — **локальная обработка текста** остаётся мощнейшим инструментом для анализа, автоматизации и отладки.

>  Главная идея:  
> **Структурированный текст + стандартные утилиты = готовое решение без программирования.**

---

#### Пример: массовая рассылка пользователям

**Задача**: отправить приветствие всем обычным пользователям (UID ≥ 1000).

**Решение по шагам**:

1. **Извлечь имена из `/etc/passwd`**  
```bash
awk -F: '$3 >= 1000 {print $1}' /etc/passwd
```
   > `-F:` задаёт разделитель полей (двоеточие)

2. **Сформировать приветствие**  
```bash
xargs -I@ echo "Hi there, @!"
```

3. **Сгенерировать команды отправки**  
```bash
xargs -I@ echo 'echo "Hi there, @!" | mail -s greetings @'
```

4. **Выполнить**  
   ```bash
   ... | bash
   ```

>  **Предупреждение**:  
> Такой подход **не масштабируется** и **небезопасен** при наличии спецсимволов в именах.  
> В production используйте циклы или скрипты:
> ```bash
> while IFS=: read -r user _ uid _; do
>   [[ $uid -ge 1000 ]] && echo "Hi $user" | mail -s "greetings" "$user"
> done < /etc/passwd
> ```

---

###  Методология работы с текстовыми данными

1. **Проанализируйте задачу**  
   Что нужно получить? Какие данные есть?

2. **Сохраните данные в структурированном виде**  
   Лучшие форматы:
   - CSV (разделитель — запятая/табуляция)
   - TSV (табуляция — надёжнее запятой)
   - одно значение на строку
   - фиксированная структура (как в `/etc/passwd`)

3. **Обработайте стандартными утилитами**  
   - `cut` — извлечение полей (просто, но жёстко)
   - `awk` — гибкая обработка (лучше для условий)
   - `grep` — фильтрация
   - `sort`, `uniq` — агрегация
   - `join` — объединение двух файлов по ключу

4. **Автоматизируйте (опционально)**  
   Вынесите в функцию, псевдоним или скрипт.

---

###  Практические примеры

#### 1. Найти всех пользователей с оболочкой `/bin/bash`
```bash
awk -F: '$7 == "/bin/bash" {print $1}' /etc/passwd
```

#### 2. Подсчитать домашние каталоги по дисковому использованию
```bash
awk -F: '$3 >= 1000 {print $6}' /etc/passwd | xargs -I{} du -sh {}
```

#### 3. Создать CSV из `/etc/passwd`
```bash
awk -F: 'BEGIN{OFS=","} {print $1,$3,$6}' /etc/passwd > users.csv
```

#### 4. Найти «висячие» домашние каталоги (без пользователя)
```bash
# Получить список UID из passwd
uids=$(awk -F: '$3>=1000{print $3}' /etc/passwd | sort -u)

# Сравнить с владельцами каталогов в /home
for dir in /home/*; do
  owner_uid=$(stat -c %u "$dir")
  if ! grep -q "^$owner_uid$" <<< "$uids"; then
    echo "Orphaned: $dir"
  fi
done
```

---

###  Ограничения и ловушки

| Проблема | Решение |
|--------|--------|
| Имена с пробелами/спецсимволами | Используйте `while read` вместо `for` |
| Большие файлы | Избегайте `cat file \| ...`, читайте напрямую: `awk '...' file` |
| Неоднозначные разделители | Предпочитайте TSV или JSON (с `jq`) |
| Отсутствие структуры | Сначала нормализуйте данные (через `sed`, `awk`) |

---

### Альтернативы для сложных данных

- **JSON** → `jq`  
  ```bash
  curl -s https://api.example.com/users | jq -r '.[].email'
  ```

- **YAML** → `yq` (не входит в базовую систему)

- **Базы данных** → `sqlite3` (лёгковесная SQL-база, работает с файлами)

Но помните:  
> **Если данные можно представить как строки — вы уже выиграли.**

---

### Итог

Текстовые файлы — не пережиток прошлого, а **основа Unix-философии**:
> «Пиши программы, которые делают одно и делают это хорошо. Пиши программы, чтобы они работали вместе. Пиши программы, которые обрабатывают текстовые потоки, потому что это универсальный интерфейс.»

Освоив обработку текста через `awk`, `cut`, `grep`, `sort` — вы получаете **универсальный инструмент для анализа любых структурированных данных**, без зависимости от языков программирования или GUI.


### Пример 1. Быстрый поиск файлов через текстовый индекс

**Проблема**:  
`find` медленный при поиске по огромному дереву каталогов (десятки тысяч файлов).

**Решение**:  
Создать **статический индекс** всех путей один раз → искать в нём через `grep`.

---

#### Пошаговая реализация

1. **Создать индекс**  
   ```bash
find "$HOME" -print > "$HOME/.ALLFILES"
   ```

2. **Искать через `grep`**  
   ```bash
   grep "animals.txt" "$HOME/.ALLFILES"
   ```


3. **Обернуть в скрипт `ff`**  
   ```bash
   #!/bin/bash
   grep "$@" "$HOME/.ALLFILES"
   ```
> Сохранить как `~/bin/ff`, сделать исполняемым: `chmod +x ~/bin/ff`

4. **Использовать**  
   ```bash
   ff animal                 # точное совпадение
   ff -i animal              # без учёта регистра
   ff '\.pdf$'               # только PDF-файлы (регулярка)
   ```

---

###  Улучшения и фишки

#### 1. **Автоматическое обновление индекса**
Добавьте в `crontab`:
```bash
# Обновлять индекс еженедельно
0 2 * * 0 find "$HOME" -type f -print > "$HOME/.ALLFILES"
```
> Только файлы (`-type f`), чтобы не дублировать каталоги.

#### 2. **Безопасность имён**
Если в путях есть символы перевода строки (крайне редко, но возможно), используйте нулевой разделитель:
```bash
find "$HOME" -print0 > "$HOME/.ALLFILES0"
# И в скрипте:
grep -z "$1" "$HOME/.ALLFILES0" | tr '\0' '\n'
```

#### 3. **Альтернатива: `fd` + кэш**
Современная утилита [`fd`](https://github.com/sharkdp/fd) быстрее `find` и поддерживает регулярки «из коробки». Но она всё равно сканирует ФС каждый раз. Индекс же — **мгновенный**.

#### 4. **Сравнение с `locate`**
- `locate` делает то же самое, но на уровне всей системы.
- Ваш индекс — **персонализированный**, работает без root, и вы контролируете формат.

---

### Ограничения

- Индекс **устаревает** — нужно обновлять после создания/удаления файлов.
- Не поддерживает **поиск по содержимому** — только по имени/пути.
- Не заменяет `find` для сложных условий (`-mtime`, `-size`, `-exec` и т.д.).

---

### Когда использовать?

✅ **Хорошо**:  
- Быстрый поиск по имени в личных данных  
- Скрипты, где важна скорость  
- Обучение: демонстрация силы текстовых данных

❌ **Плохо**:  
- Динамические среды (CI/CD, временные файлы)  
- Системный поиск (лучше `locate` или `mlocate`)

---

### Итог

Этот пример — идеальная иллюстрация Unix-философии:
> **«Создай простой текстовый файл → обработай его стандартными утилитами → получи мощный инструмент».**

Вы не зависите от внешних программ, не пишете сложного кода — просто комбинируете `find`, `grep` и скрипт.  
И это работает **быстро, надёжно и понятно**.


### Пример 2. Проверка срока действия доменов

**Задача**: отслеживать даты окончания регистрации нескольких доменов.

**Решение**:  
1. Хранить список доменов в текстовом файле.  
2. Извлекать дату через `whois`.  
3. Обрабатывать и анализировать результаты как структурированные данные.

---

#### Пошаговая реализация

1. **Создать файл `domains.txt`**  
   ```text
   example.com
   oreilly.com
   efficientlinux.com
   ```

2. **Извлечь дату окончания для одного домена**  
   ```bash
   whois example.com | grep 'Registry Expiry Date:' | awk '{print $4}'
   # → 2022-08-13T04:00:00Z
   ```

3. **Преобразовать в читаемый формат**  
   ```bash
   date --date="$(whois example.com | awk '/Registry Expiry Date:/ {print $4}')" '+%Y-%m-%d'
   # → 2022-08-13
   ```

4. **Скрипт `check-expiry`**  
   ```bash
   #!/bin/bash
   domain="$1"
   exp=$(whois "$domain" 2>/dev/null | awk '/Registry Expiry Date:/ {print $4}')
   if [[ -n "$exp" ]]; then
       date --date="$exp" '+%Y-%m-%d' 2>/dev/null || echo "invalid"
   else
       echo "unknown"
   fi
   ```

5. **Обработать все домены**  
   ```bash
   while read -r domain; do
       [[ -n "$domain" ]] && echo "$(./check-expiry "$domain")	$domain"
       sleep 5  # уважение к whois-серверам
   done < domains.txt > expiry.txt
   ```

> ⚠️ **Важно**:  
> Многие регистраторы **ограничивают частоту запросов**. Без `sleep` вы можете получить бан или ошибку.

---

### 💡 Улучшения и фишки

#### 1. **Безопасность и обработка ошибок**
- Добавьте `2>/dev/null`, чтобы подавить ошибки `whois` (например, при недоступности домена).
- Проверяйте, что дата извлечена: `if [[ -n "$exp" ]]`.

#### 2. **Сортировка по дате окончания**
```bash
sort -k1,1 expiry.txt
```
→ Самые «горячие» домены — сверху.

#### 3. **Найти просроченные или близкие к окончанию**
```bash
# Все, что истекает сегодня или раньше
awk -v today="$(date +%Y-%m-%d)" '$1 <= today' expiry.txt

# Истекает в ближайшие 14 дней
awk -v today="$(date -d '+14 days' +%Y-%m-%d)" '$1 <= today' expiry.txt
```

#### 4. **Автоматизация через cron**
Добавьте в `crontab`:
```bash
0 9 * * 1 /path/to/check-expiry-all.sh | mail -s "Domain Expiry Report" admin@example.com
```
→ Отчёт каждое утро понедельника.

#### 5. **Альтернатива: `jq` + API (для массовой проверки)**
Если у вас десятки доменов — лучше использовать API регистратора (например, Cloudflare, GoDaddy) вместо `whois`. Но для 5–10 доменов `whois` — идеален.

---

### ⚠️ Ограничения `whois`

- Формат вывода **зависит от регистратора**. Некоторые не показывают `Registry Expiry Date`.
- Для `.ru`, `.de`, `.uk` и других TLD — может потребоваться другой шаблон (`grep 'Expiry Date'`, `Expiration Date:` и т.д.).
- Некоторые домены скрывают данные (privacy protection).

> ✅ **Совет**:  
> Протестируйте `whois your-domain.tld` вручную, чтобы уточнить формат перед автоматизацией.

---

### Итог

Этот пример демонстрирует мощь подхода:
> **Текстовый файл → стандартные утилиты → автоматизированный отчёт**

Вы не пишете сложный код — просто комбинируете:
- `whois` — источник данных,
- `awk`/`grep` — извлечение,
- `date` — нормализация,
- `sort`/`awk` — анализ.

И получаете **готовую систему мониторинга** за 10 строк скрипта.

> 🔔 Главное правило:  
> **Уважайте чужие серверы. Всегда добавляйте `sleep` при массовых запросах.**



### Пример 3. База данных телефонных кодов (area codes)

 [Areacodes](https://resources.oreilly.com/examples/0636920601098/-/blob/master/ch09/build_area_code_database/areacodes.txt?ref_type=heads)

**Задача**:  
Хранить и быстро искать информацию о телефонных кодах США: код → штат → города.

**Решение**:  
Использовать **структурированный текстовый файл** с табуляцией в качестве разделителя:
```
201	NJ	"Hackensack, Jersey City"
202	DC	Washington
...
```

>  Почему **табуляция**, а не запятая?  
> Потому что в названиях городов есть запятые (`Boston, Cambridge`), а табуляция почти никогда не встречается в таких данных.

---

#### Основные операции

##### 1. Поиск по штату
```bash
grep -w "CA" areacodes.txt
```
> `-w` гарантирует, что найдётся только целое слово `CA`, а не `CAL` или `SCA`.

##### 2. Поиск по коду
```bash
grep -w "202" areacodes.txt
```

##### 3. Подсчёт количества кодов на штат
```bash
cut -f2 areacodes.txt | sort | uniq -c | sort -nr | head -5
```
> Выведет топ-5 штатов по числу кодов.

##### 4. Экспорт в CSV (для Excel, LibreOffice)
```bash
awk -F'\t' '{printf "%s,%s,\"%s\"\n", $1, $2, $3}' areacodes.txt > areacodes.csv
```
> Города в кавычках — запятые внутри не ломают структуру.

##### 5. Собрать все коды по штату
```bash
awk '{codes[$2] = codes[$2] " " $1} END {for (st in codes) print st ":" codes[st]}' areacodes.txt | sort
```
> Результат: `CA: 209 213 310 323 ...`

---

###  Улучшения и фишки

#### 1. **Безопасный формат файла**
Храните данные в **TSV** (tab-separated values), а не в «выровненных колонках» — это надёжнее для обработки.

Пример правильного формата (`areacodes.tsv`):
```tsv
201	NJ	Hackensack, Jersey City
202	DC	Washington
203	CT	New Haven, Stamford
```

#### 2. **Универсальный скрипт поиска**
```bash
#!/bin/bash
# ~/bin/areacode
if [[ -n "$1" ]]; then
    grep -iE "(^|[[:space:]])$1([[:space:]]|$)" areacodes.tsv
else
    echo "Usage: areacode <code|state|city>"
fi
```
> Ищет **точное совпадение** любого поля, без ложных срабатываний.

#### 3. **Поиск по нескольким критериям**
Найти все коды в Калифорнии, связанные с Лос-Анджелесом:
```bash
awk -F'\t' '$2=="CA" && $3 ~ /Los Angeles/' areacodes.tsv
```

#### 4. **Проверка дубликатов**
```bash
sort areacodes.tsv | uniq -d
```
> Найдёт повторяющиеся строки.

#### 5. **Генерация справочника для терминала**
Создайте функцию в `.bashrc`:
```bash
ac() {
    awk -F'\t' -v q="$1" '$1==q || $2==q || $3~q' ~/data/areacodes.tsv
}
```
> Теперь можно: `ac 213` или `ac TX`.

---

###  Ограничения и ловушки

- **Регулярные выражения в `grep`** могут давать ложные совпадения → используйте `-w` или `awk` с точным сравнением.
- **Регистр**: `ca` ≠ `CA` → добавьте `-i` или нормализуйте данные.
- **Многострочные значения** (редко, но бывает) → TSV не поддерживает, лучше использовать JSON.

---

### Альтернативы

- Для сложных запросов — загрузите данные в SQLite:
  ```sql
  CREATE TABLE codes (area INT, state TEXT, cities TEXT);
  .import --csv areacodes.csv codes
  SELECT * FROM codes WHERE state = 'CA';
  ```
- Для веб-интерфейса — экспортируйте в JSON и используйте простой Python-скрипт.

---

### Итог

Этот пример показывает, как **простой текстовый файл** превращается в:
- базу данных,
- инструмент поиска,
- источник для отчётов.

Вы не используете СУБД, не пишете веб-приложение — просто применяете:
- `grep` — фильтрация,
- `awk` — преобразование,
- `sort`/`uniq` — агрегация.

> ✅ **Правило**:  
> Если данные можно представить в виде строк — вы уже на 80% решили задачу.  
> Остальное — дело техники.



### Пример 4. Создание простого менеджера паролей (`pman`)

> **Важно**: это **учебный пример**. Не используй его для хранения реальных паролей без понимания рисков.

---

#### Шаг 1. Создание файла `vault`

Файл `vault` — это **простой текстовый файл** в формате TSV (tab-separated values).  
Каждая запись занимает **одну строку** и состоит из **четырёх полей**, разделённых **табуляцией**:

```
<username>	<password>	<tag>	<notes>
```

>  - логин  
> - пароль  
> - короткий ключ (например, `google`, `bank`)  
> - примечания

Бывает,что заместо **4**-х полей **3** поля, гле в **3**-м поле —  **ключ + примечания**.

##### Пример содержимого:
```text
sally	fake1	google google.com account
ssmith	fake2	dropbox dropbox.com account for work
s999	fake3	bank Bank of America account, bankofamerica.com
```

>  Обрати внимание: между `google` и `google.com account` — **пробел**, а не табуляция.  
> Это означает, что **весь остаток строки — примечание**, а **первое слово в третьем поле — ключ**.

---

#### Шаг 2. Безопасное создание и настройка прав

```bash
# 1. Создать пустой файл
touch ~/etc/vault

# 2. Установить строгие права: только владелец может читать/писать
chmod 600 ~/etc/vault

# 3. Отредактировать (лучше через vim/emacs, не через echo!)
vim ~/etc/vault
```

> Почему `600`?  
> - `6` = `rw-` для владельца  
> - `0` = `---` для группы и остальных  
> → Никто кроме тебя не  сможет прочитать файл.

> **Никогда не используй `echo "..." > vault`** — это легко оставить в истории терминала!

---

#### Шаг 3. Базовый скрипт `pman` (версия 1)

Сохрани в `~/bin/pman`:
```bash
#!/bin/bash
grep "$1" "$HOME/etc/vault"
```

Сделай исполняемым:
```bash
chmod 700 ~/bin/pman
```

>`700` — только владелец может запускать.

Теперь можно искать:
```bash
pman google
# → найдёт любую строку, содержащую "google"
```

---

#### Шаг 4. Улучшение: проверка аргументов и ошибок (версия 2)

```bash
#!/bin/bash
PROGRAM=$(basename "$0")
DATABASE="$HOME/etc/vault"

if [ $# -ne 1 ]; then
    >&2 echo "$PROGRAM: look up passwords by string"
    >&2 echo "Usage: $PROGRAM <search-term>"
    exit 1
fi

searchstring="$1"
grep "$searchstring" "$DATABASE"
if [ $? -ne 0 ]; then
    >&2 echo "$PROGRAM: no matches for '$searchstring'"
    exit 1
fi
```

→ Теперь скрипт не падает молча и даёт понятные сообщения.

---

#### Шаг 5. Улучшение: приоритет поиску по **ключу** (версия 3)

Измени формат `vault`, чтобы **третье поле начиналось с уникального ключа**:

```text
sally	fake1	google	google.com account
ssmith	fake2	dropbox	dropbox.com for work
```

Теперь скрипт сначала ищет **точное совпадение по ключу**:
```bash
match=$(awk -v key="$searchstring" '$3 == key' "$DATABASE")
```

Если не найдено — ищет по всему файлу.

---

#### Шаг 6. Шифрование через GPG

1. **Создай GPG-ключ** (если нет):
   ```bash
   gpg --quick-generate-key your@email.com
   ```

2. **Зашифруй файл**:
   ```bash
   cd ~/etc
   gpg -e -r your@email.com vault
   # → создаёт vault.gpg
   ```

3. **Проверь расшифровку**:
   ```bash
   gpg -d vault.gpg
   ```

4. **Удали исходный файл** (после проверки!):
   ```bash
   shred -u vault  # безопасное удаление
   ```

#### Шаг 7. Финальная версия `pman` (версия 4)

```bash
#!/bin/bash
PROGRAM=$(basename "$0")
DATABASE="$HOME/etc/vault.gpg"

if [ $# -ne 1 ]; then
    >&2 echo "$PROGRAM: look up passwords"
    >&2 echo "Usage: $PROGRAM <search-term>"
    exit 1
fi

searchstring="$1"

# Расшифровываем и фильтруем комментарии (#)
decrypted=$(gpg -d -q "$DATABASE" 2>/dev/null | grep -v '^#')

# Ищем по ключу (3-е поле)
match=$(echo "$decrypted" | awk -v key="$searchstring" '$3 == key')

# Если не найдено — ищем по всему тексту
if [ -z "$match" ]; then
    match=$(echo "$decrypted" | awk "/$searchstring/")
fi

if [ -z "$match" ]; then
    >&2 echo "$PROGRAM: no matches for '$searchstring'"
    exit 1
fi

echo "$match"
```

#### Шаг 8. Дополнительные улучшения

##### Поддержка комментариев
**Добавь** в `vault.gpg` строки вида:
```text
# Личные аккаунты
sally	fake1	google	google.com
```

>Скрипт автоматически их игнорирует благодаря `grep -v '^#'`.

##### Безопасный вывод (рекомендация)
Вместо `echo "$password"` — копируй в буфер:
```bash
echo "$password" | xclip -selection clipboard
echo "Пароль скопирован. Очистка через 15 сек..."
(sleep 15; echo -n | xclip -selection clipboard) &
```

##### Прямое редактирование
**Настрой** `vim` или `emacs` для работы с `.gpg`-файлами используй:
```bash
alias pwedit='vim ~/.etc/vault.gpg'
```

Не забудь:
```bash
export GPG_TTY=$(tty)
```
> — иначе GPG не сможет запросить пароль в фоне.
