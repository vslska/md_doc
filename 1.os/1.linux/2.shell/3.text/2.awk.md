# Язык обработки текстовых потоков awk: Архитектура, ассоциативные массивы и Highload-агрегация данных

**`awk`** — это полнофункциональный Тьюринг-полный язык программирования, ориентированный на построчную обработку данных. В отличие от `sed` или `grep`, он оперирует текстом не просто как набором символов, а как структурированной базой данных, состоящей из **записей (строк)** и **полей (столбцов)**.

---

## 1. Конвейерная архитектура выполнения awk

Программа `awk` работает по декларативной модели **«паттерн -> действие»**. Интерпретатор автоматически итерирует по входному потоку, избавляя инженера от написания явных циклов чтения файлов.

```
[Входной поток] ──► ( Чтение строки ) ──► [Разбиение по FS] ──► ( Инициализация $0..$NF, NR, FNR)
                                                                             │
[Выходной поток] ◄── ( Сброс в stdout ) ◄── [ Выполнение {} ] ◄── ( Совпадение паттерна? )
```

### Алгоритм обработки каждой записи ядра:

1. Из потока считывается строка. По умолчанию разделителем записей (`RS` — Record Separator) выступает символ `\n`.
2. Строка мгновенно разбивается на поля по разделителю `FS` (Field Separator, по умолчанию — любой пробельный символ или таб).
3. Выделенным участкам памяти ядра присваиваются системные переменные:
    - `$0` — исходная строка целиком.
    - `$1, $2, ... $NF` — значения конкретных столбцов (нумерация строго с **1**).
    - `NF` (Number of Fields) — итоговое количество столбцов в текущей строке.
    - `NR` (Number of Records) — глобальный порядковый номер строки во всем потоке.
    - `FNR` (File Number of Records) — порядковый номер строки строго внутри _текущего_ файла (сбрасывается в 1 при переходе к следующему файлу).
4. Интерпретатор сверяет строку с каждым правилом сценария. Если условие (паттерн) истинно — выполняется блок кода в фигурных скобках `{ действие }`.

### ⚠️ Критическая ловушка динамической сборки `$0`

Если внутри блока действий изменить значение любого поля (например, `$2 = "MODIFIED"`), ядро Linux автоматически **намертво пересоберет строку `$0` целиком**. При этом старые исходные разделители (пробелы или табы) будут безвозвратно стерты, а поля склеятся через символ, указанный в переменной `OFS` (Output Field Separator, по умолчанию — один пробел).

## 2.Системные переменные: Справочник инженера

Переменные управления вводом/выводом

|Переменная|Назначение|Описание физики процесса|Основные настройки|
|---|---|---|---|
|**`FS`**|Разделитель полей входа|Определяет символ или регулярное выражение, по которому строка бьется на столбцы `$1, $2...`.|`FS=":"` или `FS="[ \t]+"` (любое число пробелов)|
|**`OFS`**|Разделитель полей вывода|Символ, который вставляется между аргументами при выводе через запятую: `print $1, $2`.|`OFS="\t"` (вывод в виде красивой таблицы TSV)|
|**`RS`**|Разделитель записей входа|Символ окончания "строки". По умолчанию `\n`. Если обнулить (`RS=""`), `awk` перейдет в **параграфный режим**: записью будет считаться блок текста до первой полностью пустой строки.|`RS=""` (удобно для парсинга многострочных конфигов)|
|**`ORS`**|Разделитель записей вывода|Символ, который `awk` автоматически дописывает в самый конец после выполнения команды `print`.|`ORS="\r\n"` (конвертация переводов строк в формат Windows)|

### ⚠️ Ловушка типов данных (String vs Float/Int)

В `awk` нет явного декларирования типов — переменная является строкой или числом в зависимости от контекста. Если утилита `df` или `ps` возвращает поле с текстом (например, `85%` или `4.5G`), обычное математическое сравнение `if ($5 > 80)` отработает как **посимвольное строковое сравнение**. Строка `"9"` окажется больше, чем строка `"85"`, и автоматизация выдаст ложные срабатывания.

- **Решение (Принудительный кастинг):** Любое математическое действие над переменной заставляет ядро `awk` мгновенно преобразовать её тип в число (числовой контекст). Самый безопасный способ — прибавление нуля `+ 0`. Движок отсечет все нечисловые символы с конца строки и оставит чистый Integer или Float.

#### Боевой пример (Числовое сравнение и смена разделителей):

Парсим вывод `df -h`, отсекаем знак `%` и находим диски, утилизированные более чем на 85%, форматируя вывод в красивую таблицу через `OFS`:

```bash
df -h | awk '
  BEGIN { 
    # Задаем разделитель вывода — Табуляция
    OFS="\t" 
  } 
  NR > 1 { 
    # В $5 лежит например "87%". Операция + 0 превратит это в чистое число 87.
    # Если бы мы написали $5 > 85, сравнение пошло бы по строкам, и логика бы сломалась.
    if (($5 + 0) >= 85) {
      print "WARN:", $1, "заполнен на", $5, "точка монтирования:", $6
    }
  }
'
```

## 3. Движок регулярных выражений, операторы и управляющие блоки

`awk` под капотом использует движок расширенных регулярных выражений (ERE).

- **`~` (Соответствует) / `!~` (Не соответствует):** Операторы точечного применения регулярного выражения к конкретному столбцу, а не ко всей строке.
- **`BEGIN { ... }`**: Блок инициализации. Выполняется строго **до** того, как `awk` откроет первый файл и начнет читать строки из входного потока. Используется для жесткого задания конфигурационных переменных (`FS`, `OFS`, `RS`) и печати заголовков отчетов.
- **`END { ... }`**: Блок финализации. Выполняется строго **после** того, как весь входной поток данных был полностью вычитан и обработан. Используется для вывода агрегированных данных, средних значений и сумм из хэш-таблиц.
- **`next`**: Команда прерывания текущего цикла. Заставляет `awk` мгновенно бросить обработку оставшихся правил для _текущей_ строки, пропустить её и сразу перейти к чтению следующей строки из файла.

### Боевой пример (Парсинг `/etc/passwd` с фильтрацией комментариев и системных учетных записей):

```bash
awk '
  BEGIN { 
    FS=":"
    print "=== СПИСОК РЕАЛЬНЫХ ПОЛЬЗОВАТЕЛЕЙ СИСТЕМЫ ===" 
  }
  
  # 1. Если строка начинается с решетки (#) или полностью пустая — пропускаем её
  /^[[:space:]]*#/ || /^$/ { next }
  
  # 2. Оператор !~ : Проверяем, что командная оболочка пользователя ($7) НЕ является nologin
  # 3. Реляционный оператор: Проверяем, что UID ($3) больше или равен 1000 (стандарт для пользователей)
  $7 !~ /nologin|false/ && ($3 + 0) >= 1000 {
    printf "Пользователь: %-15s | UID: %-5d | Shell: %s\n", $1, $3, $7
  }
  
  END { 
    print "=== АНАЛИЗ ЗАВЕРШЕН. Всего строк обработано:", NR 
  }
' /etc/passwd
```

## 4. Высоконагруженная агрегация: Ассоциативные массивы

Массивы в `awk` — это хэш-таблицы (ключ -> значение).

- **Особенность:** Итерация `for (key in array)` не гарантирует порядок. Используйте `| sort` для сортировки.

**Пример:** Подсчет уникальных статус-кодов Nginx:

```bash
awk '{ status[$9]++ } END { for (i in status) print i, status[i] }' access.log
```

## 5. Встроенные функции: Строки, Время

- **`match(s, r)`**: Ищет регулярное выражение `r` внутри строки `s`. Возвращает позицию первого совпадения, а также автоматически инициализирует две системные переменные ядра: `RSTART` (индекс символа, где началось совпадение) и `RLENGTH` (чистая длина совпавшего куска текста). Если совпадений нет, возвращает `0`.
- **`substr(s, i, n)`**: Вырезает и возвращает подстроку из строки `s`, начиная строго с индекса `i` (нумерация символов с 1) длиной в `n` символов. Если `n` упущен — режет до самого конца строки.
- **`systime()`**: Возвращает текущее системное время хоста в формате Unix Epoch (количество секунд с 1 января 1970 года).
- **`strftime(format, timestamp)`**: Конвертирует сырой Unix Timestamp в человекочитаемую строку по заданному ISO-шаблону.

_(Напоминание: функции `systime` и `strftime` являются расширением стандарта GNU awk и требуют утилиты `gawk`)_.

Боевой пример (Сложный парсинг лога: извлечение подстроки по динамическим границам и генерация таймстампов):

Допустим, у нас есть лог безопасности, где внутри строки сидит динамический токен сессии неопределенной длины, завернутый в квадратные скобки: `2026-07-29 INFO [session_token_a1b2c3] Auth success`. Нам нужно вытащить этот токен и добавить к строке текущее время обработки.

```bash
echo "2026-07-29 INFO [session_token_a1b2c3] Auth success" | awk '
  {
    # 1. Ищем регуляркой текст внутри квадратных скобок.
    # [^]]+ означает: любой символ, кроме закрывающей скобки, один или более раз.
    if (match($0, /\[[^]]+\]/)) {
      
      # RSTART указывает на открывающую скобку "[". Нам нужен текст ПОСЛЕ неё -> RSTART + 1
      # RLENGTH включает обе скобки. Чтобы забрать только текст внутри, вычитаем 2 -> RLENGTH - 2
      token = substr($0, RSTART + 1, RLENGTH - 2)
      
      # 2. Генерируем текущее время обработки на базе системных часов хоста
      current_time = strftime("[%Y-%m-%d %H:%M:%S]", systime())
      
      printf "%s Экстракт токена: %s | Статус: %s\n", current_time, token, $NF
    }
  }
'
# Вывод: [2026-07-29 18:05:00] Экстракт токена: session_token_a1b2c3 | Статус: success
```

## 6. Прикладные сценарии DevOps / SRE: Практические кейсы

### Кейс 1. Парсинг Nginx access.log: Топ-10 IP-адресов по объёму трафика

Когда сервер начинает захлёбываться от запросов, нужно мгновенно вычислить, кто именно выкачивает трафик. Стандартный комбинированный лог Nginx содержит IP в 1-м поле, а размер ответа в байтах — в 10-м поле.

```bash
awk '
  { 
    # $1 - IP, $10 - размер ответа в байтах
    # Если размер ответа не число (например, "-"), прибавляем 0 для безопасного приведения типов
    traffic[$1] += ($10 + 0) 
  } 
  END { 
    for (ip in traffic) {
      # Переводим байты в Мегабайты для читаемости
      printf "%-15s\t%.2f MB\n", ip, traffic[ip] / 1024 / 1024
    } 
  }
' /var/log/nginx/access.log | sort -k2 -nr | head -n 10
```



### Кейс 2. Парсинг Nginx access.log: Подсчет Latency (Upstream Response Time)

В кастомных логах Nginx часто логируют время ответа бэкенда (Upstream Response Time). Допустим, оно пишется в последнем поле ($NF). Нам нужно найти среднее время ответа (Average Latency) и общее количество запросов, которые обрабатывались дольше 500 мс (0.5 сек).

```bash
awk '
  BEGIN { 
    print "=== АНАЛИЗ ЗАДЕРЖЕК БЭКЕНДА ===" 
  }
  {
    latency = $NF + 0 # Принудительное приведение последнего поля к float
    sum += latency
    count++
    
    if (latency > 0.5) {
      slow_requests++
    }
  }
  END {
    if (count > 0) {
      printf "Всего запросов    : %d\n", count
      printf "Средний Latency   : %.3f сек\n", sum / count
      printf "Медленные (>0.5с) : %d (%.2f%%)\n", slow_requests, (slow_requests / count) * 100
    }
  }
' /var/log/nginx/access.log
```


### Кейс 3. Точечный парсинг JSON-логов (без утилиты `jq`)

Иногда на минималистичных контейнерах (Distroless/Scratch) нет утилиты `jq`, а приложение пишет логи в JSON. Если структура плоская, `awk` может вычленить данные с помощью изменения разделителя полей на регулярное выражение.

Допустим, строка лога выглядит так: `{"time":"2026-07-29", "level":"ERROR", "msg":"Database timeout", "code":504}`

```bash
# Задаем в качестве разделителя регулярку: двоеточие, кавычки, запятые или фигурные скобки
awk -F'[:",{}]+' '
  /ERROR/ {
    # При таком FS строка бьется на понятные токены:
    # $2="time", $3="2026-07-29", $4="level", $5="ERROR", $6="msg", $7="Database timeout"
    printf "[%s] Критический сбой: %s\n", $3, $7
  }
' /var/log/app/json.log
```


### Кейс 4. Ротация и фильтрация логов по диапазону времени (gawk)

Задача: Извлечь из огромного системного лога (`/var/log/syslog`) только те строки, которые были записаны строго между 14:00 и 14:15 текущего дня. Формат лога: `2026-07-29T14:05:01+03:00 hostname service: message`.

```bash
# Используем ERE регулярку для сопоставления с ISO таймстампом в начале строки
awk '
  $1 ~ /^2026-07-29T14:(0[0-9]|1[0-5]):/ { 
    print $0 
  }
' /var/log/syslog
```



### Кейс 5. Слияние двух файлов по общему ключу (Хэш-джоин в памяти)

Это классический шедевр `awk`, который заменяет тяжелые SQL-скрипты.  
У нас есть два файла:

1. `users.txt` (Формат `ID:Имя`): `101:sally`, `102:ssmith`
2. `logins.txt` (Формат `ID:IP_Адрес`): `101:192.168.1.50`, `102:10.0.0.12`  
    Нам нужно объединить их по `ID` и вывести `Имя -> IP`.

```bash
awk '
  BEGIN { FS=":" }
  
  # Шаг 1. Конструкция NR == FNR истинна ТОЛЬКО во время чтения ПЕРВОГО файла (users.txt)
  NR == FNR {
    # Запоминаем в хэш-таблицу: ключ — ID ($1), значение — Имя ($2)
    names[$1] = $2
    next # Мгновенно уходим на следующую строку, не выполняя код ниже
  }
  
  # Шаг 2. Этот код выполняется строго для ВТОРОГО файла (logins.txt)
  {
    # Проверяем, есть ли ID ($1 из logins.txt) в нашей базе имен
    if ($1 in names) {
      printf "Пользователь %s зашел с IP %s\n", names[$1], $2
    }
  }
' users.txt logins.txt
```

_Физика процесса:_ Память сервера утилизируется только под хэш-таблицу первого файла. Второй файл читается потоком (стримом), что позволяет обрабатывать файлы размером в сотни гигабайт без риска уйти в OOM.

## 7. Чек-лист отладки

- **Проблемы с разделителями:** Используйте `BEGIN { OFS="\t" }`.
- **Ошибки функций времени:** Проверьте `awk --version` — необходим `gawk` (GNU awk), так как `mawk` (по умолчанию в Debian/Ubuntu) их не поддерживает.
