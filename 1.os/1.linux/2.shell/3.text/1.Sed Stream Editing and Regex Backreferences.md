# Потоковый текстовый редактор sed: Архитектура, движки регулярных выражений и обратные ссылки

**`sed` (Stream Editor)** — это неинтерактивный потоковый текстовый редактор. Он обрабатывает входящий поток данных (файлы или стандартный ввод `stdin`) построчно, применяет к каждой строке правила из заданного сценария и по умолчанию выводит результат в `stdout`.

---

## 1. Архитектура выполнения и системные флаги

Цикл обработки `sed` устроен следующим образом: утилита считывает строку из входного потока в энергозависимую область памяти ядра, называемую **Pattern Space (Шаблонное пространство)**, последовательно применяет к ней все инструкции сценария, сбрасывает содержимое Pattern Space в `stdout` и очищает его для следующей строки.

```text
[Входной поток] ──► ( Чтение строки ) ──► [ Pattern Space (RAM) ] ──► ( Выполнение скрипта )
                                                    │
[Выходной поток] ◄── ( Сброс буфера ) ◄─────────────┴─── ( Применение замен )
```


### Системные флаги управления выполнением

- **`-e сценарий`**: Позволяет последовательно выполнять несколько независимых сценариев над одним и один тем же потоком данных в рамках одного вызова.

```bash
# Трансформации применяются к потоку шаг за шагом
echo "initial data" | sed -e 's/initial/alpha/' -e 's/data/payload/'
```

- **`-f файл-сценария`**: Предписывает `sed` загрузить многострочный файл со сценариями и выполнить все указанные в нём правила сверху вниз.

```bash
sed -f clean_logs.sed application.log    
```

- **`-n` (Подавление вывода)**: Отключает автоматический сброс содержимого Pattern Space в `stdout` в конце каждого цикла. Используется в паре с командой `p` (print), превращая `sed` в точечный фильтр (аналог `grep`).

## 2. Параметры подстановки и глобальные флаги

Базовая структура команды замены (substitution) выглядит так:

```bash
s/регулярное_выражение/строка_замены/флаги
```

### Агностицизм разделителей

Символ косой черты (`/`) не зашит в архитектуру утилиты намертво. Любой символ, указанный сразу после оператора `s`, автоматически становится разделителем для этой конкретной команды. Это избавляет от необходимости экранировать пути к файлам и директориям (проблема «синдрома обратного слэша»):

```bash
# Использование альтернативного разделителя @ вместо / избавляет от экранирования путей
echo "/opt/nginx/bin/" | sed 's@/opt/nginx/@/usr/local/@'
```

Флаги модификации поведения (Флаги запуска)

- **`g` (Global)**: Принуждает `sed` заменить _все_ вхождения шаблона в строке. Без флага `g` будет заменено только самое первое вхождение в текущей строке.
- **`i` (Case-Insensitive)**: Переводит движок регулярных выражений в регистронезависимый режим.
- **`d` (Delete)**: Полностью очищает текущее Pattern Space и мгновенно переходит к следующей строке, прерывая выполнение скрипта для текущей.

```bash
# Удалить конкретную строку по её абсолютному номеру (индексу)
seq 1 5 | sed '3d'
 
# Удалить строки, соответствующие паттерну (например, вырезать комментарии)
grep -v '^$' config.file | sed '/^#/d'
```

## 3. Движки регулярных выражений: BRE против ERE

Утилита `sed` поддерживает два типа движков регулярных выражений. Понимание разницы между ними критично, так как синтаксис экранирования спецсимволов в них диаметрально противоположен.

```bash
# Режим базовых регулярных выражений (BRE) — стандартный режим по умолчанию
echo "123-456" | sed 's/\([0-9]\{3\}\)-\([0-9]\{3\}\)/\1\/\2/'

# Режим расширенных регулярных выражений (ERE) — включается флагом -E (или -r)
echo "123-456" | sed -E 's/([0-9]{3})-([0-9]{3})/\1\/\2/'
```

Сравнение правил синтаксиса

|Компонент|Базовые регулярные выражения (BRE)|Расширенные регулярные выражения (ERE / `-E`)|
|---|---|---|
|**Группы захвата**|Обязательно экранирование: `\( ... \)`|Чистый синтаксис: `( ... )`|
|**Квантификаторы (`+`, `?`)**|Воспринимаются как обычный текст, если не экранированы|Работают как активные операторы регулярных выражений|
|**Интервалы (`{min,max}`)**|Обязательно экранирование: `\{3\}`|Чистый синтаксис: `{3}`|
|**Читаемость**|Высокая зашумленность слэшами, частые ошибки парсинга|Чистый, современный стандарт регулярных выражений|

## 4. Группы захвата и Обратные ссылки (Backreferences)

**Обратные ссылки (Backreferences)** позволяют движку регулярных выражений сохранять совпавшие подстроки в специальные индексированные регистры памяти ядра (от `\1` до `\9`) внутри Pattern Space. Эти сохраненные фрагменты текста можно динамически вставлять, дублировать или менять местами в строке замены.

### Реальный кейс: Массовая нормализация имен файлов

**Задача:** Трансформировать массив старых бэкапов, имеющих структуру `[имя].[расширение].[индекс]` (например, `backup.tar.01`), в современный стандарт `[имя][индекс].[расширение]` (`backup01.tar`).

#### Проектирование шаблона ERE

Использование флага `-E` позволяет составить чистую схему групп без забивания кода слэшами:
```
Шаблон:   ^([[:alnum:]]+)\.([[:alpha:]]{3,4})\.([0-9]+)$
          └── Группа 1 ──┘└───  Группа 2 --──┘└─ Группа 3 ┘
```

1. **Группа 1 (`([[:alnum:]]+)`)**: Захватывает базовое имя файла (буквы и цифры), сохраняя его в регистр `\1`.
2. **Group 2 (`([[:alpha:]]{3,4})`)**: Захватывает расширение файла длиной от 3 до 4 символов, сохраняя его в регистр `\2`.
3. **Group 3 (`([0-9]+)`)**: Захватывает числовой индекс, сохраняя его в регистр `\3`.

#### Сборка пайплайна генерации команд для Shell

Сам по себе `sed` не умеет переименовывать файлы на диске — он лишь модифицирует текст. Для боевого выполнения мы генерируем готовый массив системных команд `mv` и скармливаем его на вход интерпретатору (`| sh`):

```bash
# Безопасный холостой прогон (Dry-run), выводящий готовые команды на экран для проверки
ls *.tar.* | sed -E 's/^([[:alnum:]]+)\.([[:alpha:]]{3,4})\.([0-9]+)$/mv -n & \1\3.\2/'

# Боевой запуск (раскомментировать после валидации вывода)
# ls *.tar.* | sed -E 's/^([[:alnum:]]+)\.([[:alpha:]]{3,4})\.([0-9]+)$/mv -n & \1\3.\2/' | sh
```

- Спецсимвол `&` в строке замены — это встроенная переменная `sed`, которая подставляет **всю исходную совпавшую строку целиком** (используется как исходный аргумент для команды `mv`).

## 5. Продакшен-стандарты редактирования файлов по месту (`-i`)

При изменении конфигурационных файлов напрямую на диске с помощью флага `sed -i` необходимо учитывать особенности работы подсистемы VFS ядра. Утилита `sed -i` не правит сектора файла напрямую — она создает скрытый временный файл, заполняет его измененным потоком, а затем атомарно удаляет оригинал и переименовывает временный файл на его место.

```bash
# ❌ Опасный вариант инлайн-модификации (категорически запрещен на проде!)
sed -i 's/DEBUG=true/DEBUG=false/' /etc/app/config.conf

# ✅ Стандарт продакшена: Сохраняет бэкап и принудительно разрешает ссылки
sed -i.bak --follow-symlinks 's/DEBUG=true/DEBUG=false/' /etc/app/config.conf
```


### Чек-лист безопасности для флага `-i`:

1. **Всегда указывайте суффикс бэкапа:** Конструкция `-i.bak` заставляет `sed` сначала создать физическую резервную копию оригинального конфига на диске перед его модификацией.
2. **Явно прописывайте `--follow-symlinks`:** Без этого флага `sed -i` при переименовании файла **намертво разорвет символическую ссылку (symlink)**, превратив её в обычный плоский файл. Это часто ломает системные зависимости и библиотеки.
3. **Ловушка Docker-контейнеров (Bind Mounts):** Механизм замены файла утилитой `sed -i` приводит к изменению индекса `inode` файла. Если этот файл был примонтирован внутрь запущенного Docker-контейнера через `bind mount`, Docker мгновенно потеряет связь с файлом (изменения перестанут долетать до контейнера). Для конфигов внутри контейнеров используйте перенаправление потоков через `cat/truncate` или управляйте настройками через переменные окружения.
