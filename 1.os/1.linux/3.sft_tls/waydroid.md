## Архитектура и системные требования

**Waydroid** представляет собой контейнеризированную среду исполнения для операционной системы Android, функционирующую на базе пространств имен ядра Linux (namespaces) и LXC. В отличие от традиционных эмуляторов (QEMU, VirtualBox), Waydroid выполняет код Android непосредственно на оборудовании хост-системы, что обеспечивает производительность, близкую к нативной.

Обязательные компоненты:

- **Графический сервер:** Wayland (в среде X11 запуск возможен только через вложенные композиторы, например, `Weston`).
- **Модули ядра:** `ashmem` и `binder`. В стандартном ядре Arch Linux (`linux`) данные модули отсутствуют. Требуется использование ядер `linux-zen` или `linux-cachyos`, где поддержка Android-драйверов включена по умолчанию.

## Инициализация и развертывание системы

### Выбор и загрузка образа

Инициализация выполняется от имени суперпользователя. Доступно два типа образов: `VANILLA` (чистый Android) и `GAPPS` (с сервисами Google Play). Для синхронизации учетных записей требуется второй вариант.

```sh
sudo waydroid init -s GAPPS
```

### Управление системной службой

Взаимодействие с контейнером осуществляется через демон `systemd`.

- Активация автозапуска и немедленный старт службы:

```sh
sudo systemctl enable --now waydroid-container.service
```

- Проверка текущего статуса компонента:

```sh
sudo systemctl status waydroid-container.service
```

## Управление сессией и графическим интерфейсом

Запуск графической оболочки и сессии пользователя выполняется от имени текущего пользователя **без использования `sudo`**.

### Запуск среды

1. Старт пользовательской сессии (выполняется в фоновом режиме или отдельном терминале):

```sh
waydroid session start
```

2. Вывод полноэкранного графического интерфейса Android:

```sh
waydroid show-full-ui
```

### Остановка среды

Для корректного завершения работы всех процессов Android и освобождения оперативной памяти применяется последовательная остановка интерфейса и контейнера.

1. Остановка сессии пользователя:

```sh
waydroid session stop
```

2. Полная остановка контейнера и связанных сетевых интерфейсов:
 
```sh
sudo waydroid container stop
```

## Регистрация несертифицированного устройства (Google Play)

При использовании образа `GAPPS` авторизация в сервисах Google блокируется механизмом SafetyNet/Play Integrity. Требуется ручная регистрация идентификатора устройства.

1. Переход в оболочку контейнера:

```bash
sudo waydroid shell
```

2. Получение уникального идентификатора Android ID:

```sh
settings get secure android_id
```

3. Вывод строки идентификатора в терминал хоста. Полученное значение необходимо внести на веб-странице регистрации устройств Google (`://google.com`).
4. Перезапуск контейнера для применения изменений:

```sh
sudo systemctl restart waydroid-container.service
```

## Функциональные возможности и команды управления

### Управление приложениями через CLI хост-системы

Установка APK-файлов выполняется напрямую из терминала Arch Linux:

```sh
waydroid app install /путь_к_файлу/package.apk
```

Запуск конкретного приложения без открытия полного интерфейса Android:

```bash
waydroid app launch <имя_пакета_приложения>
```

### Обмен файлами между хостом и гостевой ОС

Каталог хранения пользовательских данных Android смонтирован в файловой системе хоста по следующему пути:

```
~/.local/share/waydroid/data/media/0/
```

Копирование файлов в данную директорию делает их доступными внутри файлового менеджера Android.

### Настройка графики для дискретных видеокарт (GPU)

Если в системе установлены две видеокарты (например, Intel + NVIDIA), Waydroid может запускаться на интегрированном графическом ядре по умолчанию. Для принудительного рендеринга через определенный графический процессор используется переопределение переменных окружения перед запуском сессии:

```sh
WAYLAND_DISPLAY=wayland-0 waydroid session start
```

## Диагностика и устранение распространенных неисправностей

### Отсутствие сетевого соединения внутри контейнера

Если внутри Android отсутствует интернет-подключение, требуется настроить перенаправление трафика и брандмауэр на хост-системе.

Для систем с `iptables`:

```sh
sudo iptables -A FORWARD -i waydroid0 -j ACCEPT
sudo iptables -A FORWARD -o waydroid0 -j ACCEPT
```

Для систем с `ufw` необходимо установить политику перенаправления (FORWARD) в режим `ACCEPT` в конфигурационном файле `/etc/default/ufw`.

### Сброс конфигурации к исходному состоянию

В случае критического сбоя системы полное удаление данных контейнера производится следующей последовательностью команд:

```sh
sudo waydroid container stop
waydroid session stop
sudo rm -rf /var/lib/waydroid ~/.local/share/waydroid ~/.bin/waydroid
```

После выполнения данных шагов требуется повторная инициализация через команду `waydroid init`.
