# Аварийная загрузка Linux через консоль GRUB (LVM + XFS)

Инструкция применима к любому Linux-дистрибутиву, когда система не загружается из-за сбоя `systemd`, повреждения конфигов или критических сервисов.

## 1. Подготовка модулей

В консоли GRUB включите поддержку LVM и XFS, чтобы загрузчик смог прочитать разделы:
```bash
insmod lvm
insmod xfs
```

## 2. Поиск разделов и ядер

Выведите список дисков командой `ls`. Диски LVM будут отображаться как `(lvm/ГРУППА_ТОМОВ-ЛОГИЧЕСКИЙ_ТОМ)`.

1. Укажите GRUB, где искать файлы ядра (замените путь на имя вашего корневого LVM-тома):
``` bash
set root=(lvm/vg0-lv_root)
```

2. Проверьте, что каталог `/boot` и файлы ядер доступны:
```
ls /boot
```
 
_(Если `/boot` вынесен на отдельный не-LVM раздел, укажите его, например: `set root=(hd0,msdos1)`, и проверяйте команду как `ls /`)_

## 3. Передача управления в Bash (в обход Systemd)

_Для автозаполнения длинных версий ядер нажимайте клавишу **Tab**._

1. **Загрузите ядро** (замените имена томов и версии на свои):
```
linux /boot/vmlinuz-[ВЕРСИЯ] root=/dev/mapper/vg0-lv_root ro init=/bin/bash
```

- Параметр `ro` монтирует диск в режиме "только чтение" для безопасности FS.
- Параметр `init=/bin/bash` заставляет ядро запустить командную строку вместо `systemd`.
2. **Загрузите initrd** (версия должна строго совпадать с vmlinuz):
```
initrd /boot/initrd.img-[ВЕРСИЯ]
```
 
3. **Старт**:
```
boot
```

## Действия в аварийной консоли `#`

Вы мгновенно окажетесь в `bash` с правами `root` без ввода паролей. `systemd` и его службы не запущены.

### 1. Монтирование файловой системы на запись

Переведите корневой раздел в режим Read-Write, чтобы иметь возможность сохранять изменения:
```
mount -o remount,rw /
```

### 2. Подключение остальных дисков

Если `/var`, `/home` или другие каталоги вынесены на отдельные тома LVM, примонтируйте их согласно `/etc/fstab`:
```bash
mount -a
```

### 3. Исправление системы

Теперь вам доступно всё для ремонта:

- Сброс забытого пароля: `passwd root`
- Редактирование сломанных конфигов: `nano /etc/fstab` (или любых других файлов).
- Отключение сбойного сервиса (ручное удаление симлинка): `rm /etc/systemd/system/multi-user.target.wants/СБОЙНЫЙ_СЕРВИС.service`
- Восстановление загрузчика: `update-grub` (Debian/Ubuntu) или `grub2-mkconfig -o /boot/grub2/grub.cfg` (RHEL/CentOS).

Для выхода и перезагрузки используйте только жесткий сброс: `reboot -f` (обычный `reboot` не сработает, так как службы управления питанием не запущены).

## Важные замечания по безопасности

- Любой, кто имеет **физический доступ** к машине и знает GRUB, может использовать этот метод.  
    
- Чтобы защититься:
    - Установите пароль на GRUB (`set superusers` + `password_pbkdf2`)  
        
    - Используйте шифрование root-диска (LUKS)  
        
    - BIOS/UEFI пароль и Secure Boot  
        
- Init-shell минует все проверки PAM и паролей.
