
## Знакомство с ком.оболч.
### Вычисление переменных
Ком.оболочка может определять переменные и сохранять в них значе-
ния.
Для вывода на экран значений переменных `HOME` и `USER` 
вводим `printenv` ( прим. user: `maxim`):
```bash
$ printenv HOME
/home/maxim
$ printenv USER
maxim
```
Чтобы вычислить переменную, ставим `$` .Например, $HOME вернет `home/maxim.`
Как оболочка обрабатывает командную строку, — запустить команду `echo`, которая выводит свои аргументы (после того как болочка завершит их вычисление):
```bash
$ echo My name is $USER and my files are in $HOMEs
My name is maxim and my files are in /home/maxim
```

---
### Откуда берутся значения переменных
Переменные, как `USER` и `HOME`, предопределены оболочкой. Их значения
устанавливаются автоматически при входе в систему.
Можно определить или изменить переменную в любое время: присвоить ей
значение, используя  синтаксис:
```bash
name=value
```
Например, если часто воркаете с каталогом /home/maxim/Projects, можно
присвоить его имя переменной:
```bash
$ work=$HOME/Projects
```
и использовать его как удобное сокращение при работе с cd:
```bash
$ cd $work
$ pwd
/home/maxim/Projects
```
>!Важно:
>*При определении переменной не допускается использование пробелов около
>знака равенства.*

---
### Переменные и заблуждения

Например команда `echo` не проверяет переменную. 
```bash
$ echo $HOME
/home/maxim
```
Она просто выводит на экран любые аргументы, которые передали.
Значение `$HOME` вычисляет командная оболочка перед запуском команды echo.

С точки зрения `echo`
```bash
$ echo /home/maxim
```

Оболочка вычисляет переменные, шаблоны и другие конструкции
перед выполнением команды.

### Сокращение команд с помощью псевдонимов
В ком. об. также есть имена, которым соответствуют команды. Они
называются псевдонимами (`aliases`). Определим псевдоним, поставив после него
знак равенства и команду:
```bash
$ alias g=grep       # Пример команды без аргументов				
$ alias ll="ls -l"   # Пример команды с аргументами, кавычки необходимы	
```

Можно определить псевдоним с тем же именем, что и у существующей
команды,заменив  её, эта практика называется  затенением (`shadowing`) команды.
Псевдонимы имеют приоритет над командами с тем же именем.

Чтобы вывести все псевдонимы и их значения, которые определены на данный
момент в вашей командной оболочке, запустите `alias` без аргументов:
```bash
$ alias
alias g='grep'
alias ll='ls -l'
```

Чтобы вывести значение конкретного псевдонима, запустите `alias` и передайте
его имя в качестве аргумента:
```bash
$ alias g
alias g='grep'
```

Чтобы удалить псевдоним из оболочки, выполните `unalias`:
```bash
$ unalias g
```

### stderr и перенаправление потоков

> В Linux у процесса **три стандартных потока**:  
> `stdin (0)` ← ввод, `stdout (1)` → обычный вывод, `stderr (2)` → ошибки.  
> **`>` и `|` работают только с `stdout`**, ошибки (`stderr`) продолжают идти в терминал.

---

### Основные операторы перенаправления

| Синтаксис  | Действие                                                                 |
| ---------- | ------------------------------------------------------------------------ |
| `> file`   | `stdout` → файл (перезапись)                                             |
| `>> file`  | `stdout` → файл (дописывание)                                            |
| `2> file`  | `stderr` → файл                                                          |
| `2>> file` | `stderr` → файл (дописывание)                                            |
| `&> file`  | `stdout` **и** `stderr` → файл                                           |
| `>&2`      | перенаправить `stdout` в `stderr` (часто в скриптах: `echo "Error" >&2`) |
| `\|&'      | `stdout + stderr` → пайп (эквивалент `2>&1 \|`)                          |

---

####  Примеры
```bash
# Только ошибки в файл:
cp nofile.txt dest 2> error.log

# Оба потока — в один файл:
cat ok.txt nofile.txt &> all.log

# Пайп с ошибками (bash):
ls /root /tmp 2>&1 | grep -i "permission\|tmp"

# Вывод ошибки в терминал, а нормальный — в файл:
command 2>&1 >out.txt   # ❌ stdout → out.txt, stderr → терминал  
command >out.txt 2>&1   # ✅ сначала stdout, потом stderr → out.txt
```

Порядок важен: `>file 2>&1` ≠ `2>&1 >file`

### Памятка: цифры потоков
|Число|Поток|Можно опустить?|
|---|---|---|
|`0`|stdin|`< file` вместо `0< file`|
|`1`|stdout|`> file` вместо `1> file`|
|`2`|stderr|`2>` — **нельзя** сократить|

>  `2>/dev/null` — «заглушить» ошибки:  
> `grep xyz *.log 2>/dev/null` — покажет только совпадения, без «No such file».

## Отключение вычисления с помощью кавычек и экранирования
### Пробел в мени файла
>В linux пробел является **разделителем**,чтобы оболочка рассматривала пробел как **символ** в имени файла  используем *кавычки*  или *backslash*
```bash
$ cat 'Efficient Linux Tips.txt'
$ cat "Efficient Linux Tips.txt"
$ cat Efficient\ Linux\ Tips.txt
```
### `''`
**Одинарные кавычки ( ' ' )**: Полностью отключают интерпретацию всех специальных символов, включая переменные и команды, сохраняя все как есть, буквально
```bash
$ echo 'Variable $HOME' # Выведет: Variable $HOME (отк. интерп. переменной $HOME, пробел сохранен )
```

### `""`
**Двойные кавычки ( " " )**: Сохраняют пробелы, но позволяют интерпретировать переменные (например, `$VAR`), команды в `` ` `` или `$()` и экранировать символы с помощью `\`
```bash
echo "Hello world" # Выведет: Hello world (пробел сохранен)
echo "Hello   world" # Выведет: Hello   world (несколько пробелов сохранены)
echo "Variable is $HOME" # Выведет: Variable is /home/user (переменная расширяется)
echo "\"Hello\"" # Выведет: "Hello" (экранируем кавычку внутри двойных кавычек)

```

## `\`
Обратная косая черта, также называемая *экранирующим символом*, указывает
оболочке воспринимать буквально символ, находящийся после нее. В следующей
команде экранируется знак доллара:
```bash
$ echo \$HOME
$HOME
```
Обратная косая черта действует как экранирующий символ в двойных кавычках:
```bash
$ echo "Variable of \$HOME is $HOME"
Variable of $HOME is /home/smith
```
но не в одинарных:
```bash
$ echo 'Variable of \$HOME is $HOME'
Variable of \$HOME is $HOME
```
Можно использовать обратную косую черту, чтобы экранировать символ двой-
ных кавычек внутри двойных кавычек:
```bash
echo "This message is \"sort of\" interesting"
This message is "sort of" interesting
```
Обратная косая черта в конце строки отключает функцию невидимого символа
новой строки, позволяя командам оболочки занимать несколько строк:
```bash
echo "This is a very long message that needs to extend \
onto multiple lines"
This is a very long message that needs to extend onto multiple lines
```
 Пример читаемого конвеера, как продолжение строки:
```bash
 cut -f1 grades \
| sort \
| uniq -c \
| sort -nr \
| head -n1 \
| cut -c9
```
Начальная обратная косая черта перед псевдонимом экранирует его, заставляя
оболочку искать команду с тем же именем. Затенение при этом игнорируется:
```bash
$ alias less="less -c" # Определение псевдонима
$ less myfile  # Запуск псевдонима, который определен как less -c
$ \less myfile  # Запуск стандартной команды less, а не псевдонима
```


## Расположение исполняемых программ
Предварительно составленный список путей каталогов, хранящиеся в памяти оболочки  ( наз. `путём для поиска исполняемых программ`.),  как значение  в переменной оболочки $PATH
```bash
echo $PATH
/home/maxim/bin:/home/maxim/.local/bin:/usr/local/bin
```
> Каталоги в пути для поиска разделяются двоеточиями (:)
> Можно преобразовать двоеточия в переводы строки, передав вывод команде tr,
> которая заменяет символы
```bash
echo $PATH | tr : "\n"
/home/vslsk/yandex-cloud/bin
/home/vslsk/bin
/home/vslsk/.local/bin
/usr/local/bin
```

> *Некоторые оболочки запоминают (кэшируют) пути к программам по мере их обнаружения,сокращая количество поисковых запросов в будущем.*

Чтобы найти программу в списке каталогов для поиска, используй команду
`which`:
```bash
which cp
/usr/bin/cp
```
или встроенную в оболочку более мощную и информативную команду type, ко-
торая также находит псевдонимы, функции и встроенные в оболочку команды1.
```bash
type cp
cp is /usr/bin/cp
```
Если есть программы с одинаковыми названиями, расположенные в разных ка-
талогах, например /usr/bin/less и /bin/less, оболочка запустит тот файл, который
найдет первым. Можно переопределить команду, поместив соответствующий файл в каталог, который будет просматриваться раньше, например личный каталог $HOME/bin.
> Когда оболочка ищет команду по имени, она прежде всего проверяет,
> является ли это имя псевдонимом. Именно поэтому псевдоним затеняет
> команду (имеет более высокий приоритет) с таким же именем.


## Окружение и файлы инициализации, краткая версия
Переменные запущенной командной оболочки в совокупности называются *окружением*. Когда пользователь выходит из командной оболочки, ее *окружение* уничтожается. Утомительно при каждом запуске оболочки определять
ее *окружение* вручную. Поэтому оно определяется в сценариях, называемых
*файлами запуска* и *файлами инициализации*, которые автоматически выполня-
ются при запуске командной оболочки. 
Прим. файла `.bashrc`
```bash
# Задать путь для поиска
PATH=$HOME/bin:/usr/local/bin:/usr/bin:/bin
# Задать приглашение командной строки
PS1='$ '
# Задать предпочитаемый текстовый редактор
EDITOR=emacs
# Начать в моем рабочем каталоге
cd $HOME/Work/Projects
# Определить псевдоним
alias g=grep
# Сердечно поприветствовать
echo "Welcome to Linux, friend!"
```
Изменения, которые вы вносите в **$HOME/.bashrc**, не влияют на запущенные
экземпляры оболочки. Но вы можете заставить запущенный экземпляр заново
выполнить **$HOME/.bashrc** с помощью одной из следующих команд:
```bash
$ source $HOME/.bashrc # Используется встроенная команда source
$ . $HOME/.bashrc      # Используется точка
```
Этот процесс известен как считывание файла инициализации. Говоря «использовать исходный файл **.bashrc**», имеют в виду выполнение одной из предыдущих команд.

- Оболочка выполняет важные функции.
- Оболочка интерпретирует командную строку перед запуском любых
команд.
- Команды могут перенаправлять стандартные потоки ввода, вывода
и ошибок.
- Кавычки и экранирование предотвращают интерпретацию командной
оболочкой специальных символов.
- Оболочка находит программы, используя путь для поиска файлов.
- Вы можете изменить настройки командной оболочки, добавив команды
в файл **$HOME/.bashrc.**

### Повторный запуск команд

Предположим, только что выполнили длинную команду со сложным конвей-
ером,  `«Обнаружение дубликатов файлов»`

```bash
$ md5sum *.jpg | cut -c1-32 | sort | uniq -c | sort -nr
```
и вы хотите запустить ее еще раз. За кадром остается то, как оболочка
ведет запись вызываемых команд и их можно  повторнозапускать. Эта функция оболочки называется *историей команд.*

Точно так же предположим, что вы допустили ошибку при наборе предыдущей
команды, например написав `jg` вместо `jpg`:
```bash
$ md5sum *.jg | cut -c1-32 | sort | uniq -c | sort -nr
```
Оболочка поддерживает *редактирование командной строки* для исправления опечаток и выполнения всевозможных модификаций. Чтобы исправить ошибку, не нажимайте клавишу `Backspace` десятки раз и не вводите все заново.

`! Важно научиться печать в слепую. Попробуйте достичь 100 слов в минуту. Результат стоит потраченных усилий.`

##  История команд
`История команд` — это список команд, которые вы выполняли в интерактивной оболочке. Чтобы просмотреть историю, запустите команду `history`, встроенную в оболочку.
```bash
$ history
 8815  git add .
 8816  git commit -m "fix"
 8817  git push
```

Вывод `history` может состоять из сотен (и более) строк. Ограничьте его самыми последними командами, добавив целочисленный аргумент, который указывает количество выводимых строк:
```bash
$ history 3
  142  cd
  143  exit
  144  history 3
```

Поскольку `history` записывает в стандартный вывод, вы можете обрабатывать ее вывод с помощью `конвейеров`. Например, просмотрите свою историю по одному экрану за раз:
```bash
$ history | less #От самой последней команды к первой запущенной		
$ history | sort -nr | less #От самой первой команды к последней запущенной
```

Или вывести комманды содержащие `ls`
```bash
$ history | grep -w ls
```

Очистка истории
```bash
$ history -c
```

###  Изменение количества команд 
Чтобы посмотреть, какое максимальное количество команд истории используем:
```bash
$ echo $HISTSIZE
50000
```

Можно задать количество команд в  истории:
```bash
$ HISTSIZE=70000 # 70000 строк истории
$ HISTSIZE=-1    # бесконечное количество команд истории
```

Игнорируем добавление команды в историю ( *при условии что одна идёт за другой*)
```bash
$ HISTCONTROL=ignoredups
```

Каждый экземпляр интерактивной оболочки имеет свою независимую от других историю команд.

Всякий раз, когда интерактивная оболочка завершает работу, она записывает свою историю в файл `$HOME/.bash_history` или другой, хранящийся в переменной оболочки `HISTFILE`:
```bash
$ echo $HISTFILE
/home/username/.bash_history
```

Новые экземпляры оболочки считывают при запуске историю файла `$HISTFILE`

Переменная `HISTFILESIZE` определяет, сколько строк истории записывается в файл. Если  изменять `HISTSIZE`, управляя размером истории в памяти, желательно обновить значение `HISTFILESIZE`:
``` bash
$ echo $HISTFILESIZE
500 # Если пусто, то кол-во строк бесконечно
$ HISTFILESIZE=10000
```

### Расширение истории команд
**Расширение истории** — это функция оболочки, которая обращается к истории команд с помощью *специальных выражений*. Эти выражения начинаются с восклицательного знака, который пользователи Linux традиционно называют `bang`. 

!!!!! ОСТОРОЖНО, КОМАНДЫ  ВЫПОЛНЯЮТСЯ СРАЗУ, ЧТОБЫ ИЗБЕЖАТЬ ставим `:p`  ( в `zsh`  подставляет на выполнение, но не выполняет сразу!)

Два восклицательных знака подряд (`bang-bang`) означают предыдущую команду:
```bash
$ !! # bang-bang *выполнить предыдущую команд*
```

Чтобы обратиться к последней команде, начинающейся с `определенного выражения`, поставьте перед ним восклицательный знак.
```
$ !grep
```

Чтобы обратиться к последней команде, которая содержала заданное выражение `где-либо`, а не только в начале строки, окружите его `вопросительными знаками`:
```bash
$ !?grep?
history | grep -w cd
```

Также можно найти команду из истории  по её абсолютной позиции:
```bash
$ history | grep hosts
1203 cat /etc/hosts

$ !1203 # Выполняем команду под номером 1023
cat /etc/hosts
```

Отрицательное значение извлекает команду из истории по ее относительной, а не абсолютной позиции ( сколько  шагов назад была выполнена):
```bash
$ !-2
clear
```

```bash
$ !-2:p # выводим команду 2 шага назад ( не выполняя `:p`)
clear
$ !!    # Выполняем команду
```

Расширение истории иногда называют `bang-командами`, но выражения вроде `!!` и `!grep` не являются `командами`. Это `строковые выражения`, которые можно поместить в `любом месте команды`. Использя команду `echo` для  вывода значения `!!` в `stdout`, не выполняя его, и подсчитаем количество слов с помощью `wc`:
```bash
$ ls -l /etc | head -n3 # Запустим команду

$ echo "!!" | wc -w # Подсчитаем количество слов в пред команде
echo "ls -l /etc | head -n3" | wc -w
6
```

###  Удаление с помощью расширения команд (без ошибочного удаление,, ОТ КРИВОРУКОВТИ) )

1. `Проверка`. Перед запуском `rm` запустить `ls` с `нужным шаблоном`, чтобы
увидеть, какие файлы совпадают:
```bash
ls *.txt
a.txt b.txt c.txt
```

2. `Удаление`. Если вывод `ls` прошел проверку, запустим `rm !$`, чтобы удалить те же файлы, которые были сопоставлены с шаблоном.
```bash
$ rm !$
rm *.txt
```

Расширение истории `!$` означает «*последнее* слово, которое ввели в предыдущей команде»

Похожий метод заключается в просмотре содержимого файла с помощью ко-
манды `head` перед его удалением. Убедившись, что выбрали правильный файл, можно  запустить `rm !$`

Также в оболочке имеется расширение истории `!*`, которое соответствует *всем* аргументам, введенным в предыдущей команде, а не только *последнему*:
```bash
$ ls *.txt *.o *.log
a.txt b.txt c.txt main.o output.log parser.o
$ rm !*
rm *.txt *.o *.log
```

На практике  *лучше ипользовать* `!*` значительно *реже*, чем `!$`, так как есть риск, что в случае ошибки звездочка `*` будет интерпретирована как *символ шаблона* для имен файлов. 

### Инкрементальный поиск по истории команд
Инкрементальный  поиск — это самый простой и быстрый способ вспомнить команды из истории, даже те, которые запускал давно.
- В приглашении оболочки нажимаем Ctrl-R (R означает обратный (reverse) инкрементальный поиск).
- Вводите любую часть ранее запущенной команды — начало, середину или конец.
- С каждым введенным символом оболочка находит ближайшую в истории команду, которая соответствует вашему вводу. 

Вот еще несколько трюков с инкрементальным поиском:
- Чтобы вызвать последнюю строку, которую вы искали и выполняли, начните с нажатия `Ctrl-R` два раза подряд.
- Чтобы остановить инкрементальный поиск и продолжить работу над текущей командой, нажмите Escape, `Ctrl-J` или любую клавишу для редактирования в командной строке ,например клавишу со стрелкой влево или вправо.
- Чтобы выйти из инкрементального поиска и очистить командную строку, нажмите `Ctrl-G` или `Ctrl-C`.

## Редактирование командной строки

### 1. Расширение истории с помощью знака вставки
Предположим, что мы ошиблись в написании команды
```bash
md5sum *.jg | cut -c1-32 | sort | uniq -c | sort -nr
```


Можно исправить тем, что просто ввести старый (неправильный) текст, новый (исправленный) текст и пару знаков вставки `(^)`, например:
```bash
^jq^jpg
```
> Этот метод изменяет только первое вхождение исходного кода `(jg)`. Если ваша исходная команда содержала jg более одного раза, *только первый* экземпляр изменится на `jpg`.

БОЛЕЕЕЕ МОЩНАЯ ЗАМЕНА с помощью расширения истории )) 
Можно использвать синтаксис `sed/ed` (`s/source/target/`,  поставив `duble-bang` в начале:
```bash
!!s:/jg/jpg/
```

Можно также начать с любого расширения истории, например, `!md5sum` вызовет последнюю команду, начинающуюся с `md5sum`, и выполнит ту же замену `jg` на `jpg`:
```bash
$ !md5sum:s/jg/jpg/
```

Этот способ может показаться сложным, но иногда он позволяет быстрее достичь цели, чем другие методы редактирования в командной строке. Запустите `man history` для получения полной информации.

### 2. Редактирование командной строки в стиле Emacs

Фича, как сменить  сменить комманду, но оставить аргумент..
Например :
```bash
$ md5sum /path/to/very/long/filename.jpg
```

А теперь хочешь сделать что-то с этим же файлом, просто напиши следующую команду и нажми **`Alt + .`**:
```bash
cat [Alt + .]
cat /path/to/very/long/filename.jpg
```


Три техники упрощают использование Linux:
- Безопасное удаление файлов с помощью !$.
- Инкрементальный поиск через Ctrl-R.
- Редактирование командной строки в стиле Emacs.
