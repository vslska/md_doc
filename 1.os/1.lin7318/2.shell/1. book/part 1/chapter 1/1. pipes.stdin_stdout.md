# Конвейеры, потоки данных и каналы (Pipes) в Linux

Конвейер (`|`) соединяет стандартный вывод (**stdout**) одной команды со стандартным вводом (**stdin**) другой на уровне виртуальной файловой системы (VFS) ядра. Это фундаментальный инструмент автоматизации: цепочка простых атомарных утилит формирует мощный инструмент обработки данных.

---

Анатомия трех стандартных потоков

Каждому запущенному процессу ядро Linux по умолчанию выделяет три файловых дескриптора (FD):

|Поток|Назначение|Идентификатор (FD)|Устройство по умолчанию|
|---|---|---|---|
|`stdin`|Стандартный ввод|`0`|Клавиатура / Терминал|
|`stdout`|Стандартный вывод|`1`|Экран терминала|
|`stderr`|Вывод сообщений об ошибках|`2`|Экран терминала|

Поведение потоков в конвейере

Конструкция `команда1 | команда2` связывает строго `stdout (1)` первой команды с `stdin (0)` второй.

Поток ошибок `stderr (2)` по умолчанию **не передается** по конвейеру и выводится напрямую в терминал. Чтобы направить поток ошибок в конвейер для фильтрации, необходимо выполнить перенаправление:

- `команда1 2>&1 | команда2` (Классический POSIX-синтаксис)
- `команда1 |& команда2` (Сокращенный синтаксис, поддерживаемый в современных версиях `bash` и `zsh`)

Архитектура Pipe на уровне ядра

Анонимный канал (Pipe) — это не временный файл на диске, а **кольцевой буфер в оперативной памяти (RAM)** под управлением ядра.

- **Лимиты буфера (Backpressure):** По умолчанию размер буфера Pipe в современных ядрах Linux составляет **64 КБ**. Если `команда1` генерирует данные быстрее, чем `команда2` успевает их вычитывать, буфер заполняется. Ядро автоматически приостанавливает выполнение `команды1` (переводя её в состояние сна), пока `команда2` не освободит место в буфере. Данный механизм предотвращает переполнение RAM.
- **Сигнал `SIGPIPE`:** Если `команда2` завершила свою работу досрочно (например, утилита `head` прочитала первые 3 строки и закрыла свой `stdin`), ядро Linux мгновенно посылает `команде1` системный сигнал **`SIGPIPE (13)`**. Процесс `команды1` аварийно завершается, что предотвращает бесполезную утилизацию CPU на генерацию данных, которые больше никто не читает.

Ключевые утилиты обработки потоков

|Утилита|Назначение|Важные флаги под High Load|
|---|---|---|
|`wc`|Подсчёт строк, слов, байт|`-l` — подсчет строго по символам перевода строки `\n` (работает максимально быстро)|
|`head` / `tail`|Вывод начала / конца потока|`-n[N]` — количество строк. `tail -f` — интерактивный стриминг лога|
|`cut`|Извлечение полей или символов|`-f[N]` — номер поля; `-d` — разделитель (работает быстрее `awk`, но не умеет в регулярные выражения)|
|`grep`|Фильтрация строк по шаблону|`-v` — инверсия; `-w` — только целые слова; `-E` — расширенные регулярки (ERE)|
|`sort`|Сортировка строк|`-n` — числовая; `-r` — реверс; `-t` — явный разделитель полей; `-k[N]` — номер ключевого поля|
|`uniq`|Обработка **соседних** дубликатов|`-c` — подсчет количества; `-d` — вывод только дубликатов|

Практические высокоэффективные конвейеры

|Задача|Оптимальная команда|Архитектурный нюанс|
|---|---|---|
|Найти год самой новой книги|`cut -f3 animals.txt \| sort -nr \| head -n1`|`head -n1` сразу пошлет `SIGPIPE` утилите `sort` после получения первой строки|
|Сортировка книг по году издания|`sort -t$'\t' -k3,3n animals.txt`|**Критично:** Без флага `-t$'\t'` утилита `sort` разобьет строки по пробелам внутри названий книг, и сортировка сломается|
|Алфавитный список уникальных пользователей системы|`cut -d: -f1 /etc/passwd \| sort \| uniq`|**Правило:** Утилита `uniq` видит только _соседние_ дубликаты. Перед ней всегда обязан идти `sort`|
|Проверка наличия системного пользователя|`grep -qw brltty /etc/passwd && echo "Exist"`|Флаг `-q` глушит `stdout`, утилита возвращает только код `0` (успех) или `1` (не найдено)|
|Поиск и подсчет дубликатов файлов по MD5|`md5sum *.jpg \| cut -c1-32 \| sort \| uniq -c \| sort -nr`|**Внимание:** Старый флаг `uniq -w32` удален из GNU Coreutils ≥ 9.0. Хэш необходимо предварительно отрезать через `cut`|
|Вывод имен файлов с конкретной контрольной суммой|`md5sum *.jpg \| grep "^a1b2c3..." \| cut -d' ' -f2-`|Конструкция `-f2-` указывает `cut` забрать второе поле и все последующие символы до конца строки (сохраняет пробелы в именах файлов)|

Справочник системных флагов

text

```
-d   : Задание разделителя полей (для cut: -d':'; для sort: -t':')
-fN  : Выбор поля номер N (счет с 1)
-w   : Поиск строк, содержащих шаблон в виде отдельного целого слова (для grep)
-q   : Quiet-режим. Отключает вывод данных, используется для условных операторов в скриптах (для grep)
-c1-32 : Вырезать строго символы с 1 по 32 включительно (для cut)
2>&1 : Перенаправление дескриптора 2 (stderr) в дескриптор 1 (stdout)
```

Use code with caution.

Инженерные правила работы с потоками

1. **Превентивная проверка кода:** Перед запуском деструктивных конвейеров (содержащих `rm`, `mv`, `xargs` или перенаправление записи `> file`), всегда проверяйте корректность выборки данных. Заменяйте финальную команду на `head -n20` или оборачивайте её в `echo`.
2. **Выбор инструмента (Парсинг CSV/TSV):** Утилита `cut` работает на порядок быстрее, чем `awk`, так как выполняет простое побайтовое сканирование разделителя. Однако `cut` хрупок: если в данных CSV внутри кавычек попадется символ-разделитель (например, запятая в тексте), `cut` разломает структуру. Для сложных CSV используйте `awk` или специализированный инструментарий (например, `csvkit`).
3. **Ловушка обнуления:** Помните, что конструкция `команда file | grep "test" > file` **намертво уничтожит ваши данные**. Шелл выполняет перенаправление `> file` (обнуляя файл) еще _до_ того, как `команда` начнет его читать. Для безопасной модификации файлов «на месте» используйте утилиту `sponge` из пакета `moreutils` или флаги инлайн-модификации (например, `sed -i`).
