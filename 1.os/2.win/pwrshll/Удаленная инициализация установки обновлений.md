## Архитектура агента SCCM и механизмы WMI/CIM

Агент SCCM (`CcmExec`) управляется через пространство имен **WMI (Windows Management Instrumentation)** `root\ccm`. Все операции, выполняемые администратором через GUI Software Center или панель управления `Configuration Manager`, представляют собой вызовы WMI-методов или триггеров циклов клиентского агента.

Удаленная работа с агентом SCCM выполняется без захода в графическую сессию хоста путем отправки сигналов инициализации циклов оценки (Client Actions) или прямым вызовом методов WMI-классов установки обновлений через `Invoke-Command` или `Get-CimInstance`.

```text
  [ Административная консоль / Скрипт ]
                   │
                   │  WinRM (PowerShell Remoting / WMI / CIM)
                   ▼
  [ WMI Namespace: root\ccm / root\ccm\ClientSDK ]
                   │
                   ▼
        [ Служба CcmExec (SCCM Agent) ]
                   │
  ┌────────────────┴────────────────┐
  ▼                                 ▼
[ Trigger Schedule / Evaluation ]  [ CCM_SoftwareUpdate Install ]
````

## Предварительные требования и сетевые доступы

Для успешного выполнения удаленных команд на целевых хостах должны соблюдаться условия:

1. Разрешено удаленное управление через WinRM / PowerShell Remoting (`Enable-PSRemoting`);
2. Права локального администратора на целевом хосте;
3. Служба `CcmExec` (SMS Agent Host) запущена на целевом хосте.

## Инициализация циклов сканирования и оценки обновлений (Client Actions)

Перед запуском установки агенту требуется получить назначения из точки управления (Management Point) и выполнить локальную оценку необходимых патчей.

Для запуска циклов используется WMI-класс `SMS_Client` в пространстве имен `root\ccm`.

### Таблица идентификаторов ключевых циклов (Schedule IDs)

|**Имя цикла**|**Идентификатор (Schedule ID)**|**Описание**|
|---|---|---|
|**Software Update Scan Cycle**|`{00000000-0000-0000-0000-000000000113}`|Запуск полного сканирования требуемых обновлений.|
|**Software Update Deployment Evaluation Cycle**|`{00000000-0000-0000-0000-000000000108}`|Запуск оценки развернутых обновлений и проверка дедлайнов.|
|**Machine Policy Retrieval Cycle**|`{00000000-0000-0000-0000-000000000021}`|Запрос новой политики компьютера с Management Point.|
|**Machine Policy Evaluation Cycle**|`{00000000-0000-0000-0000-000000000022}`|Оценка и применение загруженных политик.|

### Запуск сканирования и оценки обновлений на удаленном хосте

Выполнение инициализации цикла сканирования и оценки политик обновления на удаленном сервере `SERVER01`:

```PowerShell
Invoke-Command -ComputerName "SERVER01" -ScriptBlock {
    # 1. Запрос новых политик с Management Point
    Invoke-CimMethod -Namespace "root\ccm" -ClassName "SMS_Client" -MethodName "TriggerSchedule" -Arguments @{ sScheduleID = "{00000000-0000-0000-0000-000000000021}" }

    # 2. Запуск сканирования недостающих обновлений
    Invoke-CimMethod -Namespace "root\ccm" -ClassName "SMS_Client" -MethodName "TriggerSchedule" -Arguments @{ sScheduleID = "{00000000-0000-0000-0000-000000000113}" }

    # 3. Запуск цикла оценки развертывания
    Invoke-CimMethod -Namespace "root\ccm" -ClassName "SMS_Client" -MethodName "TriggerSchedule" -Arguments @{ sScheduleID = "{00000000-0000-0000-0000-000000000108}" }
}
```

## Удаленный поиск и инспекция доступных обновлений

Перед запуском установки проверяется список требуемых патчей, поступивших на хост в пространство `root\ccm\ClientSDK`.

Класс `CCM_SoftwareUpdate` хранит статус всех поступивших обновлений.

### Скрипт проверки ожидающих установки обновлений

```PowerShell
Invoke-Command -ComputerName "SERVER01" -ScriptBlock {
    Get-CimInstance -Namespace "root\ccm\ClientSDK" -ClassName "CCM_SoftwareUpdate" | 
        Select-Object Name, ArticleID, EvaluationState, PSComputerName |
        Format-Table -AutoSize
}
```

_Интерпретация значений `EvaluationState`:_

- `0` или `1` — Не установлено (Missing / Pending installation);
- `8` или `13` — Установка в процессе (Installing);
- `14` — Требуется перезагрузка (Pending reboot).

## Принудительная удаленная установка всех поступивших обновлений

Для старта установки без использования интерфейса Software Center вызывается метод `InstallUpdates` класса `CCM_SoftwareUpdate` в пространстве имен `root\ccm\ClientSDK`.

### Полный сценарий удаленной установки всех требуемых патчей

```PowerShell
$targetHost = "SERVER01"

Invoke-Command -ComputerName $targetHost -ScriptBlock {
    # 1. Получение массива всех доступных для установки обновлений
    $missingUpdates = Get-CimInstance -Namespace "root\ccm\ClientSDK" -ClassName "CCM_SoftwareUpdate" | 
        Where-Object { $_.EvaluationState -like "*1*" -or $_.EvaluationState -eq 0 -or$_.ComplianceState -eq 0 }

    if ($missingUpdates) {
        Write-Output "Найдено невыполненных обновлений: $($missingUpdates.Count). Запуск установки..."
        
        # 2. Вызов метода установки всех найденных объектов
        Invoke-CimMethod -Namespace "root\ccm\ClientSDK" `
                         -ClassName "CCM_SoftwareUpdate" `
                         -MethodName "InstallUpdates" `
                         -Arguments @{ TargetUpdates = [CimInstance[]]$missingUpdates } | Out-Null
        
        Write-Output "Сигнал на установку успешно отправлен агенту CCM."
    } else {
        Write-Output "Доступных или недостающих обновлений не обнаружено."
    }
}
```

## Параллельный запуск установки на группе серверов

Для массовой инициализации установки на списке хостов передается массив серверов в `Invoke-Command`:

```PowerShell
$servers = @("SERVER01", "SERVER02", "DBNODE01")

Invoke-Command -ComputerName $servers -ScriptBlock {
    $updates = Get-CimInstance -Namespace "root\ccm\ClientSDK" -ClassName "CCM_SoftwareUpdate"
    if ($updates) {
        Invoke-CimMethod -Namespace "root\ccm\ClientSDK" `
                         -ClassName "CCM_SoftwareUpdate" `
                         -MethodName "InstallUpdates" `
                         -Arguments @{ TargetUpdates = [CimInstance[]]$updates } | Out-Null
        "[$(env:COMPUTERNAME)] Установка обновлений успешно запущена."
    } else {
        "[$(env:COMPUTERNAME)] Нет доступных обновлений."
    }
}
```

## Мониторинг прогресса установки и статуса перезагрузки

### Проверка статуса установки в реальном времени

```PowerShell
Invoke-Command -ComputerName "SERVER01" -ScriptBlock {
    Get-CimInstance -Namespace "root\ccm\ClientSDK" -ClassName "CCM_SoftwareUpdate" | 
        Select-Object Name, ArticleID, @{N='Status'; E={
            case ($_.EvaluationState) {
                0  { "Pending" }
                8  { "Installing" }
                13 { "Installing" }
                14 { "Pending Reboot" }
                default { $_.EvaluationState }
            }
        }}
}
```

### Проверка статуса требуемой перезагрузки (Pending Reboot)

Служба SCCM фиксирует состояние необходимости перезагрузки в классе `CCM_ClientUtilities`:

```PowerShell
Invoke-Command -ComputerName "SERVER01" -ScriptBlock {
    Invoke-CimMethod -Namespace "root\ccm\ClientSDK" -ClassName "CCM_ClientUtilities" -MethodName "DetermineIfRebootPending" |
        Select-Object RebootPending, IsHardRebootPending
}
```

## Справочник командлетов и WMI-методов SCCM

|**Задача**|**WMI Namespace / Класс**|**Метод / Команда**|**Описание**|
|---|---|---|---|
|**Запрос политики**|`root\ccm` / `SMS_Client`|`TriggerSchedule("{...0021}")`|Загрузка новых политик с MP|
|**Сканирование патчей**|`root\ccm` / `SMS_Client`|`TriggerSchedule("{...0113}")`|Запуск поиска требуемых обновлений|
|**Список обновлений**|`root\ccm\ClientSDK` / `CCM_SoftwareUpdate`|`Get-CimInstance`|Просмотр поступивших патчей|
|**Запуск установки**|`root\ccm\ClientSDK` / `CCM_SoftwareUpdate`|`InstallUpdates`|Принудительная установка без GUI|
|**Проверка перезагрузки**|`root\ccm\ClientSDK` / `CCM_ClientUtilities`|`DetermineIfRebootPending`|Проверка флага ожидания перезагрузки|

## Заключение

Автоматизация управления агентом SCCM/MECM через пространство имен WMI/CIM и консоль PowerShell позволяет полностью отказаться от ручного подключения к хостам через RDP или инспекции интерфейса Software Center. Использование системных методов `TriggerSchedule` и `InstallUpdates` обеспечивает быстрое, управляемое и идемпотентное развертывание патчей безопасности по всей инфраструктуре.
