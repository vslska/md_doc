## Архитектура PowerShell Remoting (WinRM / WSMAN)

PowerShell Remoting базируется на стандарте **WS-Management (WSMAN)** и службе **Windows Remote Management (WinRM)**. Механизм обеспечивает зашифрованную передачу команд и объектов .NET между локальным клиентом и удаленным сервером.

```
  [ Локальная консоль ]
           │
           │  WinRM (HTTP: 5985 / HTTPS: 5986)
           ▼
  [ Удаленный хост (WinRM Listener) ] ──► [ Удаленный сеанс PowerShell ]
```

По умолчанию используются сетевые порты:

- `5985/TCP` — HTTP-трафик (данные внутри сессии зашифрованы);
- `5986/TCP` — HTTPS-трафик (с проверкой SSL-сертификата).

## Подготовка удаленного хоста (Предварительная настройка)

Для включения возможностей удаленного управления на целевом сервере необходима единоразовая инициализация службы WinRM. Команда выполняется в консоли PowerShell **от имени администратора**:

```PowerShell
Enable-PSRemoting -Force
```

Данная команда выполняет:

1. Запуск и настройку службы `WinRM` на автоматический старт;
2. Создание прослушивателей (listeners) на портах 5985/5986;
3. Настройку правил брандмауэра Windows (Firewall) для входа WinRM-трафика.

## Интерактивное удаленное подключение (`Enter-PSSession`)

`Enter-PSSession` открывает интерактивную консоль ввода команд прямо на удаленном сервере.

### Установление сеанса

```PowerShell
Enter-PSSession -ComputerName SERVER01
```

После подключения приглашение командной строки изменится на `[SERVER01]: PS C:\>`, информируя о том, что все последующие команды исполняются на сервере `SERVER01`.

### Подключение с явным указанием учетных данных

```PowerShell
Enter-PSSession -ComputerName SERVER01 -Credential (Get-Credential)
```

### Настройка подключения с указанием конкретного порта

```PowerShell
Enter-PSSession -ComputerName SERVER01 -Port 5985
```

### Завершение интерактивного сеанса

```PowerShell
Exit-PSSession
```

## Пакетное и параллельное выполнение команд (`Invoke-Command`)

Для выполнения сценариев на одном или нескольких серверах без переключения консоли используется командлет `Invoke-Command`.

### Выполнение блока команд на удаленном сервере

```PowerShell
Invoke-Command -ComputerName SERVER01 -ScriptBlock {
    Get-Service -Name wuauserv
}
```

### Параллельное выполнение на группе серверов

```PowerShell
$servers = @("SERVER01", "SERVER02", "SERVER03")
Invoke-Command -ComputerName $servers -ScriptBlock {
    Get-Process -Name "lsass"
}
```

### Передача локальных переменных в удаленный скрипт (`$Using:`)

Переменные, объявленные на локальной машине, не доступны автоматически внутри блока `-ScriptBlock`. Для их передачи используется префикс `$Using:`:

```PowerShell
$serviceName = "spooler"
Invoke-Command -ComputerName SERVER01 -ScriptBlock {
    Get-Service -Name $Using:serviceName
}
```

## Управление постоянными сессиями (`New-PSSession`)

Если требуется выполнить серию команд на одном сервере с сохранением промежуточного состояния и переменных, создается постоянный сеанс (`PSSession`):


```PowerShell
# Создание постоянного сеанса
$session = New-PSSession -ComputerName SERVER01 -Credential (Get-Credential)

# Выполнение команд внутри сохраненной сессии
Invoke-Command -Session $session -ScriptBlock { $var = 100 }
Invoke-Command -Session $session -ScriptBlock { $var + 50 } # Вернет 150

# Закрытие сеанса
Remove-PSSession -Session $session
```

## Справочник командлетов PowerShell Remoting

|**Задача**|**Командлет / Пример**|**Описание**|
|---|---|---|
|**Включение WinRM**|`Enable-PSRemoting -Force`|Инициализация службы WinRM на сервере|
|**Интерактивный вход**|`Enter-PSSession -ComputerName host`|Переход в интерактивный удаленный режим|
|**Выход из сессии**|`Exit-PSSession`|Возврат в локальную консоль|
|**Однократная команда**|`Invoke-Command -ComputerName h -ScriptBlock {...}`|Запуск кода на удаленном хосте|
|**Создание сеанса**|`$s = New-PSSession -ComputerName h`|Сохранение сессии в переменную|
|**Удаление сеанса**|`Remove-PSSession -Session $s`|Освобождение ресурсов удаленной сессии|

## Заключение

Инструментарий PowerShell Remoting (`Enter-PSSession`, `Invoke-Command`) предоставляет масштабируемое решение для администрирования инфраструктуры Windows. Сочетание интерактивного доступа и параллельного пакетного исполнения скриптов на удаленных нодах позволяет полностью автоматизировать задачи обслуживания серверов без использования графических средств управления.
