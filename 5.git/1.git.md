## Ментальная модель состояний файлов в Git

В Git каждый файл находится в одном из ключевых состояний, распределенных по трем основным областям:

```
               Три области и состояния Git
                            │
  ┌─────────────────────────┼─────────────────────────┐
  ▼                         ▼                         ▼
[ Working Directory ]    [ Staging Area (Index) ]  [ Repository (.git) ]
  Unmodified / Modified    Staged (индексирован)     Committed (в истории)
   (Файлы на диске)         `git add`                 `git commit`
```

## Базовые команды и инициализация

### Инициализация и настройка

- **Инициализация репозитория:** Создание скрытого каталога `.git` в текущей рабочей директории.

```
git init
```

- **Глобальная настройка дефолтной ветки (`main` вместо `master`):**

```
git config --global init.defaultBranch main
```

### Просмотр состояния и индексация

- **Просмотр состояния репозитория:** Отображение измененных, добавленных и неотслеживаемых файлов.

```sh
git status
```

- **Добавление файлов в индекс (Staging Area):**

```sh
git add <file>    # Добавление конкретного файла
git add .         # Добавление всех изменений в текущей директории
```

- **Удаление файла из индекса без удаления с диска:**

```sh
git rm --cached <file_or_dir>
```

### Коммиты и история

- **Создание коммита:** Сохранение текущего индексированного состояния с описанием.

```sh
git commit -m "Описание изменений"
```

- **Просмотр истории коммитов:**

```sh
git log
git log --oneline --graph --all   # Компактный граф веток для анализа истории
```

### Исключение файлов (`.gitignore`)

Файл `.gitignore` используется для предотвращения отслеживания служебных файлов, логов, зависимостей и секретов.

Пример содержимого `.gitignore`:

```ini
*.log
*.tmp
*.exe
/build/
/dist/
.env
config.local.json
```

## Ветвление и работа с удаленными репозиториями

### Управление ветками

- **Создание новой ветки:**

```sh
git branch feature/login
```

- **Переключение на ветку:**

```sh
git checkout feature/login 
# Современный стандартизированный синтаксис: git switch feature/login
```

- **Создание и мгновенный переход на новую ветку:**

```sh
git checkout -b feature/login
# Или: git switch -c feature/login
```

- **Переименование текущей ветки (например, из `master` в `main`):**

```sh
git branch -m master main
```

- **Слияние ветки в текущую:**
 
```sh
git checkout main
git merge feature/login
```

- **Удаление ветки:**

```sh
git branch -d feature/login       # Безопасное удаление (если ветка слита)
git branch -D feature/login       # Принудительное удаление несвязанной ветки
```
### Взаимодействие с удаленными репозиториями (GitHub / GitLab)

- **Привязка удаленного репозитория:**

```sh
git remote add origin https://github.com/username/repository.git
```

- **Первичная отправка изменений с привязкой ветки (Push):**

```sh
git push -u origin main
# Либо: git push --set-upstream origin main
```
   
- **Получение изменений (Pull):**

```sh
git pull origin main
```

## Стратегии отката изменений, отмена коммитов и очистка

```
                      Стратегии отката
                             │
 ┌───────────────────────────┼───────────────────────────┐
 ▼                           ▼                           ▼
[ git restore / checkout ]  [ git reset ]               [ git revert ]
Отмена локальных несделанных  Перемещение указателя      Безопасная отмена
изменений на диске.          ветки назад.                публичного коммита.
```

### Отмена локальных изменений (до коммита)

- **Отменить незакоммиченные изменения в файле (сброс к состоянию `HEAD`):**
```sh
git restore <file>
# Устаревший синтаксис: git checkout -- <file>
```

- **Убрать файл из индекса, оставив изменения в рабочей директории:**

```sh
git restore --staged <file>
# Устаревший синтаксис: git reset HEAD <file>
```

- **Полный сброс всех незакоммиченных изменений в рабочей директории:**

```sh
git reset --hard HEAD
```

- **Очистка проекта от всех неотслеживаемых (untracked) файлов и папок:**
  
```sh
git clean -fd
```


### Откат локальных коммитов (`git reset`)

> **Внимание:** Команда `git reset` применяется **исключительно для локальных коммитов**, которые еще не были опубликованы в удаленном репозитории (`push`).

- **`git reset --soft HEAD~1`** — отменяет последний коммит, оставляя все изменения в индексе (готовыми к новому коммиту).
- **`git reset --mixed HEAD~1`** _(режим по умолчанию)_ — отменяет коммит и сбрасывает индекс, сохраняя изменения в рабочей директории.
- **`git reset --hard HEAD~1`** — **жесткий сброс.** Безвозвратно стирает последний коммит и все внесенные в нем изменения в коде.

- **Принудительный сброс локальной ветки к состоянию удаленной `origin/main`:**

```sh
git fetch origin
git reset --hard origin/main
```

### Откат публичных коммитов (`git revert`)

Безопасный способ отменить изменения, которые **уже опубликованы** в удаленном репозитории. История не переписывается, а создается новый компенсирующий коммит.

- **Отменить конкретный коммит по его хэшу:**

```sh
git revert <commit_hash>
```

- **Отменить Merge-коммит:**

```sh
git revert -m 1 <merge_commit_hash>
```

- **Принудительная отправка измененной истории с защитой:** При необходимости обновить удаленную ветку после локального сброса используется `--force-with-lease` вместо потенциально опасного `--force`, что предотвращает затирание чужих коммитов

```sh
git push --force-with-lease origin feature/my-branch
```

## Выравнивание истории: `git rebase` и аварийное завершение

Инструмент `git rebase` переносит цепочку локальных коммитов поверх актуального состояния основной ветки, формируя линейную историю.

```
                  Интерактивный Rebase
                             │
 [ feature ] C1 ── C2 ── C3  │  "Перенос поверх main"
                             ▼
 [ main ]    M1 ── M2 ──────► C1' ── C2' ── C3'
```


### Стандартный процесс Rebase

- Переключение на рабочую ветку и синхронизация с удаленным сервером

```sh
git checkout feature-branch
git fetch origin
git rebase origin/main
```

- Интерактивная склейка (Squash) последних коммитов (например, трех)

```sh
git rebase -i HEAD~3
```

### Разрешение конфликтов и аварийный выход при Rebase

- **Отмена процесса rebase при затруднениях:**

```sh
git rebase --abort
```

- **Алгоритм ручного разрешения конфликтов:**

Исправление маркеров конфликтов (`<<<<<<<`, `=======`, `>>>>>>>`) в файлах.
Добавление разрешенных файлов в индекс

```sh
git add <resolved_file>
```

Продолжение процесса rebase (**без вызова `git commit`**)

```sh
git rebase --continue
```

## Временное сохранение кода, диагностика и аварийное восстановление

### Временная изоляция работы (`git stash`)

При необходимости срочно переключиться на другую задачу без создания сырого коммита используется стек заначек:

```sh
# Сохранить изменения в стеке (включая новые файлы -u)
git stash -u -m "Временная рабочая заначка"

# Просмотр списка сохраненных состояний
git stash list

# Восстановление последнего состояния с удалением из стека
git stash pop
```

### `git reflog`: Восстановление случайно удаленных коммитов и веток

Команда `git reflog` фиксирует любые перемещения указателя `HEAD`, позволяя вернуть код даже после выполнения `git reset --hard` или удаления веток.

**Просмотр журнала перемещени:**

```sh
git reflog
```

**Восстановление состояния по индексу `HEAD@{N}` или хэшу коммита:**

```sh
# Вариант А: Создание новой ветки из потерянного состояния
git checkout -b rescued-branch a1b2c3d
   
# Вариант Б: Жесткий возврат к моменту времени
git reset --hard HEAD@{2}
```

### Устранение блокировки `.git/index.lock`

При аварийном завершении процессов Git возникает ошибка блокировки файла индекса. 
*Решение:* убедиться в отсутствии запущенных фоновых процессов Git и удалить файл блокировки
```sh
rm -f .git/index.lock
```

## Сквозной регламент разработки (Feature Branch Workflow)

**Инициализация задачи:**

```sh
git checkout main
git pull origin main
git checkout -b feature/user-auth
```

**Цикл разработки (создание атомарных коммитов):**

```sh
git add .
git commit -m "feat: реализована базовая логика модуля"
```

**Синхронизация перед отправкой (Rebase):**

```sh
git fetch origin
git rebase origin/main
```

**Публикация изменений:**

```sh
git push -u origin feature/user-auth
```

**Очистка окружения после слияния Pull Request:**

```sh
git checkout main
git pull origin main
git branch -d feature/user-auth
git remote prune origin
```
