# Руководство: Workflow и Стратегии Отката в Git

> **Сфера применения:** Командная разработка, контроль версий, управление ветками, безопасный откат изменений и отладка (Troubleshooting).
> 
> **Целевой стек:** Git 2.x+, GitHub / GitLab / Gitea.

## 1. Ментальная модель состояний Git

###### Основные команды Git

**Инициализация репозитория**

Чтобы начать использовать Git в новом проекте, нужно инициализировать репозиторий в рабочей директории:

Bash

```
git init
```

Эта команда создаст скрытый каталог `.git`, где хранится вся история, конфигурации и служебные объекты репозитория.

**Конфигурация по умолчанию**

Задание имени основной ветки по умолчанию (`main` вместо `master`):

Bash

```
git config --global init.defaultBranch main
```

Переименование локальной ветки `master` в `main`:

Bash

```
git branch -m master main
```

**Просмотр состояния и истории**

Просмотр текущего состояния индекса и рабочей директории:

Bash

```
git status
```

Просмотр истории коммитов:

Bash

```
git log --oneline --graph --all
```

**Индексация и фиксация изменений**

Добавление конкретных файлов в индекс (staging area):

Bash

```
git add <path/to/file>
```

Добавление всех изменённых и новых файлов:

Bash

```
git add .
```

Удаление файла из индекса без удаления из рабочей директории:

Bash

```
git rm --cached <path/to/file>
```

Создание коммита с фиксацией состояния:

Bash

```
git commit -m "feat: добавить базовую структуру проекта"
```

###### Работа с ветками и удалёнными репозиториями

**Создание и переключение веток**

Создание новой ветки:

Bash

```
git branch feature/login
```

Переключение на указанную ветку:

Bash

```
git checkout feature/login
# Или с помощью новой команды switch:
git switch feature/login
```

Создание и автоматический переход на новую ветку:

Bash

```
git checkout -b feature/login
# Или:
git switch -c feature/login
```

**Слияние и удаление веток**

Слияние целевой ветки в текущую:

Bash

```
git checkout main
git merge feature/login
```

Безопасное удаление локальной ветки (если она слита с основной):

Bash

```
git branch -d feature/login
```

Принудительное удаление неслитой ветки:

Bash

```
git branch -D feature/login
```

**Взаимодействие с удалённым репозиторием**

Подключение удалённого репозитория:

Bash

```
git remote add origin https://github.com/username/repository.git
```

Отправка изменений с привязкой локальной ветки к удалённой:

Bash

```
git push -u origin main
```

Если привязка не была установлена ранее:

Bash

```
git push --set-upstream origin main
```

Получение и автоматическое слияние изменений из удалённой ветки:

Bash

```
git pull origin main
```

###### Откат изменений и коммитов

**1. Отмена локальных не закоммиченных изменений**

Отмена изменений в конкретном файле (возврат к состоянию последнего коммита):

Bash

```
git restore <path/to/file>
```

Снятие файла из индекса (замена `git reset HEAD <file>`):

Bash

```
git restore --staged <path/to/file>
```

Полный сброс всех незакоммиченных изменений в рабочей директории:

Bash

```
git reset --hard HEAD
```

**2. Безопасная отмена опубликованных коммитов (`git revert`)**

Команда `git revert` создает новый коммит, который вносит противоположные изменения, не переписывая публичную историю.

Отмена последнего коммита:

Bash

```
git revert HEAD
```

Отмена конкретного коммита по его хэшу (без автоматического создания коммита):

Bash

```
git revert -n <commit_hash>
git commit -m "revert: отмена изменений из коммита <commit_hash>"
```

**3. Переписывание локальной истории (`git reset`)**

Используется **только для локальных веток**, которые ещё не были отправлены в удалённый репозиторий.

- **Soft Reset**: отменяет коммит, оставляя все изменения в индексе (готовыми к новому коммиту):

```
git reset --soft HEAD~1
```

- **Mixed Reset** _(по умолчанию)_: отменяет коммит и сбрасывает индекс, сохраняя изменения в рабочей директории:

```
git reset --mixed HEAD~1
```

- **Hard Reset**: полностью уничтожает коммит и все внесенные в нем изменения:


```
git reset --hard HEAD~1
```


**4. Откат локальной ветки к состоянию удалённого сервера**

Если локальная ветка испорчена и требуется полностью синхронизировать её с `origin`:

Bash

```Bash
git fetch origin
git reset --hard origin/main
```

**5. Откат опубликованной ветки (`git push --force-with-lease`)**

Если локально был выполнен `git reset` или `git rebase` и необходимо обновить удалённую ветку, следует использовать `--force-with-lease` вместо `--force` (это предотвратит случайное перезаписывание чужих чужих коммитов):

Bash

```
git push --force-with-lease origin feature/my-branch
```

###### Практические сценарии и Workflows

**Сценарий 1: Исправление последней записи коммита (`--amend`)**

Если забыли добавить файл или допустили опечатку в сообщении последнего незапушенного коммита:

Bash

```
git add forgotten_file.py
git commit --amend -m "fix: скорректирована логика и добавлен недостающий файл"
```

**Сценарий 2: Изоляция незавершённой работы (`git stash`)**

Если необходимо срочно переключиться на другую ветку, но текущие изменения еще не готовы к коммиту:

```Bash
# Сохранить текущие изменения во временный стек
git stash save "work in progress on feature"

# Переключиться и выполнить срочные задачи
git checkout hotfix/bug-fix
# ... выполнение работы ...

# Вернуться и восстановить сохранённые изменения
git checkout feature/my-branch
git stash pop
```

**Сценарий 3: Регулярный рабочий процесс (Feature Branch Workflow)**

1. Синхронизация основной ветки:

```
git checkout main
git pull origin main
```


2. Создание рабочей ветки под задачу:

```
git checkout -b feature/user-auth
```

3. Цикл разработки:
    
    Bash
    
    ```
    git add src/auth.py
    git commit -m "feat: добавлена авторизация через JWT"
    ```
    
4. Подтягивание актуальных изменений из `main` перед публикацией (через rebase):
    
    Bash
    
    ```
    git fetch origin
    git rebase origin/main
    ```
    
5. Публикация ветки и создание Pull Request:
    
    Bash
    
    ```
    git push -u origin feature/user-auth
    ```
    
6. Очистка локального окружения после успешного слияния PR:
    
    Bash
    
    ```
    git checkout main
    git pull origin main
    git branch -d feature/user-auth
    git remote prune origin
    ```
    

###### Исключение файлов (`.gitignore`)

Файл `.gitignore` помещается в корень репозитория для предотвращения попадания скомпилированных файлов, логов, секретов и зависимостей в индекс.

Пример содержимого `.gitignore`:

```
# Логи и временные файлы
*.log
*.tmp

# Директории сборки и окружений
/build/
/dist/
.venv/

# Файлы конфигурации с секретами
.env
config.local.json
```

###### Рекомендации по работе с Git

- **Делайте атомарные коммиты**: Один коммит должен решать одну конкретную задачу или логический блок.
    
- **Не используйте `git reset --hard` на публичных ветках**: Это ломает историю у других участников команды. Используйте `git revert`.
    
- **Используйте `--force-with-lease` вместо `--force`**: Безопасный вариант принудительного push, проверяющий наличие чужих коммитов на сервере.
    
- **Удаляйте неиспользуемые ветки**: После вливания PR удаляйте локальные и удалённые ветки фич, чтобы не засорять репозиторий.
